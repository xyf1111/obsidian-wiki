# Java 51 - 并发编程学什么（学习框架）

> 学完基础框架后就可以开始学并发编程。本文梳理并发编程的学习框架：先理解「并发在解决什么问题」，再按概念 → 编写 → 测试排障 → 工程思考 → 架构设计的顺序系统学习。

## 核心要点

### 并发要解决的问题

一句话总结：**在资源有限、且不改变程序执行结果（正确性）的前提下，合理运用并发编程和架构设计，尽可能多地提升程序的性能与稳定性**。

5 个关键词：资源有限 / 不改变程序执行结果 / 并发编程 / 提升性能 / 提升稳定性。

> 示例：只有 3 台 4 核 8G 服务器，要对 1000 万行数据做汇总。可以把数据均摊到 3 台机器同时汇总，再对 3 份结果二次汇总（Map Reduce 思想）——并发解决的是「资源有限下的性能与稳定性」问题。

### 并发学习五步框架

#### 1. 概念与思想

同步与异步、并发与并行、进程 / 线程 / 协程、线程安全性、线程池、IO，以及锁、资源共享、性能指标（QPS / TPS / P95 / P99）等。多数知识来自操作系统课程（进程线程概念可参考 [[Linux 01 - 基础命令]]）。

#### 2. 编写高并发程序

以 Java 为例学习 JUC 并发包：`CompletableFuture`、`ExecutorService` 等现成类与方法，避免自己 `new Thread` 裸写。相关细节见 [[Java 15 - 线程基础]]、[[Java 16 - 锁与并发工具]]、[[Java 46 - CompletableFuture 异步编程]]、[[Java 40 - CompletableFuture 异常处理实践]]。

#### 3. 测试、监控与排障工具

- **压测**：JMeter
- **监控**：JConsole
- **线程分析**：jstack（看线程状态、定位死锁与资源占用）

目的是基于实际情况分析并发占用的资源、确认有无死锁，从而针对性提升性能指标。

#### 4. 项目中的工程思考

会写之后要在项目中多问自己几个问题，做到**合理运用而非滥用**：

- 什么时候用并发（有无必要）？
- 怎么设置并发参数（如线程池核心线程数）？
- 怎么划分并发资源（如任务队列）？
- 怎么防止和解决操作冲突（如死锁）？

> 不了解并发就乱用，程序不仅可能出错，甚至性能还不如同步执行。

#### 5. 上帝视角的系统设计

跳出单个程序代码，从整体规划系统：

- **技术选型**：用什么技术实现高并发，如 Nginx、消息队列（参见 [[概念 16 - 技术选型方法论]]）
- **架构设计 / 部署编排**：如何组合编排多个服务提升并发度，如动静分离、分库分表、读写分离、弹性 / 线性扩容、冷热分离、批流一体（参见 [[概念 31 - 架构设计入门（方法与经典架构）]]、[[概念 27 - 高并发系统设计实战]]）
