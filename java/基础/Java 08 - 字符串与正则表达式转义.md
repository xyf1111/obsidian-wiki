# Java 基础 08 - 字符串与正则表达式转义

> 用 `replaceAll` 去除字符串中的字面量 `\n`（反斜杠 + n，不是换行符）时，匹配一个反斜杠需要写**四个反斜杠**——因为反斜杠在 Java 字符串和正则表达式中都是转义字符。

## 场景：SQL 预处理

设计 SQL 解析引擎时，用户输入的 SQL 往往很不规范：缩进随意、夹杂换行和冗余字符，甚至包含由字符 `\` 和 `n` 组成的字面量 `\n`（并非真正的换行符）：

```
# 转换前
select * \n 
from user;

# 转换后
select * from user;
```

解析前需要先做字符串预处理：去除回车、换行、冗余空格和特殊字符，将 SQL 标准化。

## 两种实现思路

1. 循环扫描每个字符，通过当前字符与下一个字符判断是否为 `\n` 再移除（繁琐）
2. 直接用 `replaceAll(regex, replacement)` 正则替换——现成方便，还能用一条正则同时替换多个冗余字符（推荐）

`replaceAll` 底层就是 `Pattern.compile(regex).matcher(this).replaceAll(replacement)`。

## 转义陷阱：四个反斜杠

初学时的错误写法 `str.replaceAll("\n", "")` 只能去掉真正的换行符，对字面量 `\n` 无效。

原因：在 Java 字符串常量中，`\` 是转义字符，`"\n"` 表示换行符而非反斜杠 + n。要表达一个反斜杠需写 `"\\"`，要表达 `\n` 字面量需写 `"\\n"`：

```java
System.out.println("\\n"); // 输出 \n
```

于是改用两个反斜杠 `str.replaceAll("\\n", "")`——结果依然只移除了换行符！

**根因**：反斜杠在 Java 字符串和正则表达式中都是转义字符，正则引擎收到的 `\n` 仍是换行符转义。必须为 Java 层的两个反斜杠分别再转义一次：

```java
str.replaceAll("\\\\n", ""); // 四个反斜杠 + n，才能匹配字面量 \n
```

逐层拆解 `\\\\n`：

- 第 1 个 `\`：Java 转义符
- 第 2 个 `\`：反斜杠本身
- 第 3 个 `\`：正则表达式转义符
- 第 4 个 `\`：正则中的反斜杠本身

> 一句话总结：**Java 正则表达式中，匹配一个反斜杠要用四个反斜杠！**
