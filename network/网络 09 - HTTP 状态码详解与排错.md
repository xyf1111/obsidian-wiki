# 网络 09 - HTTP 状态码详解与排错

> HTTP 状态码的含义及对应排错思路。

遇到前端报错（数据为空、按钮无响应等），先按 F12 打开开发者工具查看网络请求的状态码和响应结果，判断问题在前端还是后端。

**分类原则：**
- **4xx 客户端错误**：发送请求的机器（前端）问题
- **5xx 服务端错误**：处理请求的机器（后端）问题

## 4xx 客户端错误

### 400 Bad Request

含义：客户端发送了无效的请求。

可能原因：
- 请求参数格式、数量、类型或名称错误
- 缺少必要参数或参数值不合法

解决方案：
- 检查请求参数是否符合接口要求
- 通过前端校验提前拦截不合规参数
- 查看服务器日志定位

### 401 Unauthorized

含义：请求未经授权，需进行身份验证。

可能原因：
- 用户未登录
- 缺少或携带无效的身份验证信息（Cookie/Token 过期、权限不足）

解决方案：
- 检查请求是否携带 Cookie 或 Token
- 重新登录验证
- 检查用户权限
- 前后端登录态有效期保持一致，设置定期续期机制

### 403 Forbidden

含义：请求被服务器拒绝。

可能原因：
- 客户端 IP 被禁止访问
- 请求频率过高被限流
- 资源无访问权限

解决方案：
- 检查服务器访问限制策略（防火墙、Nginx 网关）
- 检查资源权限控制
- 前端用防抖/节流控制请求频率

### 404 Not Found

含义：请求的资源不存在。

可能原因：
- URL 地址拼写错误
- 资源 id 或查询条件错误
- 资源被删除或移动
- Nginx 未配置 SPA 单页应用的路由支持

解决方案：
- 检查请求 URL 是否正确
- 确认数据库存在对应数据
- SPA 应用部署需在 Nginx 配置 `try_files $uri $uri/ /index.html;`
- 参考框架官方部署文档（如 Ant Design Pro 部署文档）

### 405 Method Not Allowed

含义：请求方法不被服务器支持。

可能原因：请求方法（GET/POST/PUT 等）与后端接口要求不匹配。

解决方案：严格按照后端接口文档使用正确的 HTTP 方法。

## 5xx 服务端错误

### 500 Internal Server Error

含义：服务器内部发生意外错误。

可能原因：代码逻辑错误、运行时异常、资源连接异常、资源耗尽等。

解决方案：
- 查看服务器日志定位
- 逐行 Debug 检查代码逻辑
- 确认外部依赖服务（数据库、消息队列）正常运行
- 增加资源或优化代码
- 使用全局异常处理器做兜底

### 502 Bad Gateway

含义：网关/代理从上游服务器收到无效响应。

可能原因：上游服务器（实际处理后端的服务器）故障、网络问题或配置错误。

排查流程：
1. 绕过网关直接访问后端服务器，确认能否正常响应
2. 查看网关日志，检查路径配置和网络连接
3. 检查网关（如 Nginx）配置是否正确

### 503 Service Unavailable

含义：服务器暂时无法处理请求（过载或维护中）。

可能原因：
- 服务器过载、资源不足
- 服务器处于维护状态

解决方案：
- 等待后重试
- 检查服务器负载，升级配置或优化性能
- 使用 Docker 自动扩缩容
- 实现负载均衡和故障转移机制

### 504 Gateway Timeout

含义：网关等待上游服务器响应超时。

与 502 的区别：502 是后端异常响应；504 是后端响应太慢。

解决方案：
- 检查上游服务器性能和负载，增加资源或优化处理效率
- 调整网关超时设置（如 Nginx 配置）：
  ```nginx
  proxy_connect_timeout 30s;
  proxy_read_timeout    30s;
  ```
- 对慢处理采用异步方式
- 设计重试机制应对偶发超时
