# RAG 检索增强生成学习路线

> RAG（Retrieval-Augmented Generation，检索增强生成）是 AI 应用开发的核心技术之一，通过「检索 + 生成」的混合架构，让大模型基于外部知识库回答，解决知识时效性与幻觉问题。

## 开篇介绍

RAG 是如今 AI 应用开发的核心技术之一，它解决了大语言模型的两大痛点：知识时效性和幻觉问题。

简单来说，RAG 就像给 AI 配了一个「小抄本」：用户提问时，系统先从知识库中检索相关文档，再把这些文档作为上下文提供给大模型，引导模型基于检索到的真实信息生成回答，确保回答基于真实资料而不是凭空想象。从技术效果来看，RAG 不仅提升了回答的准确性，还让 AI 能够访问最新的、私有的、领域专业的知识，大大拓展了 AI 的应用边界。企业智能客服、个人知识库问答、文档分析、专业咨询等场景，RAG 都已成为 AI 应用落地的主流技术方案。

**为什么要学 RAG？**
- **市场需求大：** 据统计 2025 年超过 60% 的企业级 AI 应用采用了 RAG 技术，智能客服、知识库问答、文档分析、智能助手都依赖 RAG 支撑。
- **薪资更高：** 掌握 RAG 的 AI 开发工程师薪资比只会调用 API 的开发者高 20-50%。
- **学习门槛低：** 有 Python 基础和 AI 基础知识的开发者，系统学习约 1 个月即可掌握。
- **应用场景广：** 企业智能客服、文档问答、知识库管理、专业咨询、代码助手、学习辅导、法律咨询、医疗问答等。

### 学习前提
- **Python 基础：** 掌握 Python 语法和常用库，能阅读和编写简单脚本。
- **AI 大模型基础：** 了解 LLM 基本概念，会调用大模型 API，能编写 Prompt（可通过阶段 1 补齐）。
- **时间预期：** 零基础到精通约 2-4 个月，分阶段推进（各阶段时长仅供参考）。

### 就业方向
1. **AI 应用开发工程师：** 使用 RAG 技术开发各类 AI 应用，是最主要的就业方向。
2. **RAG 架构师：** 设计企业级 RAG 系统架构，优化检索和生成效果。
3. **知识工程师：** 负责知识库的构建、管理和优化，保证 RAG 系统的知识质量。
4. **AI 产品经理：** 理解 RAG 能力边界，更好地规划 AI 产品功能。
5. **数据工程师：** 负责 RAG 系统的数据处理、向量化、存储等工作。

## 学习路线（分阶段）

### 阶段 1：AI 大模型基础（7-15 天）
了解 AI 大模型的基本概念，掌握 API 调用和 Prompt 编写，为 RAG 学习打基础。

#### 知识点
**大模型基础【必学】：**
- 大语言模型（LLM）概念
- 主流模型（GPT、Claude、文心、通义等）
- Token 和上下文窗口
- 模型能力和局限性

**Prompt 基础【必学】：**
- Prompt Engineering 基础
- 清晰具体的指令
- 上下文提供
- Few-shot Learning

**API 调用【必学】：**
- API 基本使用
- 参数配置
- 错误处理

#### 学习建议
1. 本阶段快速入门即可，已了解 AI 大模型的可以快速过一遍，重点是理解大模型的工作原理和基本使用方法。
2. 想系统学习可参考 AI 大模型应用开发、Prompt Engineering 相关学习路线，建立整体认知。
3. 多体验各类 AI 工具，第一时间了解最新 AI 技术动态。

### 阶段 2：RAG 核心概念（7-15 天）
理解 RAG 的工作原理和核心概念，掌握文档切片、向量化、检索、生成 4 大核心步骤。

#### 知识点
**RAG 基础概念【必学】：**
- 什么是 RAG
- RAG 的价值和应用场景
- RAG vs 微调（Fine-tuning）
- RAG vs 长上下文

**RAG 工作流程【必学】：**
- 文档收集和切割
- 向量转换和存储
- 文档过滤和检索
- 查询增强和关联

**Embedding 技术【必学】：**
- 什么是 Embedding（嵌入）
- Embedding 模型
- 向量维度
- 相似度计算（余弦相似度、欧氏距离）

**向量数据库【必学】：**
- 什么是向量数据库
- 主流向量数据库（Milvus、Pinecone、Chroma）
- 向量数据库 vs 传统数据库
- 向量数据库选型

#### 学习重点
1. **检索 + 生成是核心：** 先将文档向量化存储，用户提问时检索相关文档，将文档作为上下文提供给模型，模型基于文档生成回答。这个流程是 RAG 的基础。
2. **Embedding 是关键技术：** 将文本转换为高维向量，使计算机理解文本语义。要理解原理、知道如何选模型、了解向量维度对效果的影响。
3. **向量数据库是基础设施：** Milvus（开源、功能强大）、Pinecone（云服务、易用）、Chroma（轻量级、适合学习）；也可用经典数据库的向量扩展，如 PGVector、Redis Vector。
4. **文档切割是重要环节：** 切太小语义不完整，切太大检索不精确。理解按字符数、按段落、按语义等不同切割策略。
5. 想快速体验 RAG 效果，可用线上 RAG 知识库平台（见下文）几分钟构建知识库问答系统；但平台能力有限，深入学习和自定义仍需掌握代码实现。

### 阶段 3：RAG 技术实现（15-30 天）
掌握 RAG 的技术实现方法，能够使用主流框架开发 RAG 应用。

#### 知识点
**文档处理【必学】：**
- 文档加载（PDF、Markdown、HTML 等）
- 文档清洗
- 文档切割（Text Splitters）
- 元数据提取

**向量化【必学】：**
- Embedding 模型选择
- 批量向量化
- 向量维度选择
- 向量质量评估

**向量存储【必学】：**
- 向量数据库使用
- 索引构建
- 相似度搜索
- 元数据过滤

**检索策略【必学】：**
- 相似度阈值设置
- Top-K 选择
- 混合检索（向量检索 + 关键词检索）
- 重排序（Reranking）

**查询增强【必学】：**
- Prompt 模板设计
- 上下文组装
- 引用标注
- 输出格式控制

#### 学习建议
1. **文档处理是第一步也是最重要的一步**，文档质量直接影响 RAG 效果。要学会处理各种格式、清洗无关内容、按文档类型和使用场景选择切割策略。
2. **Embedding 模型选择很重要**，不同模型效果差异大。OpenAI 的 text-embedding-ada-002 是经典选择，阿里云 text-embedding-v4 是国产优质选择，根据语言、领域、成本等因素选型。
3. **检索策略直接影响准确性：** 相似度阈值太高检索不到相关文档，太低检索到不相关文档；Top-K 太小信息不完整，太大噪音多。要通过实验找到最佳参数。
4. **混合检索提升检索效果：** 结合向量检索（语义相似）和关键词检索（精确匹配），提高召回率和准确率，Elasticsearch 可很好地支持。
5. 建议使用 LangChain、Spring AI 等框架学习 RAG 实现，这些框架提供完整的 RAG 组件，可快速上手。
6. 线上 RAG 平台（阿里云百炼、Dify、FastGPT 等）提供可视化配置界面，无需编码即可构建知识库问答系统，适合快速验证想法或给非技术人员使用。

### 阶段 4：RAG 优化和进阶（10-20 天）
掌握 RAG 的优化方法和高级技巧，显著提升检索准确率和回答质量。

#### 知识点
**文档优化【必学】：**
- 文档结构化
- 文档质量控制
- 智能切割策略
- 元数据标注

**检索优化【必学】：**
- 查询重写（Query Rewriting）
- 查询扩展（Query Expansion）
- 混合检索策略
- 重排序模型（Reranker）

**生成优化【必学】：**
- Prompt 模板优化
- 上下文窗口管理
- 引用来源标注
- 幻觉检测和减少

**高级 RAG 架构【建议学】：**
- 自纠错 RAG（C-RAG）
- 自省式 RAG（Self-RAG）
- 检索树 RAG（RAPTOR）
- 多智能体 RAG 系统

**性能优化【必学】：**
- 向量索引优化
- 缓存策略
- 批处理
- 成本控制

#### 学习建议
1. **文档质量是 RAG 效果的上限**，其他优化只是让系统接近这个上限。要确保文档内容准确、结构清晰、格式规范，可用 AI 辅助优化文档。
2. **查询重写提升检索效果：** 用户原始查询往往不够清晰或完整，通过 AI 重写查询可提高检索准确性。
3. **重排序（Reranking）是检索后的重要步骤：** 初次检索可能返回很多文档，用重排序模型重新打分排序，提高最终输入给 LLM 的文档质量。
4. **幻觉检测和减少是重要目标：** RAG 能减少但不能完全消除幻觉。可要求 AI 标注信息来源、不确定时明确说明。
5. **高级 RAG 架构是前沿研究方向**，不是实际应用的必须。理解它们解决了什么问题、如何工作即可，特殊场景可参考使用。

- [使用 Milvus 和 LangChain 的 RAG](https://milvus.io/docs/zh/integrate_with_langchain.md)：完整示例

### 阶段 5：RAG 评估和测试（5-10 天）
掌握 RAG 系统的评估方法，能够科学地测试和优化 RAG 效果。

#### 知识点
**评估指标【必学】：**
- 检索质量指标：召回率（Recall）、精确率（Precision）、MRR（Mean Reciprocal Rank）、NDCG（归一化折扣累积增益）
- 生成质量指标：事实准确性、答案完整性、上下文相关性、引用准确性

**测试方法【必学】：**
- 构建测试数据集
- 自动化评估
- 人工评估
- A/B 测试

**调优策略【必学】：**
- 参数调优
- 模型选择
- 架构优化
- 成本优化

#### 学习建议
1. **评估是保证系统质量的关键：** 建立科学评估体系，不能凭感觉判断效果。要准备包含各类问题和标准答案的测试数据集。
2. **从检索和生成两方面评估：** 检索阶段评估是否检索到相关文档，生成阶段评估回答是否准确、完整、相关。
3. **自动化评估 + 人工评估结合：** 自动化评估用于快速筛选，人工评估用于最终判断。
4. **A/B 测试是有效优化方法：** 对比不同切割策略、检索参数、Prompt 模板等，选择效果最好的方案。

### 阶段 6：项目实战（20-45 天）
通过完整的项目实践，综合运用所学知识，积累 RAG 开发经验。

#### 项目方向
- 个人知识库问答（整理笔记、文档，基于 RAG 问答）
- 企业/技术文档问答（公司制度、API 文档等）
- 学习辅导系统（课程内容、习题解答）
- 客服/咨询机器人（FAQ、产品文档、法律医疗问答）

#### 学习建议
1. 项目要包含完整功能：文档上传和管理、文档处理和向量化、向量存储、检索和生成、用户界面。建议使用 LangChain 或 Spring AI 等框架快速开发。
2. 关注实际效果：收集用户反馈，分析哪些问题回答得好、哪些不好，针对性地优化文档、调整参数、改进 Prompt。
3. 将项目开源或写成技术博客，既能帮助别人，也能作为作品展示给面试官，大幅增加真实性。

### 阶段 7：求职备战
熟练掌握 RAG 常见面试题，准备好简历和项目经历，顺利通过面试。

#### 学习建议
