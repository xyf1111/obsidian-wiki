# AI - AI 编程助手实战（CodeGeeX）

> 以免费国产 AI 编程助手 CodeGeeX 为例，演示 AI 如何作为「导师 · 程序助手 · 测试员 · Bug 修复师」提升日常开发效率。

## 核心要点

### 为什么选它演示

AI 已经不只是智能问答，而是能"自己干活"了：开发用它生成代码、设计用它生成图像、运营用它优化文案。**AI 会淘汰程序员，但只会淘汰不会用 AI 的程序员。**

选 CodeGeeX 演示的 4 个理由：**完全免费、速度更快、生态活跃、可直接作为主流 IDE 插件使用**（VS Code、JetBrains 均支持）。

### 一、安装

1. 在官网或主流 IDE 的插件市场安装（官网：https://codegeex.cn）。
2. VS Code 中进入扩展页面，搜索 `CodeGeeX` 点击安装，插件会出现在左侧栏。
3. 小技巧：在插件图标上**长按鼠标往右拖**，把插件面板挪到右侧，可与左侧文件列表同时存在，使用更方便。

### 二、工作提效：四个斜杠指令

| 角色 | 指令 | 用法 | 价值 |
| --- | --- | --- | --- |
| AI 导师 | `/explain` | 打开代码文件直接输入指令，解释整个文件；也可**选中代码片段**再执行，解释更详细 | 快速理解项目与同事的代码（AI 都解释不了的代码，值得让作者反思质量） |
| 程序助手 | 代码补全 / 直接提问 | 正常写代码时 AI 持续给出补全，按 `Tab` 采纳；也可直接提问生成完整代码（如"Java 爬虫示例代码"）；选中代码让 AI 提升健壮性 | 通用代码（数据格式校验、写 SQL）与各类 Demo 代码生成；AI 补的校验还能帮自己养成好的编程习惯 |
| 程序助手 | `/comment` | 打开文件输入指令，几秒内为代码补详细注释；也可只选中部分代码 | 直接解决「写代码不写注释，做项目不写文档」两大忌；同理可让 AI 写介绍文档（选中代码 + "帮我写一篇介绍文档"） |
| AI 测试员 | `/tests` | 打开待测试文件输入指令自动生成单元测试；**选中要测试的方法**并同时说明要求（用什么测试框架、生成多少用例），命令越具体结果越好 | 写单测耗时导致很多人不写，AI 可低成本补上 |
| AI Bug 修复师 | `/fixbug` | 打开存在 Bug 的文件输入指令，AI 自动发现潜在 Bug 并给出修复优化建议，可自主选择是否替换；也可直接带具体报错信息提问 | 区别于直接搜网页，AI 的回答更易理解、更易引导出排查思路 |

### 三、其他能力

**工具箱**
- 可上传文件让 AI 处理，例如把 JSON 文件转换为 Java 类代码。
- 有意思的是它的实现方式：AI 接到任务后**自己写了一段 Python 程序**完成文件读取与代码转换，最终给出处理好的文件下载地址。
- 除内置工具外还可自定义提问（内容加密、数据生成等）——理论上 Python 能做的事 AI 都能操作 Python 实现，只是现在能力有限、过程未必顺利。

**代码翻译**
- 把一种语言的代码翻译成另一种（如 C++ 课设代码转 Java），适合转语言、用多种语言刷算法题、重构项目的同学。
- 翻译结果未必完全准确，但能起到提醒作用、提高效率。

### 四、实践建议

- **向 AI 提问本身也是技术**：让 AI 理解你的问题需要技巧，甚至催生了 prompt 工程师这类新职业（参考 [[Prompt Engineering 01 - 学习路线]]）。
- AI 目前**不能帮你写复杂业务代码**，但通用代码、SQL、校验、Demo 代码完全够用。
- 把 AI 当日常习惯：做任何复杂的事情之前，都可以先问问 AI 有没有建议和方法；也可以先了解 AI 应用开发的全貌（参考 [[AI 大模型 01 - 应用开发学习路线]]）。
