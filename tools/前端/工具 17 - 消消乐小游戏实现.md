# 前端 - 消消乐小游戏实现

> 作者仿制爆火小游戏「羊了个羊」，做出开源小游戏「鱼了个鱼」。本文讲透它的 4 个核心实现原理：**全局参数、虚拟网格、随机生成、块的覆盖关系**，并分析原版为什么通关率极低。

## 一、游戏玩法与设计

游戏玩法非常简单，类似「消消乐」：从一堆叠放的方块中，找到**相同图案的 3 个方块**并消除即可。操作无比简单，却难住了绝大多数玩家。

### 1. 为什么原版「羊了个羊」那么难

作者玩了几次就发现不对劲，原版通关率极低（据说不足 0.1%），本质上是个**运气游戏**：

- **方块完全随机生成**：图案与坐标都没有经过「保证有解」的校验，这一局到底有没有解很难说
- **越到后面越挤**：越玩到后面的层数，方块的范围越小、可选的方块越少
- 两个条件叠加 → 能不能通关基本靠运气，而不是技术

作者还提到，这类游戏爆火除了营销套路外，主要靠**拿捏用户心理**（总觉得自己可能是那个「天之骄子」，明知概率微乎其微还是忍不住反复玩）。

### 2. 仿制品「鱼了个鱼」的设计

作者决定自己做一个能通关的版本，熬夜几小时做出雏形，打磨后正式上线，**所有代码完全开源**：

- 进入主页可选择**多种不同难度**
- 支持**自定义难度**：如设置槽位数量、设置每层的块数等
- 内置 4 种道具，每种都可以**无限使用**（不用看广告）

## 二、核心实现原理（4 个要点）

### 1. 游戏全局参数

做游戏时涉及很多参数，比如**槽位数量、层数**等，做法是：

- 将参数抽取成统一的**全局变量**，供其他逻辑使用
- 做到**修改一处，游戏自动适配**
- 额外提供页面让用户自定义这些参数，提高可玩性

```js
// 示例：全局参数集中定义，修改一处即可适配整个游戏
const CONFIG = {
  slotCount: 7,    // 槽位数量（放待消除方块的栏位）
  layerCount: 10,  // 层数
  gridSize: 24,    // 画布网格大小
  blockSize: 3,    // 一个块占用的格子数
  patternCount: 12 // 动物图案种类数
};
```

### 2. 网格系统

为了让块的分布相对规整、并且方便计算坐标：

- 将整个游戏画布分为 **24 x 24 的虚拟网格**，类似一个棋盘
- 一个块占用 **3 x 3 的格子**
- 块的位置坐标基于网格计算，天然规整、互不重叠，点击判定也更简单

### 3. 随机生成块

包括随机生成方块的**图案**和**坐标**两部分：

- **图案**：先根据全局参数计算出总块数（保证是 3 的倍数），用 `shuffle` 函数打乱存储所有动物图案的数组，再依次将图案填充到方块中
- **坐标**：随机选取坐标范围内的点；**坐标范围随着层级的增加而递减**，即生成的图案越来越挤，达到难度逐层加大的效果

```js
// 示例：shuffle 打乱图案数组（Fisher-Yates）
function shuffle(arr) {
  for (let i = arr.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [arr[i], arr[j]] = [arr[j], arr[i]];
  }
  return arr;
}

// 示例：生成坐标，范围随层级递减（越深层越挤）
function randomPos(layer, totalLayers, gridSize) {
  const range = gridSize - (layer / totalLayers) * shrinkRate;
  return {
    x: Math.floor(Math.random() * range),
    y: Math.floor(Math.random() * range)
  };
}
```

### 4. 块的覆盖关系

核心问题：怎么做到**点击上层的块后，才能点下层的块**？首先要给每个块指定一个**层级属性**，然后有两种实现思路：

| 方案 | 做法 | 特点 |
| --- | --- | --- |
| 方案 A：逐层生成后判断 | 先逐层生成，然后每个格子里层级最高的块，依次判断其周围格子有没有层级大于它的块 | 思路直观，但生成后需要额外遍历判断，逻辑分散 |
| 方案 B：生成时绑定关系 | 在随机生成块时，就给相互重叠的块**绑定层级关系**（谁覆盖了我？我覆盖了谁？） | 生成时一并建立关系，**效率更高**，作者最终选用 |

```js
// 示例：方案 B 的思路，块与块之间记录覆盖关系
block.coveredBy = []; // 覆盖了我的块（在我上面）
block.covers = [];    // 我覆盖的块（在我下面）

// 只有被覆盖我的块全部消除后，当前块才可点击
function canClick(block) {
  return block.coveredBy.every(b => b.removed);
}
```

作者选择方案 B，感觉效率会高一些。当然，以上只是作者的实现方式，未必是最好的，但完全能满足游戏的功能诉求。

## 三、小结

- **玩法**：找相同图案的 3 个方块消除；原版随机生成 + 越往后可选越少，导致近似运气游戏
- **全局参数**：槽位数量、层数等抽成统一全局变量，改一处自动适配，并提供自定义页面
- **网格系统**：画布分为 24x24 虚拟网格，一个块占 3x3 格子，便于坐标计算与规整分布
- **随机生成**：shuffle 打乱图案数组后依次填充；坐标范围随层级递减，难度逐层加大
- **覆盖关系**：方案 A 生成后遍历判断 vs 方案 B 生成时绑定覆盖关系，选方案 B 效率更高
