# 工具 14 - 接口测试工具与方法

> 汇总常用的接口测试工具：cURL、Apifox、IDEA HTTP Client、Swagger / Knife4j；并附上 Swagger 原生集成（springfox + SwaggerConfig）配置、生产环境关闭的安全提醒，以及「先定义接口再生成代码」的反向用法（Swagger Editor / Ant Design Pro）。

## 核心要点

### 常用接口测试工具概览

| 工具 | 类型 | 适用场景 |
|------|------|----------|
| cURL | 命令行 | Linux 无界面环境、快速调试 |
| Apifox | 桌面端 | 接口设计 / 开发 / 测试一体化管理 |
| IDEA HTTP Client | IDE 内置 | IDE 中直接调试 |

## 1. cURL

> 官网：https://curl.se/

**cURL** 是一个功能强大的命令行 HTTP 工具，支持用命令形式发送各类 HTTP 请求。无图形界面但非常灵活。

### 基本用法

**GET 请求：**
```bash
curl <接口地址>
```

**POST 请求（JSON 数据）：**
```bash
curl -d '{"name":"yupi"}' \
  -H "Content-Type: application/json" \
  <接口地址>
```

- `-d`：发送的数据体
- `-H`：设置请求头

### 快捷技巧

在浏览器 F12 开发者工具中找到目标请求 → 右键点击 → **以 cURL 格式复制**，即可得到可直接执行的 curl 命令，无需记忆复杂参数。

### 适用场景

Linux 开发者无图形界面环境下的接口调试利器。

---

## 2. Apifox

> 官网：http://apifox.com

**Apifox** 是一款 API 设计 + 开发 + 测试一体化的协作工具，主要能力包括：

### 核心功能

- **多格式导入**：支持 20+ 种格式的接口数据导入，快速可视化接口信息
- **Mock 数据**：即使后端服务器未启动，也可一键生成模拟数据进行调试
- **代码生成**：基于接口信息生成 130+ 种语言及框架的代码，前后端可先约定接口文档再生成代码进行调试

### 适用场景

桌面端管理接口、Mock 数据、多团队协作。

---

## 3. IDEA HTTP Client

IntelliJ IDEA 内置的 HTTP 请求工具，允许在 IDE 中直接创建、管理和发送 HTTP 请求并查看响应。

### 使用步骤

1. 菜单栏 **Tools → HTTP Client** → 创建请求
2. 支持从 cURL 格式直接转换（可见 cURL 的通用性）
3. 点击右上角导入示例请求（如 GET 请求示例）
4. 点击绿色箭头发送请求，查看详细响应信息

> 适合习惯在 IDE 内完成一切操作的开发者。

## 4. Swagger 与 Knife4j

### Swagger

> 官网：https://swagger.io/tools/swagger-ui/

**Swagger** 是一套完整的 API 开发工具，包含：

| 组件 | 功能 |
|------|------|
| Swagger UI | 在线查看和调试接口文档 |
| Swagger Editor | 接口编辑器 |
| Swagger Codegen | 代码生成器 |

在项目中引入 Swagger 依赖并通过注解描述 API，即可自动生成文档和进行接口测试。

#### 为什么需要接口文档

接口文档就是用书面形式介绍接口的**功能、地址、调用方法、请求参数、响应结构、细节**等，用于明确接口信息、推动协作。手动编写接口文档非常耗时，所以很多团队选择「口口相传，开局一张嘴，正确与否全靠脸」——这也是要引入自动生成工具的根本原因。

#### 原生集成方式（springfox）

不借助 Knife4j 时，Swagger 本身的接入方式也很简单。以 Spring Boot 项目为例：

**① 引入 SDK（Maven）：**

```xml
<dependency>
  <groupId>io.springfox</groupId>
  <artifactId>springfox-swagger2</artifactId>
  <version>2.9.2</version>
</dependency>
<dependency>
  <groupId>io.springfox</groupId>
  <artifactId>springfox-swagger-ui</artifactId>
  <version>2.9.2</version>
</dependency>
```

**② 编写配置类**（定义作者名、文档名称、需要扫描的接口包路径等）：

```java
@Configuration
@EnableSwagger2WebMvc
// 生产环境记得关闭哦
@Profile({"dev", "test"})
public class SwaggerConfig {

    @Bean
    public Docket createRestApi() {
        return new Docket(DocumentationType.SWAGGER_2)
            .apiInfo(apiInfo())
            .select()
            .apis(RequestHandlerSelectors.basePackage("包名"))
            .paths(PathSelectors.any())
            .build();
    }

    private ApiInfo apiInfo() {
        return new ApiInfoBuilder()
            .title("Swagger Document")
            .version("0.0.1")
            .build();
    }
}
```

**③ 启动项目**即可自动生成接口文档，默认访问地址为 `/接口前缀/doc.html`。

> **安全提示**：一定要像上面那样用 `@Profile` 等手段**在生产环境关闭 Swagger**，避免接口信息与调试入口直接暴露到线上。

如果对默认 UI 不满意，还可以调用 Swagger 提供的接口信息 API（如 `xxx/v2/api-docs`）拿到 JSON 后自行改造界面。


### Knife4j（推荐）

> 官网：https://doc.xiaominfo.com/

**Knife4j** 是基于 Swagger 的增强工具，提供更美观的 UI 和更多功能。由于 Swagger 默认界面在接口较多时管理不便，Knife4j 是更优的生产选择。

#### Spring Boot 集成步骤

**① 引入 Maven 依赖（Spring Boot 2.x）：**

```xml
<dependency>
    <groupId>com.github.xiaoymin</groupId>
    <artifactId>knife4j-openapi2-spring-boot-starter</artifactId>
    <version>4.3.0</version>
</dependency>
```

**② 配置 application.yml：**

```yaml
knife4j:
  enable: true
  openapi:
    title: Knife4j 文档
```

**③ 访问文档地址：** `http://<项目地址>/doc.html`

即可查看自动根据 Controller 代码生成的接口文档，选中接口可直接在线调试。

#### Swagger 注解增强文档

Knife4j 底层依赖 Swagger，可使用 `@Api` 和 `@ApiOperation` 等注解自定义接口信息：

```java
@RestController
@RequestMapping("/api/posts")
@Api(tags = "帖子管理")
public class PostController {

    @PostMapping
    @ApiOperation(value = "创建帖子", notes = "用于创建新的帖子")
    public ResponseEntity<String> createPost(@RequestBody PostRequest postRequest) {
        // 创建帖子逻辑
        return ResponseEntity.ok("帖子创建成功");
    }
}
```

> 使用注解可使文档更通俗易懂，避免大量英文描述。

### 反向用法：先定义接口，再生成代码

Swagger 的能力不止于生成文档，还可以反过来——**先定义好接口信息，再根据接口生成代码**：

- **Swagger Editor**：直接在官方提供的编辑器里写好接口的 JSON 配置，一键生成主流后端语言的服务端与客户端代码
- **前端框架读取 Swagger 配置**：例如 Ant Design Pro，填上 Swagger 的 api 地址再输入一行命令，就能生成接口代码、测试与 mock 文件

### 适用人群

上述用法更适合开发同学自测与团队协作；如果你是专业的测试人员，通常会改用功能更丰富的自动化测试、压力测试工具。
