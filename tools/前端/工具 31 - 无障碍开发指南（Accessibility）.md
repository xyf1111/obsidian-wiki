# 工具 31 - 无障碍开发指南（Accessibility）

> 让任何人在任何情况下都能平等使用互联网产品：读屏软件原理 + 前端/安卓无障碍开发四要素（语义化标签、多种操作方式、多级反馈、调试体验）。

## 什么是无障碍

无障碍（Accessibility）是指**任何人在任何情况下都能平等、方便、无障碍地获取并利用信息**。这不是小众需求：在中国，老年人、视障、听障、读写障碍人士约占人口 **20%**；全球每 7 人中就有 1 位有或重或轻的残障体验，总数超过 **10 亿**。因此无障碍既是重要的产品标准，也是一项关键技术。

## 政策背景：适老化及无障碍改造

工信部曾发起为期一年的"互联网应用适老化及无障碍改造专项行动"，首批推动 8 大类 115 家网站、6 大类 43 个 APP（微信、QQ、淘宝、京东、抖音、支付宝、滴滴等）改造，要求：

- **老年人**：大字体、大图标、高对比度；界面简单、操作方便的"一键操作"模式；文本输入提示；提升方言识别能力
- **视障人士**：与读屏软件兼容，解决验证码操作困难、按钮标签和图片信息不可读的问题；研发智能导盲技术
- **听障人士**：内容信息加配字幕、提高与助听器设备兼容性、提供在线客服等替代电话客服的方式
- **肢体障碍人士**：支持自定义手势、简化交互操作
- 改造完成的适老版/关怀版/无障碍版本**不设广告插件**，付款类操作无任何诱导式按键

## 读屏软件如何工作

读屏软件是改变设备交互方式的系统服务，如今智能设备基本都自带（如安卓知名的 **TalkBack**）。开启后屏幕上出现一个**焦点**，用户通过触摸或手势移动焦点，读屏软件读出当前焦点内容；找到目标控件（如按钮）后**双击屏幕任意位置即可激活**。滚动、放大缩小等操作也都有对应手势——盲人用户在不看屏幕的情况下也能了解界面组成并自如控制。

## 无障碍开发四要素

无障碍体现在硬件、操作系统、应用软件各层面，对应用开发者而言，实现主要集中在前端层面：

### 1. 描述用户界面控件

屏幕阅读器是解决视觉障碍最常用的方式，前提是让阅读器"认识"界面——必须给控件添加描述性内容：

- **前端**：使用语义化 HTML 标签（`<header>`、`<footer>` 等，能被屏幕阅读器理解）；用 **aria 属性**描述元素状态、**role 属性**描述元素的实际意义；还可使用无障碍表单等技术
- **安卓**：优先使用 Android 内置界面控件（默认提供无障碍支持），或用描述属性为辅助功能服务提供信息

### 2. 提供多种操作方式

确保任何鼠标能完成的功能，也能通过键盘、导航手势、轨迹球等方向型软硬件完成。实现"仅凭方向键浏览整个页面"的关键是**以焦点为基础的页面导航**：使所有界面组件可获取焦点，并调整焦点获取顺序使其符合用户操作逻辑。前端可用 JavaScript 管理焦点，配合 `onFocus` / `onBlur` 事件实现焦点获取与离开。

### 3. 多级反馈

通过多级反馈机制为不同障碍用户提供支持：手机收到短信会响提示音，但听障用户无法感知，因此还要提供**视觉反馈**（如呼吸灯闪烁）和**触觉反馈**（如振动）。

### 4. 调试与体验

添加无障碍功能后必须调试并真实体验：闭上眼睛、仅用方向键控制，借助读屏软件模拟障碍人群使用应用；建议邀请第一次使用该应用的用户来体验，效果更好。
