# 交互式教学网站与游戏机制设计

> 测试鸭（ceshiya）：由完整前后端项目「面试鸭」改造而成的纯前端交互式网络安全自学网站，内置 30+ 漏洞关卡，用户通过发现并攻击 Bug 学习网络安全知识。本文拆解其通用改造流程与游戏机制设计，可复用到任意项目。

## 核心要点

- **纯前端实现**：React + Umi + Ant Design Pro 脚手架，无需后端即可运行
- **改造三步走**：完整前端页面 → service 层静态化（mock 假数据）→ 游戏机制
- **游戏机制 = 埋点**：把「过关判定」做成类似前端监控的埋点函数，在业务代码中条件触发
- **零侵入**：所有游戏代码封装在 `games` 目录，通过 `GameBox` 组件引入，不碰业务代码
- **新手指引**：Intro.js + LocalStorage 判断首次进入

## 一、技术选型

| 类别 | 选择 |
| --- | --- |
| 开发框架 | React、Umi |
| 脚手架 | Ant Design Pro |
| 组件库 | Ant Design、Ant Design Components |
| 语法扩展 | TypeScript、Less |
| 打包工具 | Webpack |
| 代码规范 | ESLint、StyleLint、Prettier |
| 工具库 | Intro.js（引导提示） |

### 为什么采用纯前端实现

- **更侧重前端交互**，无需后台存储
- **减少攻击风险**（没有后端接口可打，自身就是教学靶场）
- **省钱**：本地 `npm install` + `npm run dev` 即可启动，无需服务器

## 二、网站改造流程（完整前后端项目 → 交互式教学网站）

通用的三步改造法，可以把任意已有项目改造成交互式教学网站：

1. **完整前端页面开发**：已有项目则此步默认完成（测试鸭直接复用了面试鸭的全部前端页面）
2. **页面数据静态化**：创建 `mock` 目录存放人为编写的假数据；把与后端交互的 service 层代码**全部改造**为操作 / 获取 mock 假数据
3. **创建游戏机制**：具体实现方式见下节

## 三、游戏机制实现

### 1. 组件化：games 目录 + GameBox 组件

遵循组件化思想，所有游戏相关代码封装到 `games` 目录，对外只提供一个 `GameBox` 组件供页面引入，**不直接侵入现有业务代码**：

```
src/
├── games/          # 所有游戏相关代码
│   ├── GameBox.tsx # 页面唯一入口组件（含新手指引、游戏面板）
│   ├── gameUnit.ts # 关卡定义
│   ├── gameState.tsx # 全局游戏状态
│   └── ...
├── tools/          # 游戏工具箱（各工具独立页面）
└── mock/           # 静态假数据
```

### 2. 关卡定义：gameUnit.ts

每个关卡称为一个 unit（单元），用类型 + 数组的方式集中定义：

```ts
/**
 * 游戏单元类型
 */
export type GameUnitType = {
  key: string;       // 关卡唯一标识
  desc: string;      // 关卡描述
  type: string;      // 漏洞类型
  score: number;     // 过关得分
  knowledge: string; // 知识点（过关弹窗展示的教学内容）
  no?: number;       // 题号
  href?: string;     // 更多知识的链接
};

/**
 * 游戏单元列表
 */
const GAME_UNIT_LIST: GameUnitType[] = [
  {
    key: 'favourInfinite',
    desc: '收藏按钮可以无限点击',
    type: '逻辑漏洞',
    score: 1,
    knowledge: '网页前端和后端都要对收藏状态进行控制，防止收藏数异常',
  },
  {
    key: 'thumbUpInfinite',
    desc: '点赞可以无限点击',
    type: '逻辑漏洞',
    score: 1,
    knowledge: '网页前端和后端都要对点赞状态进行控制，防止点赞数异常',
  },
];
```

### 3. 全局状态：gameState.tsx

记录用户已完成的关卡、分数、游戏配置等信息：

```ts
/**
 * 游戏全局状态类型
 */
export type GameStateType = {
  init: boolean;           // 是否为初始化
  score: number;           // 当前分数
  gameTip: boolean;        // 是否开启提示
  succeedUnitList: string[]; // 已通过的关卡 key 列表
};
```

### 4. 过关通知：doGameUnitSucceed（埋点思想）

实现思想类似前端监控业务中的**「埋点」**：定义统一的上报函数，参数为关卡 key，函数内完成过关状态变更 + 过关弹窗提示：

```ts
/**
 * 完成游戏（过关通知）
 * @param key 关卡 key
 */
const doGameUnitSucceed = (key: string) => {
  // 已经完成，直接返回（防止重复过关）
  if (gameState.succeedUnitList.includes(key)) {
    return;
  }
  gameState.succeedUnitList.push(key);
  const unit = GAME_UNIT_MAP[key];
  gameState.score += unit.score;
  setTimeout(() => {
    Modal.success({
      title: `太棒了，鱼皮的血鸭又高了！😡 ${gameState.score - unit.score} +${unit.score}`,
      content: unit.knowledge, // 展示知识点
      okText: '继续加油！',
    });
  }, 1000);
  updateGameState(gameState);
};
```

### 5. 业务代码接入：条件触发过关

在对应的页面 / 功能代码中增加一段过关判断逻辑，符合条件就调用 `doGameUnitSucceed(关卡key)`，即可实现过关状态的更新与通知。以点赞功能为例：

```ts
const doThumbUp = async (id: string) => {
  setThumbLoading(true);
  const res = await thumbUpComment(id);
  if (res === 1 || res === -1) {
    comment.thumbNum = (comment.thumbNum ?? 0) + res;
    // 点赞数 > 9 则过关（触发「点赞可以无限点击」关卡）
    if (comment.thumbNum > 9) {
      // 注意这行代码是关键，触发过关
      doGameUnitSucceed('thumbUpInfinite');
    }
  }
};
```

**设计精髓**：埋点式过关让业务代码只多了一行判断，游戏逻辑与业务逻辑解耦；关卡「触发条件」天然形成游戏玩法（如疯狂点击收藏 / 点赞按钮找 Bug）。


## 五、游戏工具箱

工具箱（`ToolBox.tsx`）**本质上就是集成了特定过关方法的页面**，属于定制化开发——每种工具（如请求工具：绕过前端界面直接从后台获取数据）都是独立页面，存放在 `tools` 目录下。
