# 概念 - 领域驱动设计（DDD）

> 领域驱动设计（Domain-Driven Design）由 Eric Evans 在其著作《领域驱动设计：软件核心复杂性应对之道》中提出，核心思想是将软件模型与业务领域紧密结合，以应对复杂业务系统的设计挑战。

## 核心理念

| 概念 | 说明 |
|------|------|
| **领域模型** | 对特定业务知识的精确表述，包含实体、值对象、服务、聚合、聚合根等 |
| **统一语言** | 开发团队与业务专家共同使用的语言，确保所有人对业务概念的理解一致 |
| **限界上下文** | 明确界定的系统边界，边界内有一套统一的模型和语言，不同上下文间通过映射交互 |
| **聚合** | 一组相关对象的集合，数据修改的最小单元，外部通过聚合根访问 |
| **领域服务** | 不属于任何实体或值对象的业务行为，封装特定领域的操作逻辑 |
| **应用服务** | 协调领域对象来执行任务，负责工作流程，不含业务规则 |
| **基础设施** | 持久化机制、消息传递、配置等技术组件 |
| **领域事件** | 有意义的业务事件，可触发其他子系统的反应或流程 |

## DDD 在软件设计中的定位

DDD 涵盖软件设计的方法论、范式、模型和框架：

### 范式（Paradigms）

- **结构化编程**：顺序、选择、循环控制结构
- **面向对象编程（OOP）**：数据和方法的封装
- **函数式编程**：避免状态改变和可变数据
- **事件驱动编程**：以事件为中心的响应模式

### 模型（Models）

- **UML**：图形化建模语言，描述、设计和文档化软件
- **ER 模型**：数据库设计，描述实体及关系
- **状态机模型**：描述状态、事件及转换

### 框架（Frameworks）

- **Spring Framework**：Java 应用的全面编程和配置模型
- **Django**：Python Web 框架
- **Gin**：Go Web 框架

### 方法论（Methodologies）

- **敏捷开发**：迭代增量开发，强调灵活性和客户合作
- **Scrum**：敏捷框架，管理复杂产品开发
- **瀑布模型**：线性顺序的开发方法

## 软件设计主要活动

| 活动 | 说明 |
|------|------|
| **建模** | 创建模型表示系统不同方面 |
| **测试** | 单元测试、集成测试、系统测试、验收测试 |
| **工程** | 需求分析、设计、实现、测试 |
| **开发** | 编写代码，将设计转化为软件产品 |
| **部署** | 发布到生产环境 |
| **维护** | 纠错、适应性维护、完善性维护、预防性维护 |

## DDD 目标

将软件关注点集中在**核心领域**上，通过丰富的领域模型管理复杂性，提升软件质量和可维护性。强调与业务专家的紧密合作，确保软件解决方案准确反映业务需求。
