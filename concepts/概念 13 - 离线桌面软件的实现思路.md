# 概念 - 离线桌面软件的实现思路

> 不依赖网络的桌面软件（记事本、编译器这类）怎么做？核心是让「前端界面 + 后端逻辑 + 数据」在同一台机器上完成闭环，跨语言调用也不再走网络 API。

## 为什么大多数应用依赖网络

1. **远程代码与数据**：用户访问的是远程服务器上的代码和数据，没有网络自然无法工作。
2. **跨语言/第三方能力**：应用依赖的功能可能不在自己系统里（云服务等），或与自己的系统不兼容（Java 应用需要 C++ 实现的能力）。网络 API 屏蔽了系统/应用间的差异——「怎么实现我不管，发请求拿响应就行」。

想开发不联网的应用，就从这两点下手：**代码放一起** 或 **本机内互调**。

## 思路一：前后端逻辑与数据写在同一个项目

把前端界面、后端逻辑、数据全部写在一起（同一根目录、尽量同一语言），不联网也能跑：

- **桌面 GUI 框架**（前端三件套也能写桌面应用）：C++ 的 Qt Creator、JavaScript + Electron / Tauri、C#、Rust、Java Swing / JavaFX、Python Tkinter 等
- **后端逻辑**：C、C++、Java、Python、Go 等任何语言
- **数据存储**：H2、SQLite 等支持内存/嵌入式运行的数据库；简单场景直接分配内存、new 对象存储即可

## 思路二：本机内跨语言互相调用

多个不同语言写的程序放在同一台机器上，不通过网络怎么互相调用？三种方法：

1. **类库调用**：用特定类库调用其他语言的代码。例如 Java 调 Python 脚本用 Jython（Java 语言的 Python 实现）；Java 调 C++ 用「本地方法」特性，直接找到同一台电脑上的 C++ 动态链接库（DLL）调用。
2. **命令行调用**：语言不支持调其他语言、也无第三方类库时，调用命令行工具运行其他语言的脚本或 exe。如 Java 的 `Runtime.exec()` 可执行外部程序或命令（打开记事本、执行关机命令等）。
3. **本地服务（曲线救国）**：没有网络 ≠ 不能发请求，只是不能发给本机之外的服务器。本地启动服务，通过 `localhost:port` 访问本机的其他代码——本地开发调试前后端项目时就是这样做的。前后端分离、甚至微服务在无网环境下同样可行。
