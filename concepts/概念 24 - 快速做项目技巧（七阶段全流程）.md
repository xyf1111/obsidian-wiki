# 概念 24 - 快速做项目技巧（七阶段全流程）

> 做项目分为需求分析、技术选型、系统设计、开发编码、调试测试、部署上线、运营推广七个阶段，每个阶段都有提速技巧。核心心法：同一类项目多做几遍，无他，唯手熟尔。

> 与 [[概念 19 - 大厂项目研发流程|概念 19]]（大厂八阶段规范流程）互为对照：本篇是个人项目提速技巧，更强调自主与效率；大厂流程更强调评审与规范。

## 核心要点

### 1、快速需求分析

- 别只跟着教程做功能，要自主扩展需求：如做完「按商品名称搜索」功能后，主动加搜索建议、商品热搜列表、图片搜商品等
- 从自己的生活需要或实际使用过的产品出发，分析不足并改进，做到推陈出新
- 遇到问题、想到需求时**第一时间记录下来**，但不立刻开工；记录多了会发现需求间有联系，再汇聚成新项目，同时评估时间与竞品（来不及、性价比不高、卷不过同行就不做）
- 随时记录的习惯能自然酝酿项目灵感，比等要做项目时硬想更轻松，做出来的项目也更实用、性价比更高

### 2、快速技术选型

个人项目选自己最熟悉的技术框架即可，不必纠结（企业大项目才要谨慎，避免冷门、无人维护的技术）：

- 前端：Vue 和 React 二选一，统一用 Ant Design 等多框架兼容组件库，不要一个项目换一个新组件库
- 后端：小项目、侧重前端的用 Node；追求稳定性的大项目用 Java SpringBoot
- 上线：前端用 Nginx、后端用 Docker

> 选型维度与判断方法见 [[概念 16 - 技术选型方法论|概念 16]]

### 3、快速系统设计

- 90% 的同学离开视频教程就不知道怎么设计——设计靠积累经验，用户鉴权等很多需求和业务场景是通用的，设计过一次之后做类似系统无压力
- 不会设计就去网上搜方案：参考业界主流设计方案来定制或改进，而不是纯靠自己想；没有分析文章时直接找开源项目手撕源码
- 绘制流程图、时序图、功能模块图辅助理解，用在线绘图工具 draw.io 即可

> 设计为什么重要、详细设计怎么做见 [[概念 17 - 先设计再编码（详细设计）|概念 17]]

### 4、快速开发

两大原则：

1. **能不自己写的代码就不写**：新项目选最符合需求的脚手架——前端 Ant Design Pro（布局、导航、路由、菜单、主题、组件、请求、测试、权限管理、国际化全整合好），后端用整合了常用组件的 Spring Boot 脚手架；或直接到 GitHub 找开源项目二改（如后台管理系统 Vue Admin Template）
2. **自己写过的代码绝不重复写第二遍**：多抽象复用同功能的类/方法/函数；保留好写过的所有代码，做过一次的项目直接复制粘贴改造

> 脚手架 + 代码生成链的完整套路见 [[概念 22 - 快速开发项目套路（代码生成工作流）|概念 22]]

**血泪教训：做项目一定要有计划**。今天做什么、明天做什么、每个功能花多少时间，分清主次、先完成核心功能再完善细节；别功能没开发完就纠结前端界面字体大小，也别花 2 天死磕一个小 bug 导致项目延期。

### 5、快速测试

- 编写好单元测试，每次改完代码执行一次，提前自动发现小 bug，节省人工时间
- 正式对外项目提前招募内测用户，人多力量大，比一个人自测更省时间、也更能发现问题

### 6、快速部署

操作多了会发现上线是所有环节中最简单的——上传文件、点一下就好：

- 前端：用 Vercel 免费服务器一键上线（好处是还不用备案）
- 后端：用腾讯云托管等容器平台发布 Docker 打包的代码
- 可视化运维：用宝塔面板运行 Node、PHP、Java 项目
- 微服务：用 Docker Compose 编排群起；真正上线产品、没有用户时不建议用微服务

> 部署方式详解见 [[DevOps 08 - 主流前后端项目部署方式|DevOps 08]]、[[DevOps 06 - 免费上线网站的几种方法|DevOps 06]]

### 7、快速运维

不自己搭建运维监控管理平台，直接用现成的第三方服务：

- 用户统计：百度统计、51.LA
- 服务监控：现成的云数据库、云 Redis、容器托管平台监控运行并配置告警

有现成的服务就用现成的：虽然花一些额外金钱，但能省下大量时间，性价比绝对高——对企业来说，时间就是金钱。
