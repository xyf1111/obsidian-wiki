# 数据仓库学习路线

> 数据仓库（Data Warehouse）是面向主题、集成、相对稳定、反映历史变化的数据集合，用于支持管理决策；本路线覆盖从零基础到精通的完整路径：数仓基础 → 数据建模 → ETL → Hive 开发 → 数据治理 → 项目实战 → 求职备战。

## 核心概念

- **定义**：面向主题、集成、相对稳定、反映历史变化的数据集合，将各业务系统数据集中存储，经清洗、转换、整合后以统一格式提供给数据分析和 BI 系统使用，是企业数据管理的核心基础设施
- **OLTP vs OLAP**：数据库（OLTP）用于事务处理，强调增删改查性能；数据仓库（OLAP）用于分析处理，强调查询分析性能，定期从数据库抽取数据后清洗整合存储
- **数仓分层**：ODS（操作数据层/贴源层）→ DW（数据仓库层：DWD、DWS、DWT）→ DM（数据集市层/应用层）；分层可提高数据质量、简化 ETL 逻辑、提升查询性能
- **核心技术**：数据建模（维度建模、范式建模）、ETL（抽取-转换-加载）、OLAP、数据分层、数据治理、元数据管理
- **事实表 vs 维度表**：事实表存业务过程的度量值（销售额、数量），维度表存描述性信息（时间、地点、产品）
- **技术演进**：传统关系型数仓（Oracle、Teradata）→ 大数据数仓（Hive、ClickHouse）→ 批处理/实时数仓 → 数据湖仓（Data Lakehouse，2025 年趋势，结合数据湖与数仓优势）
- **数仓 vs 数据湖 vs 数据湖仓**：三者的区别和联系（湖仓架构可选学）
- **就业方向**：数仓工程师、ETL 工程师、大数据开发工程师（Hive/Spark）、数据架构师、数据治理工程师；一线城市数仓工程师平均薪资 20-40K，资深专家 40-80K+

**学习前提：**

1. SQL 基础：熟练使用 SQL 进行查询和分析【必学】
2. 数据库基础：理解关系型数据库【建议】
3. 大数据基础：了解 Hadoop、Hive 等【建议】

**整体学习建议：**

1. SQL 是基础：重点掌握复杂查询、窗口函数、多表关联等高级特性
2. 数据建模是核心：重点学习维度建模（星型模型、雪花模型）
3. 理论结合实践：边学边做项目，搭建一个简单数仓体验完整开发流程
4. 关注大数据技术：现代数仓主要基于 Hive、Spark 等大数据技术
5. 善用 AI 工具：辅助编写 SQL、理解概念

## 学习路径

| 阶段 | 内容 | 建议时长 |
|------|------|---------|
| 阶段 1 | 数据仓库基础（概念、架构、分层） | 10-20 天 |
| 阶段 2 | 数据建模（维度建模、范式建模） | 15-25 天 |
| 阶段 3 | ETL 开发（抽取、转换、加载、调度） | 10-25 天 |
| 阶段 4 | Hive 数据仓库开发 | 15-25 天 |
| 阶段 5 | 数据治理（质量、元数据、安全） | 10-20 天 |
| 阶段 6 | 项目实战 | 30-45 天 |
| 阶段 7 | 求职备战 | 面试前 1 个月 |

### 阶段 1：数据仓库基础

**必学知识点：**

- 数仓定义和特点、OLTP 和 OLAP 的区别、数仓架构、事实表和维度表
- 数仓分层：ODS / DW（DWD、DWS、DWT）/ DM 及各层意义
- 可选学：数仓 vs 数据湖 vs 数据湖仓的区别和联系

**学习重点：**

1. 数仓面向主题，按业务主题（销售、库存、客户）组织数据，而非按业务系统
2. 分层设计提高数据质量、简化 ETL 逻辑、提升查询性能；ODS 贴源层、DW 加工层、DM 应用层
3. 事实表存度量值，维度表存描述性信息

### 阶段 2：数据建模

**必学知识点：**

- 维度建模【必学，核心重点】：星型模型、雪花模型、事实表类型（事务型、周期快照型、累积快照型）、维度表设计（SCD 缓慢变化维）、维度建模步骤
- 范式建模【建议学】：第一/二/三范式、与维度建模的对比
- 数据建模工具【建议学】：PowerDesigner、ERwin、在线建模工具

**学习建议：**

1. 维度建模（Ralph Kimball 提出）是数仓最流行的建模方法；星型模型将事实表放中心、维度表环绕，查询性能好
2. SCD 处理维度数据的历史变化（客户地址变更、产品价格变更等）：SCD1 覆盖、SCD2 增加新行、SCD3 增加新列
3. 建模要结合业务理解，从业务需求出发设计合理的数据模型，不同业务场景建模方法不同

### 阶段 3：ETL 开发

**必学知识点：**

- ETL 基础：Extract（抽取）、Transform（转换）、Load（加载）、全量同步和增量同步
- 数据抽取：从数据库抽取（Sqoop、DataX）、从日志抽取（Flume、Logstash）、从 API 抽取
- 数据转换：数据清洗、数据整合、数据标准化、数据质量
- 调度工具：Azkaban、Airflow、DolphinScheduler【建议学】

**学习建议：**

1. ETL 是数仓核心工作，负责将各业务系统数据抽取到数仓，清洗转换后加载
2. 增量同步是重点：识别新增和变更的数据，避免全量同步的性能问题
3. 数据质量是 ETL 的重要目标：过程中做数据校验、去重、格式化

### 阶段 4：Hive 数据仓库开发

**必学知识点：**

- Hive 基础：Hive 架构、HiveSQL 语法、内部表和外部表、分区表和分桶表
- Hive 高级特性：窗口函数、自定义函数（UDF）、性能优化
- Hive 数仓实践：数仓分层实现、维度建模实现、ETL 流程开发

**学习建议：**

1. Hive 是大数据数仓的主流技术，基于 Hadoop 构建，用 SQL 语法（HiveSQL）处理大规模数据，熟悉 SQL 即可快速上手
2. 分区表（按天、按月）提高查询性能，分桶表实现抽样查询
3. 窗口函数是 Hive 的强大特性，可实现排名、累计、环比等复杂计算

### 阶段 5：数据治理

**必学知识点：**

- 数据质量【必学】：质量维度（准确性、完整性、一致性、及时性）、数据质量检查、数据清洗
- 元数据管理【建议学】：元数据类型、管理工具、数据血缘
- 数据安全【建议学】：数据权限管理、数据脱敏、数据备份

**学习建议：**

1. 数据质量是数仓的生命线，建立数据质量监控机制，及时发现和处理数据问题
2. 元数据管理记录数据的来源、转换逻辑、使用情况，帮助理解和管理数据

## 项目实战

### 阶段 6：项目实战

**学习建议：**

1. 搭建完整数仓：从数据建模开始，设计分层架构，开发 ETL 流程，最终提供数据服务
2. 选择业务场景：电商数仓、金融数仓、物流数仓等，结合实际业务设计数据模型
3. 性能优化：优化 SQL、优化分区、优化存储格式等

**项目推荐：**

- 电商数据仓库
- 用户行为数据仓库
- 物流数据仓库
- 金融数据仓库

**优质开源项目：**

- [GoodReads Data Pipeline](https://github.com/san089/goodreads_etl_pipeline)：端到端数据湖、数据仓库和分析平台项目
- [ETL Pipeline with Airflow & AWS](https://github.com/supratim94336/DataEngineeringCapstoneProject)：Spark、Airflow 和 AWS Redshift 的完整 ETL 管道
- [Cloud Data Warehouse with Redshift](https://github.com/donjude/cloud-data-warehouse)：基于 Amazon Redshift 的云数据仓库 ETL 管道

## 求职准备

### 阶段 7：求职备战

**面试重点（经典面试题）：**

- 数仓基础：什么是数据仓库？与数据库的区别？OLTP 和 OLAP 的区别？数仓分层及各层作用？什么是数据集市？
- 数据建模：维度建模的优势？星型模型和雪花模型的区别与选择？事实表的类型？维度表如何设计？SCD 的类型？如何设计电商数仓订单主题模型？
- ETL：包含哪些步骤？全量同步和增量同步的区别？如何实现增量数据抽取？如何保证数据质量？调度工具有哪些？
- Hive：架构是怎样的？内部表和外部表的区别？分区表和分桶表的区别？如何优化查询性能？文件存储格式有哪些，Parquet 和 ORC 的区别？
- 数据治理：包含哪些内容？如何保证数据质量？什么是元数据及其作用？什么是数据血缘？

**备考建议：**

1. 打磨简历和项目：简历上要有数仓项目经历（设计过的数据模型、开发过的 ETL 流程、优化过的性能问题等）
2. 准备项目经历：能清楚介绍数据模型设计思路、ETL 实现方案、数据质量保证措施、性能优化方法
3. 理解业务：能说出常见业务场景（电商、金融）的数据模型设计
