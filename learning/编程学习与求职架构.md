# 编程学习与求职架构

> 一套从零基础到进大厂的 7 阶段编程学习架构与求职方法论：先广后深地学习、确定职业方向、积累作品与实习、用软技巧展现硬实力，并贯穿归纳总结与资源管理。

编程学习没有捷径，必须**明晰目标、拉长战线、掌握技巧、持续学习、做足准备**。这套体系之所以叫「学习架构」而不是「学习路线」，是因为其中很多事不是严格按顺序做，而是要在整个学习过程中长期坚持的。无论你现在处于哪个阶段，都可以按此框架规划下一步。

## 一、初入茅庐，海纳百川

### 阶段目标

打好大学基础，广泛尝试多种编程语言与技术，培养对编程的兴趣，不急于考虑就业问题。

### 核心做法

- **通识课程与绩点**：学好大学通识课程，保证成绩不能太差。绩点不止影响校内评价，更是简历的牌面，能取得前几名是绝对的加分项。
- **坚持自学**：课本知识远远不够，想要学好编程必须自学。
- **海纳百川地尝试**：初期并不知道自己擅长什么、喜欢什么，可以多了解尝试各种编程语言、技术框架和专业知识，比如在课堂之外自学 Web 网站开发或 Python。
- **选择轻松的资源入门**：不要直接啃复杂的理论书籍，选择轻松有趣、相对简单、案例丰富的书；也可以使用 W3Cschool、实验楼、FreeCodeCamp 等在线学习网站边学边敲，或去 B 站搜索视频教程。
- **边学边练**：不必局限于习题和书中的代码片段，发挥创意编写简单的网站或实用小工具，用成就感培养兴趣。
- **不必过早执着于单一技术**：除非有非常明确的方向，前期多学简单易懂的知识即可，计算机领域很多技术知识点是相通的。

### 如何选择编程语言

- **排行榜不代表一切**：TIOBE 等排行榜的统计方式、覆盖人群多种多样，不要盲目跟风（比如「学编程就学最牛的 C 语言」）。
- **先想清楚学编程的目的**：出于好奇兴趣？为了搞钱？想多门手艺提高效率？想创业做产品？还是碰巧选了计算机专业？没有目标是绝对学不下去的。
- **主流语言速览**：

| 语言 | 特点 | 主要应用场景 | 适合人群 |
|------|------|-------------|---------|
| Java | 成熟稳定、跨平台、生态丰富、应用场景广，踩坑问题网上都能搜到答案；被称为「内卷之王」 | 后端、桌面程序、安卓、大数据 | 想快速就业、走后端方向 |
| 前端（HTML/CSS/JS） | 入门相对简单，写出的代码立刻能看到效果；需求量大；大前端可用一套代码开发网页、桌面、安卓、iOS、小程序 | 网站界面、小程序、跨端 APP | 想快速看到效果、培养兴趣 |
| C 语言 | 足够底层，所有操作系统都用它实现；学习过程能接触内存管理等底层概念 | 操作系统、底层软件、嵌入式、软硬件开发 | 在校时间充足、想打好基础 |
| C++ | C 的超集，增加面向对象思想，性能高 | 后台开发、桌面程序、框架开发、图像/音视频处理、3D 引擎 | 对性能与底层感兴趣 |
| C# / .NET | .NET 是框架环境，C# 是运行其上的语言之一；国内流行度一般 | Unity（游戏、VR、AR 开发） | 游戏开发方向 |
| Python | 入门简单、生态好、现成类库多；但解释执行的动态语言运行效率低（同效率下可比 C++ 慢 100 倍） | 脚本工具、文件表格处理、爬虫、数据分析、AI | 兴趣入门 / 做小工具，不推荐作为企业开发主语言 |
| PHP | 曾是「世界上最好的编程语言」，PC 网站时代开发极快；如今性能低、其他语言开发效率已追平，逐渐衰落 | 传统网站服务端 | 已不受大公司青睐，不推荐新入行 |
| Go | 语法简单、天然支持高并发、性能高；国内生态越来越好 | 云原生应用（Docker、B 站）、大厂后端 | 想走高并发 / 云原生方向 |
| SQL | 数据库查询语言，从数据库中查询、操作数据 | 后台开发、数据库管理必备；产品经理也常学 | 数据相关从业者 |
| 其他 | Shell 与 Python 类似当工具学；Kotlin、Scala、Rust 等各有应用场景 | 按需学习 | 有明确场景时再学 |

- **移动端开发的现状**：小程序免安装、方便、易分享、开发成本低，数量已超过 APP，是很适合创业的产品形态；受小程序和大前端发展影响，Android、iOS 移动端及客户端开发前景逐渐变差（供过于求、看不到增量），想开发界面建议都先从前端学起，布局、组件化、模块化等思想是类似的。
- **选择建议**：想快速就业 → 直接学前端或后端——倾向「所写即所得」选前端，想锻炼思维逻辑首选后端 Java 或 Go；还在学校、时间充足、想打基础 → 老老实实从 C 语言学起；纯兴趣或想做小工具 → 学 Python 或前端。
- **第一门语言不等于找工作的语言**：时间允许就大胆尝试，先培养兴趣，深入学懂一门后，再学其他语言也会很轻松；不存在「最好的编程语言」，适合自己的才是最好的，解决问题、应用落地才真正体现语言的价值。

### C++ 还是 Java，怎么选？

- **校园打基础 vs 求职选 Java**：身在校园且时间充裕，建议先学 C 语言或 C++ 打基础——相对底层，能接触系统、网络等更多计算机概念，为学其他高级语言做铺垫；但最终要找工作赚钱的话，坚定选 Java，国内需求量明显更大（大公司也招 C++，但整体就业机会 Java 更多）。
- **Java 语言特性 4 点优势**：① 简单性——移除 C++ 中学习成本高、易出错的指针和多重继承，用接口机制降低类间关系复杂度；② 可移植性——通过虚拟机执行、不依赖固定平台，跨平台是 Java 最大的优点；③ 健壮性——银行电子交易、大型电商、秒杀系统多用 Java 开发；④ 安全性——自带垃圾回收等机制，能规避很多因程序设计不合理导致的问题。
- **性能差异不关键**：C++ 性能通常更高，但在大多数企业业务开发中这些提升微不足道，底层和基础架构另当别论。
- **生态与应用场景**：Spring 等知名框架崛起降低了企业应用开发成本，阿里等大厂也以 Java 为主力后端语言；Java 非常适合企业级 Web 项目，在大数据分析处理、微服务、云计算、移动开发等领域也处于领先地位。
- **学习成本**：Java 相对低很多——不需要自主管理内存，降低出 bug 概率，即使不了解操作系统也能写出较健壮的程序；C++ 更底层，涉及指针、内存管理、进程管理等系统层面知识，指针对新手是噩梦。时间有限时先熟练开发 Java 应用，再补底层知识也不晚。
- **自学 Java 参考路径**：视频教程/文档看一节敲一节 →《Java 核心技术卷 I》打实基础 → SSM、SpringBoot 等框架开发企业级项目（多敲代码、发挥想象做自己的项目）→ SpringCloud 微服务 + Redis、Zookeeper 等中间件（学会设计技术架构、用技术解决实际问题）→ 找工作前深学多线程高并发与 JVM 底层原理。
- **后端通用技能优先于语言**：C++ 和 Java 做后端要学的通用知识几乎相同——数据库、缓存、消息队列、计网、操作系统、接口开发设计、Linux、设计模式、架构设计；差异只在 C++ 更重基础和对操作系统/Linux 的理解，Java 更侧重业务开发的方法与工具。先把这些通用技能学好，两种语言的后端岗都能投（有 C++ 刷题经验还熟 STL 更是加分）；「Java 卷」更多是整个行业行情的问题、而非语言需求量比例有大调整，后端开发仍推荐 Java（资源多这点无敌，比如 C++ 微服务教程就很少）；Java 和 Go 的选择同理。

## 二、兴趣使然，纵横交贯

### 阶段目标

在兴趣驱动下深入钻研某门语言或领域，同时保持知识面开阔，让零碎知识点连成网，编程能力开始突飞猛进。

### 核心做法

- **挑选感兴趣的方向深学**：从已学知识中挑出相对感兴趣的部分（如某门语言 Java，或某个领域 NLP），读经典书籍、了解技术特性，甚至可以阅读相关源码。
- **保持开放**：深入学习一门技术的同时继续接触新知识，避免深陷其中；计算机知识相互关联，多学不同方面更容易把知识点串联成网、开拓思维。
- **算法、数据结构、计算机网络必须认真学**：即使没有兴趣也要认真学，它们培养思维、提升程序设计能力。编程语言大多相通，**语言只是工具，思想才是武器**。
  - 面试大厂时几乎每一轮都会考算法题；后台开发岗位必问计算机网络、操作系统。
  - 工作中常要用到算法思想解决问题，如滑动窗口、时间轮、布隆过滤器等。
- **选主流技术深学**：推荐 Java 语言的 SSM 和 SpringBoot 框架。主流技术教程多、文档多、遇到问题容易解决，上手快，能做出个人作品，增加兴趣和成就感。

### Web 开发 vs ACM 算法竞赛如何取舍

- **难度**：ACM 专业性强，题目多为英文、考察数学思维和逻辑，难上手且枯燥；Web 开发入门简单、即学即练，能发挥创意做出作品、收获成就感。
- **性价比**：ACM 是比赛，竞争激烈（名校学子、数学天才云集），拿得出手的奖要么靠天赋、要么投入大量时间日常训练；Web 学习时间灵活、几乎感受不到竞争。
- **未来发展**：先问自己想做算法工程师还是开发工程师。算法思维对任何方向都很重要，但如果不是走算法方向，绝大多数算法工作中用不到，求职面试的算法题也达不到 ACM 难度；有 ACM 奖项求职机会加倍，但没奖项、又没精力学开发、只沉迷刷题，找工作时反而处于不利状态。
- **风险**：ACM 正反馈慢，一道题折腾几小时做不出容易怀疑自己、搞崩心态；Web 开发网上资源多、解决方案多，进步更平稳。
- **建议**：大一到大二上学期多做一些 ACM 题，对以后找工作刷算法有帮助；对算法、数学有兴趣或有天赋的同学参与 ACM 是很好的选择；但**不要把一切堵在 ACM 上**，要抽时间学习基础开发技能，多一条路更稳。

- **ACM 的本质是数学，与开发天差地别**：虽然都是码代码，但一个偏动手实践、一个偏动脑思考；竞赛厉害的人往往就两类——要么学得早学得多，要么真的聪明（从高中甚至初中就开始学算法竞赛的选手往往两者兼备）。所以弱校很难拿大奖（作者的学校 300 人里只选 30 人进集训队、10 支队伍里两三个获奖，金奖要追溯到十几年前），而且团队赛还要看队友，光自己强不够
- **不深入的算法竞赛是「半瓶子醋」**：算法竞赛「多投一点时间就能再强一点」的特性会诱导人投入所有时间，但又永远天外有天、总被更强的选手碾压；如果兴趣没那么大，不必赌自己就是「天选之子」
- **功利视角下的一键三连**：搞项目 + 去实习 + 作品/竞赛三管齐下，性价比远高于死磕算法竞赛——笔试面试中的数据结构算法考察本质是「过关性考试」，刷 LeetCode 就够，而 ACM 是现场即时排行的实打实竞赛
- **核心结论**：努力是刚需，但努力之前的选择更关键

## 三、有的放矢，十年磨剑

### 阶段目标

确定职业方向，围绕目标岗位打磨技术栈，这是一个重在坚持的长期过程。

### 核心做法

- **确定职业方向的时机很重要**：过早或过晚都不好。很多人上大学前对某个职业充满憧憬，真正接触后才发现不适合；大学时间短暂，没有太多时间迷茫和折返，因此先广泛尝试、再定方向。
- **综合多方面选岗位**：从兴趣出发，选择与兴趣和所学技能匹配的岗位；同时参考市场需求和数据，避免冷门职业；再考虑薪资、工作时长、地点等因素。
- **给自己定最高的目标**：比如进入互联网大厂，要相信自己——只有饥饿的狼才能吃到美味的饭。
- **按大厂招聘官网定技术栈**：直接看目标公司招聘官网的岗位要求，例如 Java 开发看阿里和美团官网、C++ 看腾讯官网、Golang 或 PHP 看字节跳动官网。
- **制定明确的计划**：把大目标拆解为逐项学习的小技术，参考网上的学习路线按主次排序，规定每项技术的学习时间，少走弯路，而不是杂乱无章、主次不分地学。
  - 以 Java 后台开发为例：一般要求 Java 基础编程、Java 并发编程、数据库、计算机网络、操作系统、设计模式等；技术栈可以是 Java、MySQL、SSM 框架、Redis、Linux 等。
- **精读经典书籍**：如 Java 方向看《Java 核心技术卷 1》《Java 编程思想》等。
- **不止于「会用」**：进大厂要懂「巧用」「精用」，甚至能复刻和创造——学 MySQL 要了解底层数据结构和调优策略，学 Spring 要熟悉底层设计模式和依赖注入原理。
- **不能纸上谈兵**：要能灵活运用知识开发项目，企业需要的是能解决实际问题的人才。

### 程序员的真实职业认知（常见误解澄清）

- **薪资是幸存者偏差**：程序员平均薪资确实略高，但「人均年薪百万」是极少数，只凭技术能达到这一水平的人少之又少；发量、手速也都与水平无关——手速快可能只是重复劳动、摸鱼聊天或打游戏练出来的。
- **程序员为什么会加班（996 的真相）**：① 代码越写越多、系统越复杂，陈年老 Bug 逐渐暴露且牵一发动全身；② 对排期的错误估算——只算了做需求的时间、没算改 Bug 的时间，而改 Bug 常常比开发更耗时，所以别把需求排太满，预留改 Bug 时间；③ 不会拒绝需求、缺乏经验、系统不易维护、身边人卷等。
- **算法和数据结构的真实重要性**：不是用不到，而是缺了知识根本想不到可以用算法更好地解决问题——同样是存储查找 20 万个单词，用数组顺序查找浪费时空间，知道前缀树就能大幅节省存储、提升查找效率。上层技术不断迭代淘汰，底层原理、编程思想和基本功不会变；前端面试算法比重不大，时间紧可先以框架为主，有空仍要补基础。
- **写程序追求「特定条件下的最优解」而非完美**：真实工作往往是权衡——空间与时间（如 HashMap 用内存换查找效率）、人力成本与资源（花钱买现成服务省开发时间）、需求与实现（天天做紧急需求就没空优化架构）。所以写代码前先调研设计、多思考几种方案权衡利弊，选相对最优解；对别人的代码也多些包容，放在他的场景下你未必做得更好。
- **代码量不等于水平**：真正写代码的时间很少，需求评审、方案设计、技术选型、沟通协调更花时间；职级越高、能力越强的人写的代码反而越少——他们更懂得用自动化脚本、代码生成工具脱离重复劳动，并把精力放在方案设计与系统架构等更高层决策上。
- **优秀程序员的标准绝不止技术**：还包括问题解决能力（同样的事做得更快更好）、业务理解能力（快速判断需求是否合理、梳理流程）、沟通能力（维护用户/组员/跨部门关系、提取有效信息）、产品思维（给出推动产品发展的建议）、管理能力（组织成员、推动团队）和分享表达能力（把学会的东西清晰地讲出来）。

### 如何看待「XX 已死、XX 已凉」言论与转行决策

- **言论来源无非 3 种**：① 真的有人找不到工作（大环境如此，不止计算机行业）；② 不希望你入行的人 + 跟风玩梗（劝退一波心态脆弱的竞争对手）；③ 培训机构渲染焦虑（诱导转 C++、Go、嵌入式等）。网上信息要客观理性看待，起码要有区分真话和玩梗的能力。
- **转行判断标准**：技术没学多久、转行成本不高、还没入行 → 可以转；已经学了很久 → 不要因为一些言论或几次失败直接放弃，除非你有更好的选择。
- **找不到工作的 3 大原因**：① 大环境没有之前好（无法改变，减少抱怨）；② 竞争力不够（没卷过别人）；③ 运气（不一定是你的问题，可能是岗位不匹配或同批竞争者更强）。
- **提升竞争力的 3 个方法**：① 提升技术——免费学习资源越来越多，想脱颖而出就要比别人学更多；② 提升经验——一定要「能干活」，看完教程后自己动手做类似项目并真实上线；③ 正确的方法——比如写简历要突出优势、证明项目真实性、用专业方式表达。
- **简历自测技巧**：去求职平台对比 20 份别人的简历，如果觉得自己的简历比 50% 的同学强，大概率能找到工作。
- **运气靠坚持对冲**：抓住每次投递、实习、面试机会；多加一位面试官/HR/技术大佬微信主动链接人脉；每天花 30 分钟多关注一家招聘渠道，不要嫌弃小公司、不要限定投递范围，先有机会再决定去不去。
- **转行前必做的 4 步功课**（以「大四 Java 后端想转运维」案例为例）：① 明确求职目标（预期薪资、公司等）；② 调研目标岗位学什么、学到什么程度能达到目标——面向岗位学习，目标是小公司就先查小公司的要求，别一上来学大厂高大上技术；③ 了解目标岗位的学习路径、学习周期与核心竞争力（如运维常需考证，先评估时间是否足够）；④ 做完功课再自问：现在方向真不能坚持了么？不满意的真正原因是什么？转方向 vs 继续学哪个更容易？把转行的时间投入深耕现在方向会不会更好？
- **临近春招/大四切方向风险太大**：已做了几个项目说明已投入很久，继续深耕已有方向的成本低于从 0 学新方向；同理，「看似简单、投入时间少就能找到工作」的方向往往更卷（否则就是收益低），不能用学过的教程数衡量能否找到工作。
- **备选方案思维**：后端开发本身就要学 Linux 部署管理项目，可把服务器运维当备选——优先投开发、其次投运维，不必把全部精力投入运维；「你放弃了，是在给别人机会」，盲目转行只会加剧内耗，想清楚「为什么转行」再决定（行业没发展/无趣/想尝试新职业且无生活压力 → 可大胆尝试；只因卷/觉得自己不行 → 不如掌握正确方法投入更多时间勤能补拙）。

### 开发岗还是产品岗：怎么判断自己适合哪个方向

> 一位软件工程本科生的复盘：做了三个月后端开发实习后，果断放弃开发、转向产品岗，最终上岸大厂。核心不是「哪个岗位更好」，而是「哪个岗位更适合自己」。（下文的转行判断标准同样适用。）

- **别只因为「专业对口」就默认做开发**：作者真正开始找工作时，下意识就投开发岗，但看着招聘网站上一个个陌生的岗位，既不知道选什么、对其所需技能也基本完全不了解。**早点实习、早点了解工作后到底干什么**，比在学校里闷头猜想重要得多
- **警惕「随波逐流」的方向选择**：努力奋斗是必须的，但**根据个体差异和兴趣选择适合自己的赛道与奋斗方向，比把努力当借口、不管不顾人云亦云更重要**
- **判断自己适不适合开发**：作者复盘出自己做不下去的两个原因——① 对技术缺乏热情；② 做开发时注意力不够集中、坐不太住。开发这项工种很大程度靠兴趣和天赋驱动——有兴趣有天赋的室友能深夜放着音乐哼着歌敲代码，而自己既体会不到敲代码的快乐、也体会不到实现某个功能的成就感。还要注意：**开发面试顺利通过，并不代表实际上手的「痛苦」会减轻**，所以拿到开发 offer 前也该认真评估自己能否长期从事开发
- **开发思维 vs 产品思维有根本差距**：一个像下蛋的、一个像孵小鸡的。先做两三年开发还是直接做产品各有利弊——积累技术经验对做产品有帮助，但两种思维本质不同，可结合自身情况权衡
- **产品岗也并非「零门槛」**：它需要技术（但专业性要求没那么高），同时需要大量组织沟通、设计规划能力；技术没学多久、转方向成本不高时可以考虑，反之建议谨慎（详见上文转行前必做的 4 步功课）

### 刚入职场被要求转语言，怎么办？

> 刚入职大厂的朋友提问：工作两年间一直在不同语言中转换，会和一直学同一门语言的人差距很大么？以下为个人回答。

- **刚毕业尽量多用同一门语言**：尤其 Java 这种高度封装、成熟的语言，「能写出代码」和「能优化代码」差距很大——并发编程、JVM 等知识需要系统学习，平时写增删改查用不到，一旦生产环境遇到内存泄漏、并发冲突、GC 问题就容易一脸懵逼。但人在江湖身不由己，工作需要的语言常与方向不同（如作者在某大厂时前端、Java、PHP、Python、Scala 都写过），无法决定和避免，能做的只有改变自己
- **重点关注 3 方面提升**：
  1. **学习自主性**：始终坚持某一门语言的学习，工作忙就每天读 1-3 篇技术文章，也是持续进步的过程。作者刚进公司天天看内部知识库、参与内部开源的 Java 轮子项目（有问题可直接和作者大佬交流，提升飞速），还跳出小组限制、自主学习整个大部门（几千人）的 Java 基础建设——阅读类库/框架源码、写轮子、优化别人的轮子、帮新人答疑，后来自己编写的消息推送 SDK 在内部开源并被同事使用致谢。长期自主学习一门语言，哪怕每天投入不多（或不是工作主语言），两年后进步也很大；反之两年一直跟着业务写重复的增删改查，即便一直写同一门语言也不会有技术成长
  2. **学习通用知识**：有句话叫「语言只是工具」——同方向的语言（后端 Java、PHP、Go）写起来基本没区别：① 框架封装得好，拿来就能用，无需过多前期学习；② 项目绝大多数代码是业务逻辑，而非某语言特有的代码；③ 数据库、Redis、MQ 等中间件及算法、设计模式、软件开发原则等思想独立于语言；④ 无论什么语言，开发项目的流程/方法/工具一致（需求分析、系统设计、开发、测试、部署上线，以及流水线发布、灰度发布、多环境隔离）。作者主语言是 Java 后端，临时帮同事开发 PHP 项目却毫无压力——框架和编程规范都有人搞好，只需写接口和业务逻辑（if else），部署用的 Linux 命令也早已烂熟。建议多学语言无关的通用知识，尤其 **业务理解能力**（能讲清负责业务的流程、意义与价值）；作者组长还给过建议：把视野打开、关注整个部门同事的业务，从更高视角整体分析问题，而非只关注自己的「一亩三分地」
  3. **高效自学能力**：学过的语言越多，学新语言越快。高效自学是对多个能力的概括——文档阅读能力（快速输入新知识的核心，工作中很少有保姆级教程，多靠文档甚至口头交流）、归纳总结能力、问题解决能力。落到工作中：接手同事项目先要文档，读完自己再归纳总结，就知道项目如何运行、有哪些开发规范、如何部署；遇到报错也能凭过去踩坑的经验和搜索能力快速解决。很多大佬都有跨语言能力、发展机会更多
- **警惕「学生思维」**：初学编程或刚毕业的同学容易保留——什么都去问别人、没有教程就不会做、从来不写总结、经常重复踩坑；这些都是职业发展的阻力，需要刻意改变。最终目标是成为**一专多长、各路开花**的强者

### 跨技术方向发展：先做好本职，再扩展边界

> 鱼友提问：已在前端岗位转正，日常需求完成后看后端书籍（《MySQL 技术内幕》《Redis 设计与实现》讲存储内核、引擎、服务架构设计）比前端更上头，该继续深耕前端还是转后端？以下为个人回答。

- **跨技术发展很常见，越往上层越需要一专多长**：作者在腾讯见过后端同学成长为客户端的 Leader、前端同学成长为后端 Leader 乃至整个技术总监；作者自己走的是应用开发通道（相比单一技术更侧重业务理解）。绝大多数情况下，前端、后端或其他技术都不是真正影响晋升的瓶颈（除非所在部门以技术研究为主），**卷技术的前提是看技术实际产生的成果与价值**，而不是自以为技术强。
- **先做好本职、成为团队的技术核心，再向外扩展**：本职是前端且刚进公司时，建议先把自己的岗位做到组内**头部**——同事平时遇到问题能第一时间想到先问你，那就真的成功了；此时再把更多精力分给其他方向（比如后端）。否则即使会一些后端，对团队内的技术掌控力、业务完成效率、同事对你技术的信服度提升都不大。
- **扩展方向也要讲究性价比与目的性**：对后端书籍感兴趣可以看，但要**控制好时间**并明确目的，最好能对当前工作有直接帮助——比如读计算机网络、HTTP 协议，能更好地和后端通过网络接口协作、提高整体工作效率；即使把 MySQL 内核研究得很深，想从前端转后端也需要一个过程，而且对当前工作帮助有限（很多后端同学也不了解 MySQL 内核）。很多事情都能做，但要考虑性价比，建议做好长期计划、一步一步来。
- **综合能力比单一技术更影响发展**：业务理解能力 + 高效工作能力（同样一个工作交给你，能用更少的人力和时间更漂亮地完成，更容易得到领导赏识）+ 打破边界（不仅关注自己的工作，还关注同组人的工作，在完成自己目标的同时为组内业务发展或公司技术建设做点事，会大大加分）。作者在腾讯暑期实习时参与公司内部开源项目、和内部技术大牛交流，之后在组内做技术分享、负责越来越多项目，工作一年就拿到连续 2 次优秀员工（四五星）和绿色通道名额。

### 在职成长：技术落后时的自救与心态

> 工作后公司技术落后、工资低，想跳槽又拿不出项目、水平一般，怎么办？结合鱼友提问的回答与个人经验。

- **改变不了外界环境，就改变自己**：作者自己也长期被历史遗留问题折磨，但依然保持乐观——要么更努力地朝目标前进，要么重新选择目标，但无论如何心态要稳、不要躺平。工作中的收获未必是技术提升，也可能是做人处事的经验方法。
- **不被重复工作「同化」，坚持持续自学**：作者每天利用早餐、午休、下班之后的时间**自学**（阅读文章、看视频教程、自己做项目），是这些工作之外的努力带来了更大的提升和收益。日常需求之外的时间才是拉开差距的地方（对照上文「跨技术方向发展」与「刚入职场被要求转语言」的自主学习建议）。
- **想跳槽但没资本，先做 3 件事**：① **分析现状**——列举自己目前会的技术，在学习路线上找到当前位置，继续按路线学新技术；② **没有拿得出手的项目就自己做一个**——参考公司的业务场景去设计系统（注意不要抄袭），或者直接用学到的新技术重构公司的代码；③ 养成每天阅读文章、持续记录和总结的好习惯，任何一天都不要让自己停止学习。
- **做项目的方法**：严格按教程/视频的步骤来（文件名、包名、依赖、版本号都保持一致，演示有差异就容易出问题）；排查 Bug 要有耐心、完整走一遍流程；**不管 Bug 有没有解决，都记录踩坑经历**；不要闭门造车，多和人交流——学习时脸皮厚一点、社牛一点，机会总是偏向善于沟通交流的人。
- **别被条条框框束缚**：不要背代码，也不必追求高大上的项目，想做什么就去做什么，兴趣是最好的老师。编程能力和解决问题的能力，正是在一次次开发项目中提高的，这也是企业招聘时看重项目经历的原因。

### 被老板说「能力不行」，怎么办？

> 鱼友提问：23 届毕业生实习近一年、已转正，老板约谈说「能力不行、没有团队要你、不养闲人」，建议离职或再给一个月看表现。以下为个人回答——先端正心态，再依次做 5 件事。

- **1、复盘分析**：想清楚这段时间工作哪里出了问题、为什么老板此时才说（已待近一年，是不是最近某件事让老板有了不好的评价？），也可能是公司效益不好、随便找个理由劝退。**最关键是分清是自己的原因还是其他因素**——先发现问题才能针对性解决；若确实是自己的原因、八股也忘光了，就先争取抓住现有机会，老板愿意再给一个月说明还有希望
- **2、寻求帮助**：意识不到问题就主动找老板、同事和信得过的人交流，礼貌询问「如何改进才能达到要求」。**工作内容一定要和老板的预期对齐**——做的事对公司没有价值、无关痛痒，技术再好也很危险；跟人交流时要把自己的情况完整客观地说明，别让对方带着猜测、在缺背景的情况下给建议（实习这么久该有上千字的背景，而不是只有几句话的提问）
- **3、制定计划**：明确老板的预期和改进方向后，制定周计划、日计划，把改进方案写进文档或表格，每日进步一点点
- **4、记录总结**：持续记录工作和改进，尤其要**让老板注意到你的改变**——多积累明确的成果，如某项工作提前完成、线上系统没出 Bug
- **5、寻找备胎**：若确认不是自己的工作或能力问题、或感觉希望渺茫，就赶紧找下份工作。巧妙做法是——老板觉得你技术不足时，去补学**对自己找工作也有帮助**的技术，相当于用同一份时间兼顾两种未来
- **心态**：不要因当前困境放弃，把它看作改变的机会；老板没直接开掉、愿意给改进时间，已经比很多公司好了

## 四、学以致用，宁静致远

### 阶段目标

通过作品、竞赛和实习把知识转化为实践能力，让简历有内容；同时保持平稳心态，不受外界干扰。

### 核心做法

- **实践靠自我驱动**：互联网公司产品、运营、策划等岗位都要求较强的实践能力，而学校课本偏理论、多少有些过时，实践创新要靠自己。
- **边学边练**：否则看完一本书打开电脑一行代码都写不出来，再翻书找代码会浪费大量时间。
- **从 Demo 到完整作品**：没有创意时先按视频教程做一个简单 Demo 并好好保存；学到新知识后对现有 Demo 改造和包装——添加功能、优化性能，尽量做出完整的作品。
- **让作品产生价值**：用作品完成课程设计作业、参加作品类竞赛、申报科创项目、申请软件著作权和专利；做得好的作品甚至可以正式上线。
- **积累简历亮点**：作品带来的「项目经历」「竞赛奖项」是面试官非常看重的。
- **先找实习**：正式求职前先找一份与目标岗位相关的实习。数据表明，入职头条的员工中 50% 曾在头条实习，网易员工中超 70% 有实习经历。
  - 第一段实习要求不必太高，但最好与职业目标契合，感受真实企业环境、学习工作经验、在团队中实践技术。
  - 不用担心水平不够：参加面试能更快、更有针对性地发现不足，面试后复盘总结反而成长更快。
- **找实习的平台**：牛客网、实习僧 APP、找学长学姐内推、直接在企业招聘官网投递简历等。

### 找实习的判断标准

- **判断标准**：是否具备干活（甚至打杂）的能力。一般情况下，主流开发框架（后端 Spring Boot、前端 Vue）已经学完、完成 2-3 个项目、能写出一份完整简历后，再去找实习。
- **例外**：有其他特殊的牛 X 经历或学历特别好，可以提前去实习，因为经历本身也许已经证明了你的能力。
- **好处**：检验自己的技术水平和实践能力是否过关；提前积累求职面试经验，哪怕没通过也是有收获的；成功找到实习后，可以提前接触工作环境，判断自己是否适合某个岗位，帮助做出未来规划。
- **建议**：达到标准后多关注求职信息，建议找寒假实习或日常实习，或把它当作目标，投递试试也不亏。

### 实习期跑路与短期实习的影响

- **提前离开的顾虑**：拿到小厂实习 offer 后中途去中厂/大厂（「刚来就跑路」），从公司角度确实浪费了招聘成本，但公司对这种情况一般也没办法；提前离职通常不会有不良影响，前提是离职前坦诚和领导沟通好
- **短期实习能否写进简历**：取决于两点——① 做了什么：只实习几周大概率做不了完整项目，能写的内容会很水、很有限；② 精确周期：小于 2 个月在招聘方看来是「不稳定」信号、会给简历减分；大厂实习因平台光环（可能只是业务不合适），影响相对小
- **接受实习 offer 前要了解**：入职后 1-2 个月内大致做什么工作、负责什么项目、公司对你的培养计划——问清楚这些才能评估这段实习能带来的成长
- **签合同注意**：如果已预判「可能实习不久就走」，签实习劳务合同时留意有无提前离开的约束条款；一般提前一周和领导说即可
- **先想清楚值不值得**：实力足以进中大厂时，不必在练手的小公司纠结；实习不是必选项——自学上线项目、竞赛同样能增加实践经历，别到头来浪费了自己和对方的时间

### 实习常见问题：时长、薪资与学校不放人

- **实习对找正式工作的影响**：有一段实习经历是加分项，但**实习质量与时间长短不一定成正比**——一般 2 个月左右的实习期就已经比较完整，这期间成长效率最大；「年薪 30w+」没那么好拿，不是有实习经历就能达到，跟个人水平、地区等都有很大关系，机构课程的说法别全信
- **实习时长**：至少 2 个月，3 个月也不算久；第一个月可能都在熟悉环境、流程和代码，未必能直接接触业务、学到的东西有限，真正上手开发上线那段时间成长最大
- **实习薪资**：网上说的实习期 6-7k 偏高（比作者当年在腾讯实习还高），多数人拿不到这个数字
- **学校不放人怎么办**：利用大二~大三、研一的寒暑假去实习（大多数同学也是这样）；如果时间充足，可以提前修完课程、腾出大三的日常时间实习（需提前和辅导员商量）
- **课程与实习冲突的解法（真实经验）**：① 申请「自修」——先和辅导员/老师沟通协调，承诺利用业余时间自学课程、完成作业、考试照常参加，再走学校自修申请流程（一次申请 2-3 门即可，量力而行，别给自己扛不住的压力）；② 与公司协商弹性到岗——和 leader 沟通每周只到岗 3-4 天、其余时间在校远程办公（周末也可算上班天数）；③ 实在协调不了时，该放弃的（某门课/某个机会）就放弃，把没放弃的部分做到最好——机会是靠沟通和努力争取来的
- **为什么实习总被安排打杂**：换位思考——能力还没达标时，企业不会把有难度的工作交给你；想被安排复杂任务，先让自己的能力配得上

### 实习打杂天天 CRUD，如何争取成长

- **面试官想从实习经历看出什么**：你解决过什么有难度的问题。只「看懂」公司系统里别人写的复杂业务就写进简历，缺乏真正理解，面试官问深一点容易被识破；把 Leader 完成的工作说成自己做的同理
- **抱怨学不到东西前先自问 5 个问题**：① 简单的工作做到最好了么？有做到让上级满意么？② 有想过主动学习公司其他业务、主动承担工作么？③ 有利用公司资源来提升自己么？④ 有把自己的想法和导师/上级反馈过么？⑤ 工作态度足够认真，还是眼高手低看不上这份工作？
- **成长需要自己去争取**：公司不会单方面给成长。比如和导师共同完成有含金量的任务时，主动交流说想参与业务设计或部分代码实现；导师解决过的问题，想办法把解决方案学会
- **主动做事清单（作者腾讯实习亲历）**：参与公司内部开源项目贡献代码；导师繁忙时主动分担工作；旁听导师的晋级答辩（提前学到答辩技巧和系统设计方案）；熟悉公司内部基础技术建设并整理笔记供组内学习；积极参与内部分享会拓宽业务边界；主动在组内给大家做技术分享——这些没人安排，做了就是加分
- **把小事做到超预期**：作者带的实习生把每个工作都完成得很好、项目文档写得非常完善，不到一个月就被授予核心项目源码，很快成为核心负责人、收获正式 offer
- **争取过仍无果**：没什么好遗憾的，继续努力自学，**哪怕是摸鱼也要抽时间自学**，尽快去更好的公司

### 实习转正：字节实习转正的经验

- **新人培养靠自觉**：有的实习生入职有 mentor 一对一，有的连 mentor 都没有、Leader 只帮忙找工位；大厂内部资源开放（可看不同部门的项目代码和文档），「成长是个人的事情」，利用好资源没人带也能进步
- **尽早定目标**：实习开始就明确目标——打算转正？纯粹积累经历？还是学某个方面的技术？目标决定投入方式
- **转正靠实习期表现**：想转正就要主动承担工作，努力被 Leader 看在眼里，答辩和加面时才有好评（案例：实习约 2 个月，9 月答辩+加面通过拿到意向 offer）；答辩 PPT 的建议是**把「工作内容、方法和成果」讲清楚**
- **说话的艺术**：吃饭等非工作时间多和同事/上级交流（实习感受、学习情况、热点话题都行），尽量不要脱离团队
- **大胆提问但先梳理清楚**：刚接触公司级项目，很多问题不是能凭一己之力解决的，对文档/业务/代码/规范不理解要即时提问；提问前先理清问题、起码知道自己在问什么（见 [[提问的智慧]]）；前期不确定的地方都要找时机确认，不要想当然——存在大量信息差
- **向上管理**：为取得更好的绩效结果，有目的地配合上级工作、获得认可——完成需求的同时提炼方法论（即使可行性不高也能体现思考）；记录自己的代码量、Bug 数、开发进度，整理成文档贴在显眼位置，让 Leader 随时了解你的工作情况与项目进展
- **持续打探信息、留后手**：关注岗位信息、转正 HC 数量、竞争人数、其他同学的学习进度；HC 数量不是 Leader 能决定的，如果感觉 HC 过少或候选人很多，就得考虑尽早准备其他机会
- **平衡学校课程与实习/求职**：决心就业的话，在不挂科的前提下，可以充分利用课堂时间自学（刷题、背八股文）；大学课程重在打基础、很多与企业实践有偏差，要学会自己判断、合理分配时间

### 没有实习经历，如何进大厂

- **实习经历不是必须的**：简历是综合评价（教育经历、个人技能、学术研究、实际经历、项目经验、荣誉奖项等），没有实习经历，只要其他方面能吸引面试官——比如用**和求职方向相关的项目 + 科研成果**来弥补——依然能有面试机会，之后凭实力通过面试
- **学历是加分项但非唯一**：学历好（如名校、科班）在简历筛选时有加分；学历一般就要尽量争取实习经历或多做项目，机会要靠自己争取
- **好的项目需要持续打磨**：在合理的前提下，把学过的技术尽可能多地运用到项目中；一定要有自己的「主打项目」，而不是所有项目都一个样
- **基础要持续巩固**：操作系统、计算机网络这类可以面试前 1~2 周突击背诵；数据结构和算法必须坚持每日刷题——数量不必多、重在坚持，建议从面试前 2 个月开始，时间更充裕
- **编程思想 vs 解决问题能力**：编程思想指算法/数据结构/设计模式等基础学得好，遇到问题能想到运用它们解决（刷算法题是很好的提升方式）；解决问题能力指根据需求快速设计出架构和程序流程，并能快速编码实现。两者都强才是优秀程序员；对大多数同学，计算机基础学到「面试水平」即可，先重点提升做项目、解决问题的能力（以后在基础架构部门则要求基础极深、甚至对底层有自己的见解）
- **深挖一门技术也加分**：对某门语言/框架研究得很透彻、每次版本更新能给出自己的见解、能给开源项目提 issues 或贡献代码，面试都很加分
- **学习性价比**：时间足够学什么都可以（学大数据计算的过程中也能学到后端开发思路）；时间来不及不如多做项目、参加竞赛——学的东西写不到简历上，求职性价比不高。学完微服务后可继续学并发编程、JVM、容器等进阶知识

### 考研与就业两手抓

- **答案**：能两手抓，且建议两手抓，给自己多一条退路。
- **大三寒假前**：把更多精力放在学习技术、做项目、提升实践能力上，趁早找一份实习，切身体验企业实际工作氛围，帮助自己做出未来的规划和决策。
- **考研全力准备一年足够**：过早准备学了就忘、性价比不高；而且万一失利后，就业也会更难。
- **读研的价值不只在能力提升**：过来人的经验是研究生阶段能力未必大幅提升，但读研本身是一段特殊的人生经历——「生命对每个人而言只有一次，为什么要放弃读研这段特殊的经历呢？」
- **路是自己走出来的**：身边劝工作、劝读研的各占一半，但大家都只是站在不同角度思考，没人知道什么选择最适合你；不要让别人帮你选择。

### 考研 vs 就业的利弊对照

- **别把考研当「退路」**：如果内心不想考，就不考——考研需要长时间静下心来准备，目标不坚定、动力不足时，考研可能比学编程更难；眼下立刻行动起来，才是纠结的解药。
- **大二下必须利用好**：多学喜欢的技术，争取暑假找份实习感受工作氛围；不建议 all in 考研，从大三再开始准备也有一年半载，完全来得及。
- **考研的好处**：① 本科学校一般时，提升学历能增加通过简历关的概率，且 AI、大数据、计算机视觉、区块链等前沿/细分方向通常只有研究生才有机会；② 本科知识基础零散，读研有机会「咸鱼翻身」；③ 为喜欢研究、持续学习的同学提供好的环境与资源；④ 享受校园时光；⑤ 回应家人的期待；⑥ 提升自信。
- **直接就业的好处**：① 很多技术岗位并不需要研究生学历，研究生毕业后一样做开发，前沿岗位数量少、竞争更卷；② 不必学高数等考研知识（对多数岗位没帮助），省下时间专注实打实的技术；③ 尽早进入产业界，更容易感知行业变化与科技前沿动态；④ 互联网行业不确定性大，可能去年某大厂大力招人、今年就因寒冬凉凉；⑤ 提前赚钱和晋升（如大三暑假开始实习，比同届研究生早约 2 年达到同样职级）；⑥ 走出校园成熟更快、更有责任感；⑦ 在企业中紧密合作，获得更多沟通经验、企业级项目开发和项目管理技巧；⑧ 不用处理学校杂事；⑨ 没有论文和毕业压力。
- **判断标准**：看自己的兴趣——喜欢研究/学术还是实干/产业，不要随波逐流；不确定就趁早去体验（大二暑假找份不错的实习），体验过才知道是否适合；无论考研还是直接就业，只要肯努力、抓紧学习，都会有很好的发展。

### 考研的风险与失败后果（真实抉择复盘）

> 另一位同学的复盘：大学前三年一直打算考研（大三暑假已学完高数），最后却放弃考研转去求职。他的权衡过程，供「要不要考研」纠结中的同学参考。

- **先分清自己为什么考研**：是想做学术、对科研深感兴趣，还是只「想混个学历」、随大流做这个年龄这个节点「同学眼里父母眼里很该做的事」？如果只是随波逐流，考研不算坏选择——计算机硕士学历仍值钱，研究生阶段别太作、简历别太烂，过多数大厂的简历筛选没问题；但肯定不是最好选择
- **随波逐流读研的两大风险**：① 研究生的本职毕竟是做研究，而计算机专业薪资高、找工作卷，水一水毕业时容易陷入尴尬——想走算法岗科研水平不够、竞争不过博士，做前后端开发开发经验又不如某些本科生；② 国内硕士两年半到三年时间很长，要掂量这段黄金年龄的三年对自己是不是最佳选择（作者认为工作三年可能比读研三年收获更大）
- **考研失败的后果不亚于高考失利**，正常情况下只有两条路：
  1. **找工作**：完美错过求职黄金时间秋招——秋招 0 收获、即将到来的春招又 0 准备，非常被动；即使找到了工作，同等程度的努力用在找工作上的效果可能比考研更稳定、更显著，而第一份工作对人生至关重要
  2. **准备二战**：先想清楚一战失败的原因是什么，想不明白的话二战失败概率非常高，届时只会面临更尴尬更难的局面；二战还要先扛住较大的心理压力、重新掂量自己的能力，再给一次机会能不能考过
- **结论**：硕士学历一方面越来越平民化、另一方面越来越难考（计算机研究生报录比低、大神多）；决定考研就要下十足决心、做足准备、尽量一次上岸，并想清楚自己是否做好了承担这份风险的觉悟

### 考完研后的寒假：春招冲刺行动清单

> 刚考完研的同学，无论自我感觉好或坏，都要立刻行动起来，不要等结果出来再做准备——你是在和一直在准备找工作的同学竞争，没有时间耽误了。考研过程已磨练了心性、巩固了计算机基础，立刻开始备战什么时候都不算晚，不必因别人进度快而焦虑；放下游戏和短视频，行动是第一生产力。（只考虑读研的同学可以忽略。）

1. **明确方向**：先确定 1 个目标岗位方向（前端、Java 后端、Go 后端、测试、运维等），不要想着全栈、前后端两手抓都去碰运气；优先选自己目前所学知识最多的方向，避免从 0 开始；别花时间纠结哪个方向卷不卷，主流方向（Java、C++、前端）更适合大多数人，实在不知道选什么就先学 Java（网上资源多、容易坚持学下去）
2. **先认真准备简历（而不是先背题、刷算法）**：写简历的过程就是回顾、梳理、总结自己学过的所有技术知识和做过的项目，便于发现不足、明确之后的学习改进方向
   - 技术板块不知道怎么写：想想自己学过什么技术，去网上看培训机构的课程大纲快速浏览该技术的知识点，再针对性地学习和查漏补缺
   - 项目板块不知道怎么写：翻一翻之前做过的课设，无论项目好坏，先把用了哪些技术、做了哪些功能写上去——有总比没有好，后面再持续完善
   - 写简历过程中有压力是正常的，要做的就是克服压力、弥补不足
3. **制定计划**：从大到小的计划都要有（下个月完成一个项目、这周看完一套课程、今天上午学算法、下午做项目），计划越细越好，有效防止时间偷偷溜走；计划内容结合自己的简历来定——不熟悉的知识点按学习路线一个个弄懂并写出代码；项目没亮点就学习更多技术并应用到项目中（把课设做得更好更精细）；还没做过项目就先学开发框架（后端 Spring Boot、前端 Vue），再抓紧看网上的项目教程去完成
   - **设置里程碑**：给计划定关键时间点，如 2-3 月春招开始，1 月底前完成基础巩固并上线 1 个项目；2 月第一周复习数据库、第二周复习缓存、第三周复习 JVM
   - **不会做计划时**：参考其他同学的学习计划和总结，或和其他同学交流；也可以查看招聘官网的岗位描述，确定学习重点
   - **Java 岗突击参考计划**：① 学 Java 基础（黑马的 Java 教程，常见算法和集合进阶可跳过）② 学 Java Web 开发框架（黑马 Java Web 一条龙教程，前端部分可跳过）③ 直接做项目、以项目驱动学习（网上搜项目教程即可）④ 系统学习后端中间件（Redis、消息队列、Elasticsearch 等，B 站搜教程）；每天冲刺学习 6-8 小时，2-3 个月可完成项目上线
4. **上线项目**：校招面试主要考项目、算法、专业技能三部分，项目最能区分面试者水平——能看出编程能力、编程经验、编程思维、学习能力、自主性、问题解决能力；好的项目经历还能主导面试：自我介绍时提到项目用了数据库、缓存等技术，面试官就会顺着问项目里的技术，因为自己做过，回答起来才更自然
   - **项目一定要上线**：提供可在线访问的地址；否则万一和别人的项目撞车，面试官可能觉得你是抄的、不够真实
5. **刷算法题**：算法是基本功，大厂面试基本每轮 2-3 道；但如果简历还没有已上线的项目、技术没学到位，每天刷题时间不要超过一个半小时、做 2-3 道巩固语法即可——算法无法突击速成，而且刷题不能给简历增加亮点（刷了 200 题简历还是老样子），性价比远不如做项目
6. **准备面试**：技术和项目准备得差不多（符合公司岗位描述要求）再开始；从简历出发——简历上着重写了什么技术，就去网上搜该技术对应的面试题和题解，而不是什么都背；后端通用高频考点：数据库、Redis、计算机网络、操作系统
   - **八股文确实有效**：经典面试题就那么多、反复问来问去，还能帮自己查漏补缺（很多知识是学编程时没接触过的）；例：Java 后端常问 MySQL 如何性能优化、JVM 内存结构、Redis 是单线程还是多线程，前端常问网页性能优化、Promise 原理、HTTP 和 HTTPS 的区别
   - **背完要动手实践**：时间允许就动手做一遍，比如试着提升自己项目中的数据库查询性能，面试时才能说「我做过」而不是「应该是这样吧」
   - **认真准备自我介绍**：流畅地介绍自己的优势、做过的项目、擅长的技术，便于引导面试官提问
   - **面试问答随缘**：不同面试官/HR 的问题差别大，直接准备的命中率不高，不如先做好其他事，参与面试后持续复盘总结

**时间安排**：先花 1-2 天写简历总结、再花 1 天左右确定学习计划；寒假这一个月必须利用好——每天上午趁头脑清醒做 1-2 道算法题（或学新课程），下午或晚上做项目、实践新技术，睡前背面试题（第二天醒来没睁眼时回忆一遍，印象更深刻）；2 月份大公司陆续开始春招（暑期实习生 + 校园招聘），2-4 月是春招黄金时间，**早就是机会**——准备得不错就抓紧海投简历、多去面试；不参与春招的，可利用寒假连续时间和学长或朋友一起做个项目（为年后的作品类竞赛做准备），或系统学习 2-4 个技术，连续每天学习的效率比开学后断断续续地学高很多。

### 如果不考研：从准大三开始的追赶计划（以已学完 JavaWeb 为例）

1. 暑假结束前学完 MySQL 数据库和 MyBatis
2. 9 月份学完 Spring MVC 和 Spring 框架
3. 10 月份学完 Spring Boot，并独立完成一个小型后端项目（如用户中心项目）
4. 12 月份前学完 Spring Cloud 微服务、Redis、RabbitMQ 消息队列
5. 次年 2 月份前做完一个微服务项目，开始准备简历和大三暑假的暑期实习（刷算法、背面试题）

- **平均每天至少投入 3 小时**，按时完成该计划，技术知识基本能达到大厂要求。
- **进大厂不止会技术**：平时多了解系统设计、架构设计等后端知识；多做项目、参加竞赛丰富实践经历——「学过」和「会用」是两个完全不同的境界（大厂要求的技术 95% 的同学都学过，只有 5% 能灵活运用）。
- **不建议赶寒假实习**：暑期实习招聘开得很早，技术学习时间紧张的话，不如集中精力提前准备暑期实习。
- **不必有学历焦虑**：学历已比大多数同学好；焦虑没有用，不如努力学习。

- **宁静致远的心态**：找实习和求职时难免受外界影响——有人拿高薪 offer，有人抱怨竞争激烈。这些夸耀或负面情绪与自己无关，像考场做卷子，提前交卷的不一定考得最好。
  - 用关联的视角看待：拿到好 offer 的人往往付出了更多努力、舍弃了更多娱乐时间；面试失败往往是因为付出不够或有失误，而不是面试官戴有色眼镜。
  - 多和优秀同学交流，分析他们成功的原因，学习经验方法；记录并吸取每一次失败的教训，多多自省。
  - 保持宁静，按照自己的规划一步一步往前走。

### 大学期间用编程技术赚钱的 9 种方式

支持大学期间用自己感兴趣的、与未来发展目标一致的技术赚钱——既能解决生活费问题，又能锻炼技能、激发编程兴趣。按实践难度与推荐程度排序：

1. **找实习**：工资稳定可预期，还能在企业中学到东西；暑期、寒假、日常、线上实习均可，甚至可以同时兼职。工作内容最好与自身发展方向相关，且不要影响正常学习进度，翘课实习大可不必。
2. **帮忙做项目**：需求不会主动找上门，可以主动请缨——联系辅导员、老师或项目组学长，表现出做项目的决心和诚意，一般都会被接受；一个需求做好后老师还会帮你宣传，需求和钱滚滚而来，还能混个脸熟。
3. **维护项目**：学校的很多老项目需要维护翻新，难度不大、占用时间不多（如帮学院维护年久失修的服务器、小系统），赚点小钱很轻松。
4. **参与竞赛**：档次和获奖级别越高奖金越多（少则几千、多则上万），对简历帮助也大；但凭本事赚钱，想拿大奖要付出日以继夜的努力。
5. **进实验室**：加入学院实验室跟老师和学长做项目，通常意味着有稳定收入（学院经费充足）；项目经历还能写进简历、面试有的聊。
6. **申报项目**：国家级、省市级大学生创新创业项目难度和完成度要求都不高；国家级项目经费 1-2 万，虽未必能直接提现，但可以拿来购买设备书籍，还有可能开劳务费。
7. **搞工作室**：学校鼓励学生工作室并给经费支持，但对技术兴趣和精力投入要求很高。
8. **辅导功课**：很多非计算机专业也要学 C/Python/Java/Web，愿意花钱找计算机同学速成辅导；讲课赚钱的同时还能帮自己复习、发现曾经疏忽的知识点，一举两得。
9. **接外包**：程序员客栈、猪八戒等平台有短期和长期外包；但不建议在校生接大外包——需求变更风险大、容易被甲方拿捏，也别信网上「几天几万」的噱头。

**原则**：大学期间无论如何要以学习为主，多做和未来目标相关的事情。赚钱方式很多（拍抖音、直播带货、做公众号等），但别人的成功未必能模仿；先踏踏实实学好技术再考虑赚钱，或者像上面提到的方式边学边赚，不要掉进钱眼里。

### 为什么不建议大学生接公司单

适用于所有没有独立负责开发过完整项目的同学，5 个原因：

- **风险 ≥ 收益**：接公司单要走正规合同，大学生作为乙方缺乏合同意识、处于弱势地位，公司可能利用你的「无知」变着花样加需求、让你打杂、甚至赚违约金；相对于收益，没必要冒这个风险。
- **缺乏掌控力**：对项目开发流程、需求、验收标准不熟，难以保证按时交付（但凡一个细节没考虑到就可能导致延期）；校园教学项目和企业实际项目的差别巨大——时间要求、需求变更、验收标准、项目稳定性等因素，很多同学连自己的问题和需求都描述不清，更别说掌控公司项目。
- **缺乏判断力**：接单价格没有统一标准，要多了显得无知、要少了等于亏本打工，也很难找到市场价参考。解决方法：给自己「标价」——预估项目耗时 × 自定时薪算出总价。
- **学业压力**：课程、考试、学校活动会占用时间，导致项目延期风险；投入过多时间在项目上也会影响学业和技术学习。
- **职业发展**：大学时光非常宝贵，除非生活所迫，尽量不要做和提升自己无关的事情；如果能力和项目经验已经非常丰富，接单确实能进一步提升能力，也可以接。
- **更推荐的替代方案**：多做自己的项目、做开源项目、和同学组队参加竞赛、参与老师的实验室项目、找正式实习，同样能增加经验；即使真想接单，也尽量帮同学做程序这类低风险方式，而不是接公司单。

### 软著（软件著作权）：要不要申请

> 软著即软件著作权，是为自己开发的软件申请的正式所有权。申请成本极低、价值有限，但仍建议大学生申请一个。

- **申请成本极低**：自己按流程写一些文档、复制粘贴源代码（哪怕是增删改查的 Demo 项目）提交即可；甚至可以在淘宝代买，几乎什么都不用写，取个标题等证书就行
- **价值不高**：能轻松拿到（甚至买到）的证书，认可度大概率不高；挑战杯等作品类竞赛路演时几乎每组都有几个软著、专利、专家推荐，软著分量最小、已不是加分项；找工作时认可度也不高——重点还是看做了什么项目、如何在项目中运用技术
- **但仍建议大学生申请一个**：成本低，有一个总比没有好；写进简历能体现自主性——「自己做软件申请软著」比「做了个课程设计」更有说服力；不少面试官自己也没申请过、不了解软著的价值，可能反而觉得有分量
- **用开源项目申请的前提**：用别人的开源项目做课设/毕设/申请软著，一定要有自己动手的部分（给项目换皮、改造），不要生搬硬套；把源码拿去售卖、或完全不提原作者，则有侵权风险

## 五、锋芒毕露，放手一搏

### 阶段目标

在具备技术储备、项目经验和实习经历等硬实力的基础上，用简历、自我介绍、面试等软技巧把优势全部展现出来。

### 简历的构成

1. **个人简介**：基本信息、照片、学校、成绩等。
2. **个人技能**：熟悉的技术知识，即技术栈。
3. **竞赛奖项**：参加过的竞赛和获得的奖项。
4. **项目经历**：课程设计、学习作品、竞赛作品、实习项目等。
5. **科研学术**：学术研究和科研成果。
6. **实习经历**：在哪实习、做过什么、带来什么成果。

### 简历 8 技巧

1. **一页排版**：简历必须一页，排版整洁清爽，色调不宜过暗或过亮，可以使用淡蓝色。
2. **亮点放上**：分析个人优势，对各板块排序，把亮点放在上面。
3. **用词专业**：文字精炼，用词专业，拒绝口语化；简历是给专业面试官看的，不用担心他看不懂。
4. **STAR 梳理项目**：用场景、任务、行动、成果来梳理核心工作，成果最重要，最好列举明确数据（如「使用 xx 技术将项目并发量提升 30%」）；每个项目介绍不宜过长，给面试官留提问空间。
5. **用简历引导面试官**：面试官常从简历中挑感兴趣的项目或技术提问，必须足够熟悉写上去的内容，提前想好对策：用了哪些技术、为什么用、有什么亮点、怎么优化。
6. **HR 点评 + 借鉴他人**：写完通读几遍，找专业 HR 点评，多阅读借鉴他人的简历。
7. **针对岗位定制**：针对不同岗位和岗位描述准备不同简历，在细节和内容上调整，例如投递产品和运营岗时，项目和实习介绍分别侧重对应职位。
8. **适度夸大，不可欺骗**：内容允许适度夸大但绝对不能欺骗，尤其适用于项目不多的同学，但要注意别被面试官戳破。

### 简历造假的代价：不诚信 · 不负责任 · 不公平

> 借 23 届某同学简历造假被扒出、举报者专门写「论文」举证一事，聊聊简历造假的真实代价。作者大二暑期实习时同批入职的一位同事，因被查出多报一两年工作经验，没几天就被开除。

- **不诚信**：公司按「3 年经验」的标价给上万月薪，你没到年限却靠造假拿到同样薪资，从公司角度看并不合理
- **对自己不负责任**：社招要求 3 年经验，是希望候选人有能力应对工作中的问题；只工作 1 年却写 3 年，面试也许能靠背八股蒙混过关，但入职后经验和水平很容易暴露，既耽误项目也让自己「怀疑人生」（有鱼友就提问：「包装了一两年经验进公司，但安排的工作完不成怎么办？」——欠下的债总要还，想留下只能抓紧补课、加班加点）；即便没被查出，也可能因能力不足过不了试用期，白白浪费时间
- **对他人不公平**：坑位有限、人人之间存在竞争——某公司只招 2 人，谁奖项多谁加分，我编造几个奖项压过你，你愿意么？上面那位同学之所以被扒，很可能就是造假影响了别人的机会
- **建议**：除非「走投无路」，否则真心不建议造假，把心思花在提升自己上；也别羡慕靠造假混进公司的同学，出来混迟早要还
- **没有学历、奖项和经验的替代思路**：先把学过的技术（没有就去学）、做过的项目（没有就去做）认真梳理一遍写进简历并尝试投递；有回复最好，没回复就去看网上其他同学的面经、找自己简历的不足；实在没办法了，再考虑适当「包装」去争取面试机会帮助自己进步——**打铁还需自身硬**

### 简历常见「通病」：项目介绍过长 · 描述宽泛 · 过于直白 · 用词随意 · 没有重点

> 帮小伙伴们改简历时反复出现的 5 个共性问题，可作为投递前的自查清单。

- **1、项目介绍过长**：项目经历里大段罗列项目功能，自己实际负责的却只是一个小模块——面试官问其中某个功能怎么实现，答不上来就很尴尬。项目本身的介绍一两句话直击核心即可，重点交代**你在项目中负责什么、做了什么、怎么用技术和设计能力解决问题**，其余留到面试中展开介绍
- **2、对工作的描述过于宽泛**：「完成了 xx」这类描述可以原封不动套在任何一个项目上，面试官根本看不出你到底做了什么，只会有一种感觉——你在糊弄。哪怕真的做了很多事，也要从中挑亮点去讲
- **3、过于直白**：只平铺直叙「用 xx 技术做了 xx」，找普通公司或实习也许够用，冲大厂就显得太「平平无奇」。要改用案例体现技术、设计能力与自主性，例如「由于项目模块众多、调用链路复杂，选用**责任链设计模式**重构项目，使各模块职责清晰、项目更易于扩展」
- **4、用词不专业**：简历上的每个词都反映你的水平。反例「我用 axios 库完成了对数据库的查询」——axios 是前端请求库，这样写语言不清晰凝练，还会让人怀疑「你真知道 axios 是什么、真和后端联调过么」；尽量减少口语化，把「用 xx 技术做了 xx」改成「用（基于）xx 技术实现了 xx」，保证用词准确、不产生歧义
- **5、没有重点**：又会 Python、又会 Java、又会前端，写上去的项目各方向都有，简历开头却没写求职意向，招聘方完全不知道你要找哪个方向。要有侧重——找 Java 岗就把 Java 项目放最上面、用更多篇幅介绍；也建议越早明确求职方向越好，别到最后什么都只学了一点、反而平平无奇

### 简历优化补充：期望薪资 · 技术栈写法 · 引导面试官 · 适当包装

- **一般不要写期望薪资**：大公司薪资相对公开透明，没必要写；更关键的是防止你的表现超出预期时，被人按照你自己写的预期薪资来砍价（除非有意把预期写得很高，用来过滤一些公司、猎头的打扰）
- **技术栈用列表而非长句，并补半句「能用它做什么」**：把「能够熟练使用 springcloud 微服务框架及 mysql、redis、hbase、mongodb 等数据库及 kafka 等消息中间件的有使用」这类长句拆成分条（熟练使用 springcloud 微服务全家桶 / 熟练使用 mysql、redis、hbase、mongodb 等数据库 / 熟练使用 kafka、rabbitmq 等消息中间件 / 熟悉 netty 等网络框架），更直观清晰；每条再补充你能用这些技术做什么，例如「熟练使用 springcloud 微服务全家桶，**能独立开发微服务项目**」「熟悉 netty 等网络框架，**能独立开发即时通讯系统**」——借以表现出你能干活、能帮公司解决问题
- **用措词主动引导面试官**：在一堆「了解」中适当加「掌握」「尤其熟悉」等词，面试官大概率会去问这些技术；更进一步可以**细化**技术点，把「熟悉多线程」改成「掌握多线程 **AQS**、并发包等技术」，主动吸引火力、一定程度上避开自己相对薄弱的部分——面试准备时间不足时这个方法可能有奇效。现在简历千篇一律（人均 Java 小能手），提到 Java 中某个有一定学习深度的高级知识点，反而更容易被选中
- **实习经历与项目经历的侧重点不同**：实习经历重点写你在这家公司负责什么（地位）、你的作用和价值；项目经历重点写你对这个项目的贡献、项目特色、实现项目的关键技术
- **「适当包装」的具体手法**：把常用技术组合起来、添加一些修饰词和专业名词，例如「使用了 MySQL 数据库、Redis 缓存、OSS 对象存储技术」→「使用 MySQL、Redis、OSS 三维一体的多元存储技术」，体现专业性；但仍要有度、不要乱吹（原则见上文「简历 8 技巧」第 8 条「适度夸大，不可欺骗」）

### 标杆简历案例：一页四部分 + 项目经历的四要素写法

> 作者向腾讯内推过 300 多名同学，逐份看过简历后印象最深的一份，来自同校直系学弟：**零竞赛奖项、零科研成果**，却靠写法吸引面试官，最终拿到腾讯 offer。这是所有同学都可以参考的「标杆简历」。

- **整体结构**：只有一页、非常精简，分四部分——**教育经历**（学校/专业/外语：大一通过 CET4、CET6）、**技术栈**（按后端 / 数据库 / 中间件 / DevOps / 云计算 / 前端分组，用「熟悉 / 了解」区分掌握程度）、**实习经历**、**项目经历**
- **技术栈写法示例**：后端 熟悉 Java、了解 SpringCloud/Express.js/Node.js/Python；数据库 熟悉 MySQL、了解 MongoDB；中间件 了解 Redis/RabbitMQ/Elasticsearch；DevOps 了解 微服务/Jenkins/Gitlab CI·CD/Nginx/Traefik/Linux；云计算 了解 Docker/Kubernetes；前端 了解 React/React Native/JavaScript/HTML/CSS/Grafana
- **实习经历写法**：公司 + 岗位 + 分条描述——负责哪个系统、参与哪些功能（从需求分析、数据库设计、界面原型到前后端实现）、带来什么效果（如「加快运营团队的迭代速度」「开发监控视图让成员快速掌握运营状况」）
- **项目经历写法（核心，占简历约 50% 篇幅）**：与「用什么技术实现了什么功能」的平铺直叙不同，每条介绍都点明四个关键——**为什么做**（为适应产品特性、加快迭代速度）→ **怎么做 / 用什么技术**（后端由 SpringBoot 重构至 Node.js，数据库由 MySQL 迁移至 MongoDB）→ **实现了什么**（前后端一体的集中式配置中心）→ **达到什么效果**（开发效率提高近 1 倍）。有前因、有技术、有后果，给人「做事有目的、有自主性、善于分析和总结」的印象，正是面试官看重的特质
- **细节加分**：大量**加粗**强调重点；用具体数据量化效果（如减少 50% 开发时间、降低 90% 以上数据库压力、搜索效率提升 80%、10 个节点的 K8s 集群）
- **还有两点可学**：① 最好给项目附上可直接访问的链接，有个人博客也列举上去，并在博客中记录总结学到的知识，让面试官感受到你的积累与脚踏实地；② 不知道写什么就先认认真真做一个项目，再按上面的四要素写法展示到简历上

### 简历补充：项目搭配与区分度

- **向别人提问先把自身情况介绍清楚**：技术掌握程度、目标、项目经历要交代完整，否则只能得到「自己看学习路线」式的机械回答
- **大厂简历的核心竞争力两点**：① 有竞争力、能和别人拉开区分度的项目；② 在某一项技术上比别人学得更深入
- **简历上的技能必须能在项目中体现**：简历很好模仿，「了解 Webpack 的几个概念」这类描述是虚的；写「熟练掌握小程序原生开发」就要有对应的小程序项目
- **前端简历项目搭配推荐**（3 选 1）：
  - 1 个 PC 端业务项目 + 1 个轮子项目
  - 1 个移动端业务项目 + 1 个轮子项目
  - 1 个业务项目（PC/移动端）+ 1 个小程序
  - 面大厂/高级岗可以全是轮子项目；但绝大多数公司招前端是做业务，最好保留业务项目
- **轮子项目（如组件库）学习法**：先研究业界成熟开源组件库，带着问题学——样式如何统一、设计体系怎么做、全局编码规范、主题模块设计、如何快速生成易维护的文档、怎么保证改动不出 Bug、前端单元测试怎么写；时间有限先学思想、做小 Demo，再逐步完善。前期调研越用心，项目上限越高
- **相关实习经历建议写**：实习经历与求职方向有关联就如实写（代表你了解公司规矩、沟通方式和项目流程，本身就是竞争力）；觉得没干什么活就少占篇幅
- **简历篇幅可以超过一页**：把最想展示的内容放第一页、能吸引面试官，他自然会往后看
- **选项目的 4 条标准**（参考一位二本非科班逆袭大厂的鱼友的筛选思路）：① **技术栈互补**——实习用的 Vue，就挑一个 React 项目来补齐；② **有重难点**（能讲出深度）；③ **可扩展性好**（方便做差异化）；④ 选 star 较少、不烂大街的开源项目
- **魔改现有开源项目是最省力的差异化手段**：把 JS 升级为 TS，加入 ESLint / Prettier / Husky / CI·CD 等工程化配置，再修 Bug、加亮点功能、补标准化注释与 README——改造完就是一个「有你自己的东西」的项目
- **长期运营个人博客 / 笔记是隐形加分项**：把学习笔记整理成博客并持续更新（案例中的同学返校后用半个月把 Hexo 博客部署到服务器，累计近 40 篇，连大一的单片机项目都写成了博客），面试官点进去就能直观看到你的积累
- **项目的最大价值是给面试官「抓手」**：面试大多在自我介绍之后就是项目环节，这段时间要着重展示自己的技术栈和亮点，为面试官的后续提问做好铺垫——**项目要让面试官有得问**。所以选项目时尽量覆盖可延伸的话题：网络编程框架、Zookeeper 等协调服务、fastJSON 等序列化框架；基础层面用上动态代理、反射这类「高阶 Java 特性」；再预留 QPS、负载均衡、消息队列、Nginx 等可展开的点（哪怕项目本身没用到也能延伸到相关话题）
  - 案例：一位同学用一周做的 RPC 项目替换掉原来的「单体博客」作为主力项目——**分布式、微服务几乎是后端岗必备**，项目里没体现，面试官必然会盘问对应知识点，简单的单体项目很难满足期望；RPC 项目代码量不大、却更好聊，最终助他面上了大厂
- **项目必须一行一行手打出来**：不要偷懒，有不会的地方就去学对应的内容，大概一两周就能完成；做完再整理一套自己对项目的理解话术，并在后续面试中根据面试官反馈不断调整表达方式

### 简历项目撞车怎么办：真实性 · 扩展 · 细节 · 表达

> 项目撞车非常正常（大家多半都是跟着网上教程做项目），面试官不会因此直接挂简历，而是在名额有限时挑出最好的几个。关键是让自己在撞车中胜出——「项目撞车不可怕，谁 X 谁尴尬」。

- **1、真实性（最重要，反映诚实品质）**：把项目上线并提供线上地址；项目开源、能看到每次提交代码的记录（不是直接搬运别人的代码）；提供项目文档辅助说明；补充更多细节（如自定义线程池参数、项目优化效果）。高薪岗位尤其要重视——作者曾收到一份很棒的项目简历，一看 GitHub 却发现代码全是复制别人的
  - 给项目增加背书：拿项目参加比赛获奖、在工作室跟团队一起开发；还有个特立独行的操作——在 B 站等公开平台发个项目介绍视频，真实度一下就上来了
- **2、扩展（最能体现自主性）**：无论学的是谁的项目，只要有撞车可能都建议做扩展——增加新功能、优化性能与体验。与其写好几套简单的增删改查项目，不如持续完善 1 个项目：更有竞争力，花的时间可能还更少
- **3、细节（体现认真负责的态度）**：不要有任何错别字、尤其是技术名词；严格注意技术名词的大小写；补充具体的技术细节和数字（如「使用 JMeter 压测，4 核 CPU 单节点 QPS 超过 1000」）；项目本身的细节——用域名代替 IP 便于访问，前端注重页面美观/兼容性/多端适配，后端注重提交数据的校验与事务
- **4、内容表达（最难，体现用心与专业）**：语句通顺有逻辑（「熟悉 Git 版本控制工具」优于「熟悉 GitHub 版本控制工具」）；惜字如金、尽量凝练（「独立完成用户管理系统的登录注册、用户管理功能」优于罗列功能的长句）；减少模糊表述、尽可能量化（把「参与需求评审、方案设计、库表设计、遵循代码规范」优化为「参与 XX 需求的评审和方案设计，使用 ER 图完成数据库设计，使用 CheckStyle 保证代码规范」）

### 简历项目真实性补充：开源查重 · 个人标识 · 无处部署的替代方案

> 项目撞车不可怕，可怕的是让面试官怀疑「这项目不是你做的」。本节补充几个让（哪怕是教程/开源）项目更可信的小操作。

- **开源项目的两个细节**：① 认真写项目介绍文档，把演示截图、主要功能、架构设计、关键实现细节写清楚，顺带展示文档编写能力；② 不要本地写完再一次性整体提交、更不要直接 fork 别人的项目，而应**在本地多次提交**，让面试官能从提交记录看出你是如何一步步做出来的
- **警惕 GitHub 代码查重**：GitHub 支持直接搜索代码片段（和论文查重一样）；学网上教程或开源项目后千万别不做修改就提交，建议认真学习、重新敲一遍，否则面试官一搜发现代码一模一样，结果可想而知
- **给项目加个人标识**：项目主页放上自己的昵称、头像等标识；做个人博客类项目再挂上个人文章，真实性毋庸置疑
- **实在没服务器就用「内网穿透」**：不要拿「买不起服务器 / 服务器过期」当借口，用内网穿透让面试官直接体验项目也 OK；前端尽量保证打开速度（压缩图片、上 CDN），后端至少提供一个 Swagger 接口文档，也比不上线强
- **把项目说成「你很厉害」**：不要给人「在吹某个项目很厉害」的感觉，而要给人「你很厉害，所以才做出很厉害的项目」的感觉——用明确动词和量化数据描述个人职责，例如「带领 5 人团队，通过 Git Flow 管理协同、按期交付，并通过 SQL 优化和压测实现 50% 性能提升」

### 自我介绍

> 简历上的自我评价与面试开场逻辑一致：不要「正确的废话」，要用事例、数据证明。

- 重点是通过校园经历、学习过程、竞赛、实习、研究等，突出**学习能力、沟通能力及解决问题的能力**。
- 个人性格等部分用几个成语带过即可，属于「正确的废话」。
- **结尾一定要提及自己最擅长的方向、项目或技术**，因为很多面试官会从自我介绍展开提问。
- **自我评价必须有信服力**：夸自己谁不会？热门岗位的简历上几乎都是雷同的自我评价，面试官都能背下来了——「学习能力强、乐于挑战、善于总结」本身没错，但没有事例支撑就是凑字数的废话。给每句话补上证据：
  1. 我学习能力强、对新技术有好奇心 ⇒ 曾通过官方文档、自主查阅资料自学 XX、XX 技术，并通过 RSS 持续关注该技术最新动态
  2. 我乐于从事有挑战性的工作 ⇒ 曾担任 XX 队长，在 XX 困难的条件下解决了 XX 问题、取得 XX 成果
  3. 我喜欢分享知识、善于总结 ⇒ 连续 XX 天发布个人博客、发布过 XX 篇学习总结
  4. 我很帅 ⇒ 补充个人照片
- **照着目标公司的岗位描述写（对号入座）**：到官网看岗位要求，要求「有团队协作经验」就写「我善于团队合作，曾组队参与 XX 项目、统筹负责 XX，并想办法提升团队效率」，让招聘方看出你是有备而来
- **面试自我介绍要精心准备、切忌现场 free style**（很容易「阿巴阿巴」、不知所云）：**比较虚的**是「我是谁、来自 XX、求职意向 XX 岗位」＋一番自我夸奖；**比较稳的**是「我是谁、来自 XX、求职意向 XX 岗位，主动学过哪些技能、哪些学得比较好、通过什么方式自学」，再用事例证明自己哪些能力强，最后带出最擅长的方向——逻辑清晰、有理有据，面试官会很受用
- **没有实习、在校经历单薄时，可着重介绍最近在看的技术书籍和收获**：既能填充自我介绍时间、不至于太短，又能**引导面试官围绕你擅长的方向提问**，还容易留下「善于自我驱动」的印象。案例同学用《从根儿上理解 MySQL》聊 MVCC 实现、被删数据为何仍占硬盘、事务实现等原理——面试官未必都了解这些细节（工作中用得少），正是展示技术深度的机会，比只会硬背面经的竞争者有辨识度

### 招聘方视角（上）：投递与初筛 —— 了解行情 · 招呼语 · 自我介绍

> 作者以招聘者身份（同时招实习和社招）复盘招聘全流程：发布岗位 → 候选人初筛 → 简历初筛 → 简历二筛 → 面试 → 发 offer。本节对应前两个环节。

- **了解市场行情**：注册一个求职者账号、看招聘网站推荐的岗位就能了解市场；更直接的方式是到 BOSS 招聘后台看某岗位的平均薪资（如上海 Java 开发 3-5 年约 1.5 万/月、应届约 1 万，仅供参考）
- **招呼语（投递时的第一条消息）技巧**：招聘方那里大概只能直接看到 **18-20 个字**，必须用心写、吸引对方点进去：
  1. 不要让千篇一律的客套话占用这宝贵位置（「您好，我对您的 XX 岗位很感兴趣」会让面试官不知道怎么回复）
  2. 尽量不要用问句（「你好，可以聊聊么？」面试官：聊啥？）
  3. 用有限空间凸显自己的优势与和公司的匹配度，例如「您好，我符合贵司 XX、XX 要求，项目：http://xxxx」
- **自我介绍（直投）技巧**：招聘方在社群、朋友圈收到直投的候选人，符合度与认真程度普遍高几个等级。除基本技能、经历外，尽量写一些与众不同的内容；没有特别亮点就尽量匹配公司要求——公司「急招」时可说明自己可立即到岗（有同学写「家离工作地点近，当天即可到岗」）。作者举例：候选人高考数学 138 分在他看来很加分——数学好的人逻辑思维通常比较强，是程序员的重要软实力
- **别海投、更别造假**：作者沟通的近 100 人中真正符合岗位基本要求的不到 5 人——求职者无视要求海投、自动打招呼甚至编造信息，招聘者广撒网、自动回复甚至不回复，陷入恶性循环；BOSS「人才库」按学历/经验搜索也不可靠（这些标签候选人自己可以随意修改）

### 面试博弈

- 面试是应聘者和面试官之间的博弈：一场完美的面试由你来引导面试官，让他对你产生兴趣和信赖，而不是被他牵着鼻子走。
- 在不过分夸大的前提下大胆展示自己，面试官喜欢爱思考、善于交流、有发散思维、有执行力的同学。
- 大厂最注重团队合作：如华为心理测试若结果显示「不喜欢团队合作」，再优秀也不会被录用——因为不符合企业文化。

### 面试执行细节：自我介绍常更新 · 听清问题 · 答不上来的应对 · 录屏复盘

> 一位 Java 后端实习生的求职总结（原文 8000 字）精华。其求职经历（外包 → 春招线上实习 → 阿里一面被拷打，最终因做 OJ 项目积极、每期直播交作业并有自己的扩展而被作者相中）印证了「实践经验、自主性、积极性」是招聘最看重的（呼应「大厂看上限」）；以下只列前文未覆盖的面试执行技巧。

- **自我介绍要专门写、并随经历持续更新**：作者专门写了自我介绍、交给 ChatGPT 润色后背下来，每次面试都用同一套。但坑在于——实习完之后没更新自我介绍，面试时又说习惯了旧版，没把实习经历在自我介绍阶段讲出来，导致面试官没顺着实习经历提问、自己只能反复说「项目都是 CRUD」。**有新经历（实习/项目/获奖）后务必同步更新自我介绍**
- **听清面试官到底想问什么**：不明白就多沟通一下，别没搞清问题就抢答。作者反面案例——多次没搞清就凭猜测回答，有的面试官会顺着错误方向走，有的直接打断重述问题，这个过程很减分
- **回答不上来时不要只说「不会」**：直接说不会没错（让面试官别再深究），但应给面试官一个继续往下问的方向——「这个知识点我不太会，但相关的 XXX 我有些了解」，引导面试官往下走，至少不会冷场、印象分不减太多
- **线上面试尽量录制视频**：作者每次线上面试都录下来供后续学习总结；注意提前调试好录制软件（他前几次录制的面试都没声音）
- **表达能力是最重要的软实力**：可以对着镜子背八股来锻炼——至少能把想表达的内容都清晰地讲出来；面试时要自信，哪怕说错也要自信地把观点表述出来（作者印象很深：一位计算机组成原理老师讲错了东西却非常自信、逻辑严谨，让在场学生都不自信了）
- **面试后一定要调整心态**：无论成功失败都要稳住——作者曾因阿里面试受挫，较长一段时间不敢投简历、一直在背八股，反而错失机会

### 面试答题与项目包装策略：引导面试官 · 必准备清单 · 讲实习项目

> 一位经历技术面试四十多场、最终拿到阿里等大厂 offer 的同学的实战总结（原「从家里到阿里，学弟超神的一年」干货部分）。

- **不会的问题不要只说「不会」，要把面试官引导到你会的地方**：面试官问一个问题，往往是在考察你的整个知识体系，而非单点——被问到 IOC 若确实不会（太基础仍会扣分，此处仅举例），可以接一句「IOC 我不太了解，但可以讲讲 Spring 的另一块基石 AOP」，把话题引到你擅长的方向；同时尽量避免长时间停顿冷场，否则气氛尴尬、影响后续发挥
- **百分百会被问到的 4 个问题务必提前准备**：① 介绍项目/实习中的亮点或难点；② 项目/实习中收获最大的是什么；③ 项目/实习中结合了哪些知识点；④ 反问环节——必问面试官对自己的评价或建议（面试不是自娱自乐，表演效果如何需要观众来评价）
- **每一次面试机会都要珍惜、录音复盘**：面完从各角度给自己挑刺（回答语气是否尖刻、知识点是否答全）；没把握时先找小厂练手，能力提升后再面大厂，避免留下糟糕面评（案例同学次年投快手简历反复被筛掉，疑与去年的差评有关）
- **讲实习项目：优先讲技术类工作，而不是业务 CRUD**：实习生做的大多是业务 CRUD，别人很难 get 到你的点；而数据库、网络一类属于技术人必备技能——可重点讲实习中接触的 SQL 与优化点（结合联合索引、最左匹配等八股知识点），在实习期间就有意识地去挖掘这类亮点
- **定期梳理工作、主动汇报**：每月整理本月做了什么，主动发月报给 mentor/leader 看，既获取反馈、也避免实习期太长产生遗忘（写总结的习惯对日后晋升答辩同样重要）
- **面试过程本身就是打磨话术的手段**：同一个需求选哪个角度介绍 ROI（收益比）差别很大——案例同学起初讲一个业务场景复杂的需求，耗费大量时间却难获正向反馈，换成另一件工作介绍后效果好了很多；每次面试后都据此调整表达

### 招聘方视角（下）：简历筛选与面试考察重点

- **简历初筛常见问题（投递前请再完整阅读 3 遍）**：项目写了上线却根本无法访问；很简单、很常用的技术名词都写错；招呼语提到的分布式项目却没写进简历；项目直接照搬网上的、没做任何换皮和扩展；工作经历只写公司名称、没写具体负责的工作内容；甚至简历链接都打不开——小细节往往决定成败
- **简历二筛（沟通环节）的 3 条建议**：
  1. 招聘方主动和你沟通，大概率是对你有一定意向——不管是否想去这家公司，多聊聊总没坏处（能了解行情）；真想争取面试就表现出积极态度、及时回复
  2. 招聘方单独沟通，说明你已在候选名单中犹豫——这时要**有效沟通**，多补充简历上没有、尤其能增加项目真实性的内容：自己做的项目可分享学习笔记、代码；不是自己做的也可短时间内快速了解
  3. 从与岗位的匹配度下手增加优势：公司业务和 AI 有关，就提自己学过的 AI 知识和用过的 AI 工具，动动嘴皮子就能加分
- **面试考察重点**：
  1. **表达能力**：从开场自我介绍就能感觉出来——能一气呵成讲清自己的学习过程、会的技术、优点、项目与工作经历，并在最后强调最大优势、引导面试官提问，是明显加分项；尽讲家在哪、爱唱跳 RAP 篮球这类无关爱好，面试官只能去问八股
  2. **项目实践 > 技术水平**：公司要找的是能干活的人，网上不缺教程、学会某个技术并不难，所以更关注你是否**能实际应用技术**——看你做过的项目、写过的代码、参与过的实习与业务场景
  3. **包装项目的 3 个「杀手锏」问题**（回答不出说明包装还不到位）：① 介绍项目的业务流程、主要模块及自己负责的工作？② 做这个项目中遇到的最大难点、或解决过的最复杂 Bug 是什么？③ 项目有实际上线吗？用哪种方式部署？（网上教程一般不教上线，没上线大概率也没有线上调试经历）
  4. **其他品质**：几分钟对话就能看出性格、逻辑与态度——听清问题、思考片刻再回答体现沟通能力和沉稳；没听完就抢答、问项目 A 却聊到项目 B 则减分。面试时间有限，不是说得越多越好，而要精准回答、让面试官在有限时间内足够了解你
- **面试中该问与不该问**：「我这场面试表现怎么样？」值得问（能从有耐心的面试官口中得到真实反馈、便于改进，也显得态度积极）；「我能否通过本轮面试？」不建议问（显得经验少、不了解规则）——面试官通常要面完所有候选人、综合对比后才给答复，所以发挥好却没拿到 offer 可能只是运气差、同期竞争者更强，反之亦然
  - HR 说「已经通过了」千万别当真，接着去找别的机会——作者当年就被某大厂这样坑过
- **主动展示作品**：发作品视频、学习笔记、代码仓库地址（有同学甚至紧急上线了一下自己的网站）都能让招聘方眼前一亮；对认真争取机会的同学，招聘方更愿意给一次面试机会

### 招聘方视角（补充）：投简历为什么没回复 —— 烂简历画像与「上线项目」

> 换位思考：如果你是招聘方，能在工作时间、海量简历中选中自己这一份吗？作者帮上千位程序员改过简历、创业后也以招聘方身份看过几百份简历，看到的大多数简历其实是下面四种样子。

- **招聘方眼中的 4 类简历**：① 清澈见底（内容太少）；② 千篇一律（同质化严重）；③ 模糊不清；④ 一眼包装——和刷短视频一样，内容都一样，HR 自然会划走
- **招人最看重的 3 点**：能干活、有自主性、有攻坚能力（正好分别对应小厂、中厂、大厂招聘的核心要求）——投了几百份简历没回复，先自查简历里能否体现出这几点
- **怎么证明「能干活」：必须有真实上线了的项目地址**：仿写专业技能、抄网上热门项目、写四六级/普通话证书都证明不了能干活；最直接有效、而且人人都有机会的方式是**做项目并上线**——面试官一点开就能看到运行效果，才知道你是真的做过（「高可用、高并发、高性能」谁都会说）
- **上线项目为什么这么重要**：① 区分学生与工作者的界限——学生项目只要能跑在自己电脑上即可，课设、竞赛甚至跑 100 次成功 1 次就能写进论文和 PPT；而真实上线运行才会遇到网站攻击等只有生产环境才经历得到的问题。② 上线过程本身能学到更多技能——服务器、网络安全、数据库、存储服务、权限控制、Linux 系统、服务监控等
- **破除一个错误认知**：别以为「只有进了公司才能真实上线项目」——现在是**没有上线项目经历，都不一定能进公司**。还没上线过项目、连上面这些技术名词都不懂时，与其盲目投递碰运气，不如先快速补上这些技能（网上有大量免费/付费教程、开源项目、云服务实战课可提高实践能力），在简历上写出自己真正做过的项目，凭本事争取机会

### 为什么面试官夸你，却不让你通过？—— 结果反馈与后路管理

> 面试官反馈「回答得挺不错」却没进下一轮，很多人会觉得被「耍」了。代入招聘方视角就能理解，除自身问题外还有多种可能；求职中「HR 答应发 offer 又不发」「发了 offer 又毁约」「入职后不给过试用期」等闹心事也屡见不鲜，关键是做好主动跟进与后路管理。

- **「夸你不通过」的 3 种可能**：
  1. 面试表现一般——面试官出于友好给个鼓励，「答得不错」可能只是客气话
  2. 技术题对答如流，但经验或其他软技能不符要求（如面试国际化部门却英语口语不过关）
  3. 面试表现确实很好，但竞争太激烈——同期有个「会唱跳 RAP」的候选人，却只有一个坑位
  - 作者亲身经历：秋招面百度时面试官笑容灿烂、夸实践经验丰富，最后仍毫不留情地给挂了
- **更闹心的情况**：HR 答应发 offer 又不发、发了 offer 又毁约、入职后不给过试用期——作者面某公司时 HR 说「没问题的话过几天就发 offer」，最后却没收到；他复盘认为可能是自己听到发 offer 时没表现出激动，让对方觉得大概率不会接（真回到那个场景，他会表现得再积极一点）
- **能做的 3 件事**：
  1. **主动跟进**：想办法联系内部员工帮忙打听、查询求职进度；面试后主动要面试官或 HR 的微信便于后续交流（同上文「人脉链接」）
  2. **保持乐观自信**：不要自我否定——求职真的需要运气和机遇，你可能已经满足要求，只是正好有人比你强一丢丢
  3. **多给自己找后路**：不要因为过了一场面试就放弃其他面试机会；不要觉得能拿到 offer 就不看其他公司、不做横向对比；不要觉得转正稳了就不再学习提升——时刻做好应对风险的准备，才能做到「泰山崩于前而色不变」

### 校招 vs 社招：看重点不同

- **校招更看重基础**：数据结构、算法、计算机网络、操作系统等基础功底（笔试常出现 ACM 水平算法题）
- **社招更看重做项目的能力**：实际项目经验、解决真实问题的能力
- 启示：大学阶段把基础打牢，工作后持续沉淀项目能力
- **简历维度的差异**：校招简历可以不带项目或实习（有的公司甚至 985 科班就能进）；社招则更侧重技术与业务维度——如果你在业务上是「业务巨人」，也能在一定程度上弥补技术不足，考量的维度比校招更多

- **校招生的考察面（4 个方面）**：校招生很少能接触企业实际项目、社会经历干净得像一张白纸，所以通常就从**八股文、计算机基础、学过的技术、个人项目** 4 个方面考察
- **社招考察过往经历与项目的匹配度**：更注重你之前的个人工作经历——做过哪个方面的业务、做过什么样的项目、项目中用过哪些技术、你是怎么解决问题的、对行业有哪些自己的个人思考；八股文、算法、基本功也会考，但比重相对小一些。尤其是若你已有一段不错的工作经历（比如之前已通过字节的面试拿到过 offer），本身就证明了你的实力，下一家公司考察基本功就会更少——面试官就不会再考你算法
- **无论校招社招，八股文都要准备**，但最重要的是能把自己的真实经历（校招重项目经历、社招重工作经历）讲清楚、流畅地表达出来——但凡有点水准的面试官，都会围绕你的简历出发，问你学过的技术、过去的经历，从而评估你的真实能力
- **别拿「有很强的执行力」这类空话自我包装**：要摆出你做过的事、或者明确要做的事去证明

### 从小公司到大厂：不同规模公司的考察重点

> 一年经验的小公司后端想跳槽中大厂，先搞清不同规模公司的招聘考察重点，再针对性准备。以下为个人观点仅供参考。

- **小公司：最重实践能力（看下限）**：关注「你能不能干活」，要求一般不高，能用开发框架写代码基本就行；简历上有实际上线的项目经历格外加分，面试也重点考察项目经历。当然也有老板不懂技术的小公司，喜欢从网上找八股文像考试一样机械考察
- **中厂：实践能力 + 基础与可培养性**：简历不仅要有编程开发相关的技术栈，还要有算法数据结构、计算机网络等计算机基础；面试一般会有算法题、八股文基本功考察，以及项目经历考察
- **大厂：实践 + 基本功 + 自主性与潜能（看上限）**：不仅关注下限，更关注上限——未来能否推动事情发展、应对种种挑战；因为投递无成本、竞争激烈，才有了笔试和学历门槛。想进大厂要用一切办法在简历上贴金——竞赛奖项、实习科研经历、各种光环都能快速证明能力与自主性，让你在众多简历中脱颖而出
  - **为什么自认为优秀却没拿 offer**：可能只是因为竞争者的能力上限比你高
  - **大厂场景设计题举例**（作者当年真实被问）：腾讯实习「如何设计短链系统？」、字节实习「如何设计一个实时弹幕系统？」、字节校招「如何设计地铁轨道调通系统？」、百度「你怎么看待区块链的发展？」（因为简历上有区块链经历）
- **大厂招人更谨慎**：校招能力强的人很多，宁可漏掉一个人才也不希望错招（怕出「删库跑路」式的招聘事故）；流程中可能含性格测试、综合素质测评，并进行严格背调——**投递大厂千万不要简历造假**，被查出来可能拉进黑名单
- **社招跳槽的加分技巧**：投递与你之前工作经历业务相似的公司——相关术语和业务知识你基本都理解，相比没做过此类业务的竞争者更有优势，找工作也更轻松
- **一步跳不到中大厂就持续跳槽、不断涨薪**，一级级往上走即可——来日方长，需要不断学习、持续成长

### 测试 / 测试开发岗：入门捷径与利弊

> 技术不够自信时，测试/测开岗是进入大厂的一条备选路径。综合一位测开实习转开发的同学的观察，供参考。

- **面试难度普遍低于开发岗**：考察技术栈与后端基本吻合，额外了解一些测试相关知识即可——确实是对自己技术不自信又想进大厂的一条「捷径」；大厂里相同资历的测开与开发薪资相差无几
- **利的方面**：测试岗相对不那么内卷，肯在技术上多打磨自己，比较容易崭露头角、成为团队核心骨干；加班一般也没有开发那么多（项目上线前依然会很忙）
- **弊的方面**：测试团队相对不那么受重视、分配到的资源较少；若测试 Leader 不能在整个技术大团队中为团队争取，可能导致晋升名额少、团队整体绩效不高
- **建议**：先找准自身定位——对技术不那么执着、不想太「卷」的同学，把测开作为职业方向也未必不是一个好选择

### 产品岗求职：学历门槛 · 能力积累 · 针对性准备

> 产品岗（尤其校招产品）的考察方式与开发岗差别很大，需要长久的能力积累而非突击；不过其中不少技巧对开发岗同学同样适用（面试官想方设法「打破你的突击准备」的逻辑是通用的）。

- **学历门槛比开发岗更硬**：开发岗有入行门槛（基本仅限计算机专业学生），产品岗专业放宽了许多，导致学历「神仙打架」——校招产品经理基本最低要求 211 本科，985 本科或 211 硕士是推荐配置。作者在哈啰实习时组里实习生多为交大本硕、同济本+帝国理硕、华理本+宾大硕等；即便最后签下华为（产品岗、通信计算机优先），也是完美错过秋招、学历放宽到 211 才跟着一堆 985 硕一同入职。所以**学历较低的同学求职产品岗要慎重**，或趁早多攒几份实习弥补
- **简历**：像「超级简历」那种白纸模板、写满一页纸是基本要求，内容要有针对性
- **面试形式：聊天式，不考技术细节**：校招产品不像社招有历史产出可问，更看重个人综合素质和未来发展的潜力，所以面试以聊天为主、不太涉及专业技术细节。这种形式既「简单」（不会像开发面试那样一问三不知），又「很难」（不同人的面试表现差距极大）——面试官会用灵魂提问、性格探讨、压力注入等各种花样，唯一的目的是**打破你的虚假突击准备、揭开你的真实面目**
- **前期能力积累（靠日常，无法突击）**：
  1. **实习**：一定实习、尽早实习——大二大三、寒暑假与其闲着不如去实习；大厂难进就先去小厂，迂回实习
  2. **竞赛**：挑战杯、三创赛、数学建模等，容易被忽视但很重要——它能让你在一件具体的事情里与队友为共同目标做组织沟通，对沟通能力与可行性分析能力的提升帮助巨大（远胜多数学生组织的「自娱自乐」）
  3. **商赛 / 精英营**：对非理工科专业的学生帮助尤其大（如各类商赛挑战赛、PwC 暑期精英营等）
  4. **学生组织**：差异性和随机性很大，多数（尤其院级）组织锻炼效果有限；作者因在校合唱团担任声部首席、独立承担声部加排约一百次并随团出访比赛拿金奖才真正得到锻炼——一定要衡量这项活动是否值得投入时间精力、是否真的感兴趣，并尽量搞出一些「名堂」
- **针对性突击（不提升长期能力，但可能是单场面试的胜负手）**：
  1. **资料收集**：活学活用互联网，全方位了解目标公司、部门岗位从事什么业务——百度、Google、牛客、力扣、脉脉、知乎，甚至贴吧微博都用上
  2. **针对性出击**：作者面华为期间正逢 MWCS 世界移动大会、华为正是主会方之一，他完整收看了华为演讲部分并整理笔记，最终对面试帮助非常大——面试官想打破你的虚假突击，但有针对性的认真准备反而会让面试官感受到你的认真态度
  3. **态度传达**：一定要表现出对通过面试的强烈渴望，至少让对方感到你并非无所谓——面试只有短短几十分钟，面试官也是有感情的人，这可能直接影响最终结果
  4. **适当多说**：「能说却少说」和「不能说」相差两个 level；尽量多说，但语速别太快、不要抢话
  5. **简历 / 自我介绍微调**：别一招走天下，根据单位、职位、业务线不同做相应微调，突出你在该业务场景下的特长特色（比如公司是卖烤地瓜的，就该突出食品行业相关经历，而不是宣扬自己擅长修自行车）

### 算法刷题

- **每天坚持刷几个小时算法题**，推荐 LeetCode 平台；国内也可用洛谷的题单（如大一新生 AK 洛谷题单）练习。
- 重点题型：树、链表、动态规划、栈、队列、深度优先搜索（DFS）、广度优先搜索（BFS）。
- 线下面试可能是白纸手写代码；线上面试可能使用在线面试平台，要求程序正确执行，难度更大。
- 无论何种形式：先理解题意、想清楚再写，字迹工整、缩进得当；即使做不出来，也要试探性地向面试官说出自己的想法，通常会得到友好提示。
- **刷题量与方法（两位大厂上岸同学的共识）**：一位同学前后刷了不到 300 题，到量后会发现前面的题忘得差不多——正好开始**第二遍**，第二遍会轻松很多，重点题一定要多练；另一位遵循「一道题 7 天之内必再写一次」来对抗遗忘曲线，难题多想几遍、理清思路再做，别在一道题上死磕，一定要找到做题的感觉。
- **刻意练习、形成肌肉记忆**：案例同学快排学了忘、忘了学，后来规定每天早上醒来就写一遍，一周后不用过脑子就能敲出来——**在理解的基础上刻意练习、巩固所学**；面试中能当场手撕堆排、LRU 这类较长的算法，会非常加分。
- **学习资源**：首推 LeetCode 评论区（各路大神分享题解，一篇看不懂马上换、多看几篇总有适合自己思路的，不懂就留言提问）；算法课可看左程云（左神），适合初学入门。**刷面经也是高效的复习手段**——集中刷一批目标公司的面经、自己尝试作答，能快速明确自身还有哪些不足。

### 八股文怎么学

- **学习顺序**：优先背项目里用得最多的技术（如 Redis、MySQL、RabbitMQ），再看计算机基础（操作系统、计算机网络）基本足够
- **节奏**：每天坚持 1-2 小时、背几道题即可，关键是要理解；有面试预约就集中突击（甚至可以一整天背，像考前临时抱佛脚）；背完一道把思路整理记录到笔记中
- **段位进阶**：

| 段位 | 特征 |
|------|------|
| 青铜 | 没学过技术，死记硬背 |
| 白银 | 学过技术，能理解一部分、背一部分 |
| 黄金 | 能理解并**结合项目运用**（如把 MySQL 性能优化实践到项目里；设计模式有没有实践经历，回答效果天差地别） |
| 钻石 | 能理解运用 + **横向/纵向扩展**（如 Redis 数据结构不仅答出基本和高级结构，还能横向扩展到应用场景、纵向延伸到 ziplist 等设计巧思） |

- 第一次背八股、时间有限时，达到白银/黄金段位即可；之后通过系统学习技术底层、项目实战逐步提升段位

### 后端面试必学知识框架（从大厂高频题反推）

一位大厂 Java 后端面试官给大一新生做的「考点摸底」几乎全中高频题；把题目按知识块归类，就是一张「后端要学什么」的地图——每个知识块都对应面试官的考察动机：

| 知识块 | 代表高频题 | 为什么要学 |
|--------|-----------|-----------|
| 语言·基础 | `==` 和 `equals` 的区别、final / volatile | 语法细节是 bug 高发区（判断相同的值却判成不相等），也是面试官最爱考的小细节；推荐《Java 核心技术卷 I》 |
| 语言·类库 | 集合及继承关系、HashMap 原理与 HashTable 区别、ArrayList 与 LinkedList 区别 | 类库是最常用的工具，懂原理才能用得对、用得快，也是自己封装库的前提 |
| 语言·框架 | Spring 依赖注入、IOC / AOP、多级缓存解决循环依赖 | 企业开发都用现成框架，会用只是底线；榨性能、降 bug、省成本、乃至自研框架才是分水岭 |
| 语言·底层 | JVM 内存结构、垃圾收集器与回收算法 | 大厂要的不是「你现在能做什么」而是「未来能否应对挑战」——线上突发问题要现看 GC 日志就晚了；推荐《深入理解 Java 虚拟机》 |
| 计算机基础 | 栈实现队列、爬楼梯、TCP 三次握手四次挥手、什么是死锁 | 数据结构 / 算法 / 网络 / 操作系统独立于语言，决定思考深度与优化极限 |
| 数据库 | MySQL 如何性能优化、按场景设计表结构 | ToC 业务数据千万上亿，设计与优化是硬要求；别只背，用项目实战验证优化效果；事务 / 锁 / 索引 / 慢查询也要会 |
| 缓存 | Redis 数据类型、RDB 与 AOF 区别、为什么单线程 | 缓存、分布式锁、会话令牌、排行榜、计数器、队列、布隆过滤器几乎处处是 Redis |
| 设计模式 | 手写单例模式、工厂模式、观察者模式 | 复用代码、易维护可扩展、提升效率；23 种里面试重点就是这几种 |
| 并发编程 | 为什么用线程池、秒杀系统设计、订单超卖怎么解决 | 「用最少资源写出更高性能、更可靠、更可扩展的程序」是后端核心命题 |
| Linux | top 命令输出各字段含义、常用排障命令 | 项目都部署在 Linux 云服务器上，部署、装服务、看运行信息、线上排障都离不开 |
| Git | 分支、合并、回退、解决冲突 | 团队协作必修课，入职第一件事往往就是拉代码 |
| 架构 | 什么是微服务、和传统架构有什么区别 | 单点 / 集群 / 分布式 / SOA / 微服务 / 容器 / 云原生 / 服务网格各有场景，会选会用是进阶必答题 |

> 换个角度看面经：拿一张目标岗位的高频题清单当**学习路线自查表**，比自己漫无目的地学更能定位缺口。

### 复习准备：分阶段推进 · 模拟面试 · 总结业务优化点

> 一位双非非科班同学（大四自学、工作一年后跳槽成功）的复习路径。整体思路：先打基础，再由浅入深看框架，并结合项目与工作实践分析框架/中间件的作用，全程持续刷算法、读面经。

- **第一阶段（侧重基础、查漏补缺）**：直接找总结好的博客或 GitHub 项目按分类过基础知识（案例同学用 GitHub 上一个分类完善的知识库，每天看四五个小时，对基础不扎实的人非常友好）
- **第二阶段（侧重框架与业务优化）**：把目标方向框架的文档和源码从头到尾看几遍，逐步理解面试官的问题；组织几场**模拟面试**排查自己的短板（案例同学正是在模拟面试中发现自己对 Vue 完全不熟练）
- **总结业务中的坑与优化点**：把日常业务里踩过的坑、做过的优化（如优化首屏加载）提前总结好；回答时**从多个维度分点讲**、不要杂糅成一团，否则即便内容说对了，也会让面试官觉得你思路很乱
- **算法贯穿整个求职周期**：复习框架、补 ES6/Webpack 等进阶考点的同时，算法不能停
- **按方向列出复习清单**（以某同学的前端复习为例）：计网（HTTP/TCP/请求响应头）+ 前端三剑客 + Vue 框架与源码 + Webpack 优化思路 + 微前端 + Node（Koa）+ 设计模式（MVVM/MVC），另兼顾后端（数据库、Redis、Linux、Nginx），再撸几十篇牛客面经补足考点
- **常用书单**：后端方向——《从根儿上理解 MySQL》《深入理解 Java 虚拟机》《码农翻身》《图解计算机网络》《剑指 offer》《啊哈算法》；前端方向——《你不知道的 JavaScript（上中下）》《JavaScript 高级程序设计（红宝书）》《TCP/IP 协议簇》《深入浅出 Node》《深入浅出 Webpack》《ES6 入门教程》

### 招聘时间线

- 多数互联网公司号称「金九银十」，但很多公司的**提前批从 7-8 月就开始面试和录用**，必须提早准备、合理安排日程。如今越来越卷，知名公司为抢人：秋招提前批最快 6-7 月、春招最快 1-2 月就已开始招人。
- **关键时间点**：
  - **秋招**：每年 9-10 月（金九银十），面向大四/研二等即将毕业的同学；补录一般从 11 月之后开始
  - **春招**：每年 3-4 月，岗位比秋招更少、更偏向「补录」；补录一般在 5 月左右——补录时间取决于各公司招聘情况，招满了大概率就没有补录
  - **暑期实习**：每年 2-5 月，面向大二、大三或研一、研二的同学，务必重视（大厂越来越看重实习经历，也能顺便验证自己是否适合这类工作）
  - **日常实习**：不定期招聘、时间灵活，腾讯/阿里/字节等都有岗位，哪怕大一、大二（有一定能力）也可投递
- **求职渠道**：① 实习僧（实习机会多）② 牛客网（互联网公司内推多）③ 各公司官网或官方招聘公众号（如腾讯招聘，还有求职指南）；其他可关注智联招聘、Boss 直聘、前程无忧、拉勾招聘
  - **内推往往比官网直投更有效**：案例同学拿到的大厂 offer 大多不是官网直投的——滴滴、阿里都是找 Boss 直聘上的内推人**组内直推走流程**（能实时跟踪反馈结果），百度则是直属 Leader 在脉脉上主动联系。**找内推最好直接找目标部门/小组内的员工**，机会更大，并小心猎头
  - **配套工具**：牛客网查面经/找内推、脉脉查公司与部门信息并找 HR 内推、小程序 offershow 查应届薪资、LeetCode/Codetop 备算法、超级简历做简历模板、掘金/极客时间学技术
- 争取大公司**暑期实习的 offer**，有机会直接转正；拿到转正 offer 后，再去其他公司面试会自信很多。
- 不要过度自信，也不要盲目悲观：多投递一些企业，多一个机会、多一个选择。
- **技术与项目达标后尽早投递**：大厂官网直投（大厂有集中的招聘批次，一次面试挂了也可能被其他部门捞）；中小厂能投就投，多一次面试检验水平。
- **学生视角把求职分为 5 个阶段**：① **大三下的暑期实习招聘**（3-5 月，难度相对不高，对有一定实力的同学是进大厂的好机会）；② **大三到大四的秋招提前批**（7 月陆续开启，大厂多有提前批、HC 更多，但一起竞争的多是大佬，面试难度未知）；③ **大四初的秋招**（说是「金九银十」，实际越来越卷、基本变成「金八银九」，10 月还在招的公司已明显变少）；④ **秋招补录**（10 月之后，秋招 offer 被拒或没招满的公司补招，难度可能略降、但 HC 少了一大截）；⑤ **春招**（年后 2-4 月，难度往往排第一——HC 少但竞争一点不少：被裁员工、考研考公失利的同学、留学回国、秋招失利或对工作不满意重新准备春招的同学都是竞争对手）
- **准备节奏（以放弃考研、转就业为例）**：距秋招结束还有 3-4 个月时，1-2 个月学完 SSM + SpringBoot、约 15 天完成一个项目、剩余时间准备简历和复习面试题，是来得及的——**原则是赶早不赶晚，冲刺一下还能赶上秋招**；即使秋招没赶上也没关系，全力准备次年 2-5 月的春招，半年专注学习完全足够学好 Java 基本开发技能，还能再完成 1-2 个完整项目。对 Java 方向来说，学完企业级开发框架 SSM + SpringBoot 就可以去找工作，只是能找到什么样的工作取决于经验、技术掌握程度、经历和会多少技术
- **目标略高一筹 + 高低先投不亏**：一开始就根据自己的能力定好目标——感觉有中厂水平就把目标定为大厂、还有待提高就定为中厂，很多公司的难度并没有想象中恐怖（《孙子兵法》：「求其上，得其中；求其中，得其下」）；投递时不必过度自我审查，不管够不够格「高低先投了再说」，能面最好、不能面也不吃亏——有同学最终投了几十上百家、笔试面试二三十家才上岸
- **起步晚、非科班也有机会（真实案例）**：一位末流二本 → 211 非科班的同学研一末才转前端，靠「把时间填满」打开局面——暑期留守实验室边学边敲三大件，再依次学 Node、刷算法、学 Vue 并做后台管理项目，很快拿到实习；实习期间主动利用空档把算法题量提到 250 道、补齐 React/TS/小程序；返校后部署博客、魔改开源项目、准备简历。秋招中虽经历美团 HR 面挂、快手二面挂，仍坚持投递到 10 月，最终收获 6 个 offer。要点：起步晚就用更密集的投入补回来、把每次面试都当练兵、屡挂不弃

### Offer 选择的 3 个思考角度

> offer 选择的核心：一是尽可能多地收集各公司的信息，二是明确自己的核心诉求和职业发展规划，综合对比分析后再做抉择。纠结难选往往是因为职业规划不清晰，下面 3 个思考角度可供参考。

- **角度 1：按发展阶段选**——「一年看技术，三年看业务，五年以上看行业」：
  - 一年看技术：大学期间及初入公司阶段，还不清楚未来朝哪个业务/行业发展，重点放在技术上，提高**通用竞争力**（熟练运用主流语言/框架/工具、了解最新技术趋势）
  - 三年看业务：工作越久，精进技术的性价比越低——技术的本质是解决实际业务问题。此时以熟悉业务为核心目标，争取成为某个业务/项目的负责人（了解业务背景、产品思考、客户需求、市场竞争、盈利模式等）；晋升看的不是技术学得多牛，而是你负责的业务好不好、能否推动业务发展——「得业务者得天下」。技术也要持续进步，尤其是所在业务的主流解决方案（如做支付业务三年，应能主导新项目支付功能的设计开发）
  - 五年以上看行业：不满足于公司内的技术/业务，扩大视野了解所在行业的趋势、发展、未来展望（参与者、创新、政策、全球市场），从「跟领导安排做需求」到能按行业玩法创造新业务机会，成为行业内有影响力的专家
  - **落地建议**：预计 1 年左右跳槽 → 优先选公司背景好、业务核心、有挑战性和自主发挥空间、领导/导师技术强的（短期积累背景与技术利于跳槽）；追求稳定长期发展 → 优先选业务好、收益稳定、行业行情好的公司
- **角度 2：按业务类别选**——一般来说，**toC ≥ toB ≥ 内部工具**：
  - toC（面向消费者）：对用户体验、性能、可用性要求更高，需支撑大规模用户（百万并发），技术要求高，收益与成就感也更大
  - toB（面向企业）：对 UI/体验要求相对低，但技术更专业化——数据安全性要求高、第三方集成、定制功能开发；用户规模通常小于 toC，高并发实践机会可能更少
  - 内部工具（组织内部需求，如技术轮子/基础组件/内部管理平台）：做基础架构类对技术提升大；做内部管理平台要求不高、不直接产生收入，地位可能不高
- **角度 3：按现实维度逐条打分对比**——拿到多个 offer 时，把「薪资高低、工作强度（如周平均工时）、福利（餐补/房补/夜间打车补贴）、离家距离、行业稳定性、平台与发展」等维度列成表格逐条比较，再结合核心诉求定夺。真实案例：一位同学在 6 个 offer 间纠结（得物白菜价最高但周均工时 62.8h、美团 SP 且大厂平台与氛围好、度小满不卷时薪最高、TCL 开价最早最定心但业务偏传统、联影/汇川离家近且行业稳定），最终以「平台大 + 业务稳定 + 开价诚意」为理由选择走互联网
- 以上只是一般情况，以实际公司、工作内容、个人想法为准；决定前先调研清楚，列出各维度 offer 对比表格综合分析

### 薪资对比：Base 为主还是总包为主

> 个人经验建议：应届生对比薪资时以 **Base（底薪）为主**，不要被总包迷惑——到手的钱才是钱，Base 高才是真的香。以下为个人观点仅供参考。

- **概念区分**：
  - **Base**：合同规定的基本底薪，一般不含奖金、福利或附加条件，不受绩效影响；以月为单位（月薪 1 万、2 万通常指 Base）
  - **总包**：工作所得所有价值总和——底薪 + 奖金 + 五险一金 + 股票期权 + 培训津贴 + 住房补贴等；以年为单位（package 10 万、年包 20 万通常指总包）
  - **大厂薪资构成**：Base × 月数 + 绩效奖金 + 股票/期权 + 其他福利 + 一次性签字费
- **为什么总包高不一定是好事（不确定性 2 方面）**：
  - 浮动绩效奖金：如一年 20 个月薪资中藏着 8 个月浮动绩效，部门/个人绩效差可能 1 个月年终都没有，总包直接崩盘（部分公司合同会给应届生承诺保底月数，具体分析）
  - 股票/期权不稳定：股价波动 + 需等解禁才能卖（真实案例：入职时腾讯股价 450 左右，涨到 700 多却要等解禁，后来跌到 200-300，亏超 1/3）；未上市公司的期权要掂量公司发展与可能市值，别被单方面画饼
- **Base 高的好处**：涨薪潜力大——很多公司涨薪幅度按 Base 计算（行情好时跳槽涨薪 30%/50% 多基于 Base），Base 越高未来涨幅越大；对应届生而言 Base 也是基本生活来源（股票/期权常分 3-4 年给完，没人能保证干那么久）
- **例外**：不打算和公司绑定的应届生 → 关注 Base、公司潜力和个人发展最重要；工作多年、追求稳定、在公司有一定地位的老员工 → 总包更重要（干得越久拿到的股票/期权越多，越能证明价值）
- **通用原则**：只要涉及股票/期权授予，就要了解清楚授予机制、公司发展、变现机制、税收影响等

### 招聘季自查四问：目标明确 · 发力到位 · 准备充分 · 心态积极

> 招聘季（秋招/春招）是持续的过程，与其焦虑行情，不如定期用下面 4 个问题自我检查、对症下药。

- **目标是否明确**：把劲往一处使——每个方向都只学 50% 的同学，竞争不过单方向投入 100% 的人；不要因为「寒气」半路纠结换方向（Java 凉了？转 Go/C++？见上文「XX 已凉」言论与转行决策），不确定时先朝自己投入精力最多、学得最深的方向继续，最稳妥
- **发力是否到位（先诊断再发力）**：拿不到面试 → 大概率是简历问题——背再多八股、做再多项目，写不进简历别人就看不见，先解决简历再背题；能拿到面试但总挂 → 复盘三问（① 到底为什么挂？② 每次面试后是否记录了问题？③ 之前没答出的问题后来能答上来了么？）；只埋头投简历+背题而不复盘总结，投 10 份和 100 份的效果可能相当，不过是撞运气
- **准备是否充分**：反例——985 硕士、国奖、实习齐全却面试少、面了就挂：简历太注重堆砌奖项、忽略了体现技术能力（你究竟能做什么），大量时间花在投简历、焦虑和吐槽上；对照的双非同学从大二就以找工作为目标（实习、项目、面试经验丰富），招聘季每天仍学技术、完善简历、刷面试题——「人家准备三年，你准备一年」；还没面临就业压力的低年级同学应趁早准备（行动清单见四区「考完研后的寒假」）
- **心态是否积极**：招聘季窗口仍比拖到明年春招有优势；目标太遥远时可以适当降低预期，每天学点技术、完善一点简历、刷几道题，也是不断靠近目标、超越躺平者；不要借着环境不好否定自己；**杜绝侥幸心理**——笔试作弊、简历造假必暴露（技术手段和竞争关系如此，有时你自己都不知道已被识破，还在网上抱怨找不到工作），适度包装可以、欺骗不行（见「简历 8 技巧」第 8 条）

### 春招补充建议：尽早行动 · 预期管理 · 持续整理 · 海投

> 补充几条春招建议（目标聚焦与心态调节见上一节「招聘季自查四问」），来源为「春招，启动！」。

- **能春招不秋招（尽早行动）**：准备和行动越早，机会越大；别因担心准备不到位就干脆放弃春招、等毕业后再找——错过一个集中的求职时间点、毕业后找工作会更难。哪怕目前什么都不会，也别把目标定得太远（容易自我安慰和拖延、延误战机），有机会就把目标定为「春招上岸」，抓紧学、抓紧突击
- **预期管理**：求职前明确自己的目标和期望——理想的公司、职位、薪资范围，并了解具体招聘要求；这样既能更有针对性地准备，拿到 offer 时也能做出清醒判断。很多咨询 offer 选择的人根本不清楚自己到底想要什么；这点对社招更重要——同一个岗位，不同公司、不同年限的要求完全不同，很多社招岗位还要求特定业务或行业经验
- **持续整理**：关键词是「持续」——学习笔记、背过的八股文、面试后的经验，求职期间接受的所有信息和知识都整理好。春招是高强度、持续的过程，期间会学到很多新知识、也遗忘很多；整理的资料就是一套「缓存」，忘记时不用再从原始资料里重复提取，能快速捡回当时的知识
- **海投**：无论预期如何，投递时建议先海投——别考虑距离远、公司不好，先争取面试机会、通过面试锻炼自己，拿到 offer 后还能作为跟其他公司谈价的筹码；现在大家都在海投，你不海投就亏了（特别优秀自信的除外）

### 秋招进阶建议：建立连接 · 一专多长 · 简历视角切换

> 从招聘方视角补充几条秋招建议（不必全做到，做到 5 条以上秋招大概率能上岸），只列前文各节未覆盖的要点。

- **建立连接（认识大佬、积累人脉）**：求职不只是投简历——若一家公司只招一人，面试官是你的朋友，结果可想而知。途径：多和学长学姐交流（他们进公司后可帮你内推）、多和面试官交流（面试后主动要联系方式，之后有别的机会还能推荐你）、多和 HR 交流（关系好甚至能拿到行业信息）；再通过写博客、参与开源社区、线下交流会认识同行、向上社交。作者真实经历：在 GitHub 上被字节主动邀请面试；坐车时认识一位阿里老乡，没多久就拿到阿里 P6 橄榄枝
- **一专多长**：大家的技术与项目经历区分度低，除主流技术外，**至少深入一个技术**作为个人专长吸引面试官。进阶路径：阅读该技术的高级书籍 → 了解底层原理 → 阅读 GitHub 上的简化版底层实现源码 → 再读官方开源代码 → 尝试提 PR（能给知名项目成功贡献 PR 基本就稳了）。从「学习者」变成「实践者」，再从「实践者」变成「研究者」，优势会被放大
- **切换视角、去掉学生思维**：写简历要用招聘方视角自查（「如果我是面试官，看这份简历会问什么、哪里写得好不好」）。典型问题：写「我的学习能力强」这类自我评价一定要有说服力——列举自学/获奖经历来证明；说文档写得好就贴上文档链接。简历内容在精不在多，避免凑字数、写重复的技术/项目/「正确的废话」（写不满一页时先有啥写啥，后期再持续优化）
- **有的放矢（针对目标公司定制）**：想进某家公司，就仔细阅读岗位描述、提前了解公司业务与系统，针对性地准备项目和简历；简历可加公司 Logo、在个人优势中响应公司价值观、对业务做市场调研，甚至给公司提建议、帮他们修 Bug 都是大加分
- **差异化**：给网络热门项目**换皮并自主增加 2-3 个原项目没有的功能**；或学一个较新、网上教程较少的技术（云原生相关中间件、服务网格、Serverless、DDD 架构设计等）；有开源项目或个人上线项目经历更能突出实践能力——告诉面试官你不止能跟着教程完成项目，而是真能自己做项目
- **时间「复用」**：用同一份时间做多件事——背八股遇到没接触过的知识，不要只背下来，而是搞懂后补充到简历上、合适的话再运用到项目中（如背到 MySQL 性能优化，就把加索引、Explain 分析用到项目里实测），既通过实践理解了题目，又完善了简历和项目

## 六、归纳总结，方法唯上

### 阶段目标

把归纳总结变成终身坚持的习惯，从每次经历中提炼出适合自己的学习工作方法论。

### 核心做法

- **事事皆可总结**：学到知识要总结，完成项目要总结，参加竞赛要总结，每天的实习工作也要总结；凡是有意义的事，无论成功或失败都值得总结。
- **总结不是草草写文档**：要针对某件事从零开始全面复盘——回顾目标、回顾工作、用 5why 提问（为什么要这样做而不是那样做）、分析优缺点、思考如何改进完善。
- **总结的价值**：减少重复错误、优化工作、发散思维，最终提炼出一套适合自己的方法论，帮助在工作中快速适应和晋升。
- **写完后必须存储**：推荐使用云盘，如腾讯微云、阿里云盘、OneDrive、印象笔记，方便日后查阅回顾。学了不总结、总结不存储，就像小熊掰棒子，徒做无用功。
- **总结也能帮助他人**：企业无论大小都会维护自己的知识库，沉淀技术和业务，也给新人提供参考和指导；可以把自己的总结沉淀进去。
- **从重复工作中提炼共性**：工作必然会重复，但重复不代表无法成长——如何从重复中提炼共性、多提想法改进现状，才是值得关注的。

### 用「表达」来学习和检验：写出来 · 讲出来

> **表达和写代码一样，是程序员的核心素养**。表达能力不行，面试就通不过（技术再强也「茶壶里倒饺子」）；入职后对上如何跟老板汇报战功、述职晋升时如何在半小时内打动评委，对下如何和测试、产品对齐方案，都靠表达。把表达当成学习方法，可以一举两得。

- **文字表达**：网上收集的「XX 知识点大全」对别人参考意义很小，**整理知识点的最大价值只对整理者本人有效**——梳理的过程就是构建、完善自己知识体系的过程（面试中不断调整认知），且只有自己一行行打出来的字才真正理解。建议坚持写笔记，可自己搭一个简单的个人博客（GitHub Pages + Jekyll，免费省心、半小时搞定），写作工具推荐 Typora（Markdown、优雅美观）；把文章分享出去、看别人能否看懂，也是检验。
- **语言表达（小黄鸭调试法）**：对着小黄鸭讲解一段代码的思路，用「表达」来梳理逻辑，就能发现潜藏的漏洞。判断一个知识点有没有真正掌握，就看你能不能独立把它讲出来——讲不清只有一个原因：理解还不够深入。也可以拉着朋友一起学习、互相讲解（讲 LeetCode 的股票买卖、凑硬币等智力题同样有效）。
- **进阶**：试着把讲解过程录成视频，能很大程度加深对知识的理解和印象。

## 七、春风化雨，颗粒归仓

### 阶段目标

充分利用时代提供的丰富学习资源，分类收藏、善加选择，并借助人脉合作放大学习效果。

### 核心做法

- **资源丰富，分类收藏**：编程网课、培训资料、项目实战、开放源码、线上直播课等营造了良好的学习环境，应充分利用并分类收藏，颗粒归仓。
- **有选择地使用资源**：资源过多也会造成困扰，看得多了自然能分辨好坏。
- **注重信息时效性**：例如学习新框架时，尽量不要看出版超过 1 年的书籍。
- **线上线下认识前辈伙伴**：多认识优秀的前辈和小伙伴，一起学习讨论，甚至可以合作参加比赛、开发作品；一个人坚持会很孤单，结伴前行收获的不仅是编程能力的提升，还有友谊。

## 总结

整个学习与求职过程就像一次大数据推荐：起初面对海量知识感到迷茫；经过学习和摸索产生兴趣，挑选几个相对感兴趣的技术深入学习，过滤掉不感兴趣的；随着知识积累、喜好明朗，确定求职目标和主要技术方向；然后日复一日坚持学习，通过项目实战、参加竞赛、找实习提升实践能力；最后放手一搏，把技术展现给面试官，找到心仪的工作。过程中的每个行为都会影响最终的面试结果，你现在做的每个努力，都有意义。
