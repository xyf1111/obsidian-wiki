# 自学编程的入门方法

> 面向刚高考完、想提前学习编程的零基础初学者：如何选专业、如何入门编程、常见学习误区与建议。

## 计算机专业怎么选

### 课程：本科阶段专业区别不大

大学阶段，很多计算机相关课程都是**公共课**，是打好基础、修炼基本功的：

- 计算机导论
- 离散数学
- 数据结构与算法
- 操作系统
- 编译原理
- 数据库系统原理
- 计算机网络

无论学什么专业，这些基础课都要好好学，它们占据了大一大二的时间。大二下学期或大三开始，不同专业的课程才出现差异。

### 软件工程 vs 计算机科学与技术

**软件工程**（偏应用 / 上层）

- 特色课：软件架构设计、软件项目管理、软件体系结构等
- 培养软件设计与实现的思想、方法和技术能力
- 相对更专精

**计算机科学与技术**（偏理论 / 底层）

- 特色课：计算机组成原理、汇编语言、微机原理等
- 软 / 硬件都会涉及的计算机学科宽口径专业
- 相对更全面

### 其他计算机类专业

- 网络工程：运维、网络设计、管理
- 信息安全：密码学、网络攻防、渗透
- 大数据、人工智能、嵌入式、物联网等

这些专业各有特色课，但大三要忙于找工作 / 考研，剩下能学到的企业实践知识有限。

### 结论

- 本科阶段各专业教的东西有限，未来就业还是读研、从事什么职业，取决于大学期间的思考、感悟和拼搏
- 无论选什么专业，大部分毕业生最终都是开发程序员（算法工程师岗位竞争异常激烈）
- **没有明确方向就选软件工程**——它与开发程序员今后的工作最相关

## 如何入门编程

### 先培养兴趣

- 不要一上来就啃复杂的书籍和路线大纲，容易被枯燥的理论劝退
- 入门重点在于寓教于乐：写的每一行代码都应能直接看到效果

### 选一门零基础语言

**Web 前端（最推荐）**

- 容易上手，写的每行代码立刻能看到效果
- 学习 1-2 周即可写出自己的网站（留言板、记事本、个人博客、个人笔记等），还能发布到网上给同学访问
- 包含 HTML、CSS、JS 三门语言，语法各有千秋，能感受编程语言的多样性，学到更多编程知识与技能
- 学会后可做网站、APP、桌面应用、小程序，有机会实现自己的想法

**Python**

- 适合想做小工具的同学

**C / C++**

- 适合想打好基础的同学

### 推荐学习网站：FreeCodeCamp

- 免费、在线实战、适合零基础入门的学编程网站，偏 Web 前端
- 地址：https://learn.freecodecamp.one/
- 用法：跟着左侧的教程，一步步在中间的编辑框中输入代码，完成任务、通过关卡
- 不需要看任何复杂书籍，轻松愉快入门

## 编程学习 4 点建议

编程学习没有捷径，需要明晰目标、拉长战线、掌握技巧、持续学习、做足准备。

### ① 确定目标、制定规划、脚踏实地

- 可参考把编程学习分为 7 个阶段的学习架构，规划自己的学习路径

### ② 不同阶段选择适合的学习方法

**核心原则：以能学下去为前提，保证学习效率最大化；不同阶段选择不同类型的资源。**

**分阶段的资源类型选择：**

| 学习阶段 | 推荐资源 | 说明 |
|---------|---------|------|
| 初学入门 | 在线实战练习网站 | 敲代码闯关式网站（如 FreeCodeCamp），快速上手、培养兴趣，能直接写出入门级代码 |
| 打基础 | 经典书籍 | 入门后不要再依赖练习网站（没有任何网站能带你从入门到精通），读一本经典书籍巩固基础（如 Java 读《Java 核心技术卷 1》）；看书枯燥可先看视频课程，但看完必须倒过来读经典书籍，基础不牢就强学框架必然踩坑 |
| 学框架 | 视频教程 | 框架要先会用、再理解和深挖原理；跟着老师节奏敲代码多练习，系列视频看完一定要亲自做出个项目，否则「一看就会，一写就废」 |
| 提升实践 | 开源项目 | 阅读他人代码、学习代码规范和写法技巧；只照视频教程写，遇到不规范的写法可能被误导一辈子 |
| 深入底层 | 技术书籍 | 系统学习一门技术（如 JVM 的设计思路、实现原理、性能调优），大厂面试必问底层；优秀程序员要能写出高可用、高性能、可扩展的好代码 |
| 持续进阶 | 官方文档 / 源码 | 官方文档最新、最专业、最全面，其他所有资源都建立在它之上；更彻底的方式是直接看源码，源代码面前没有秘密 |

**基础是否打好的判断标准**：能把书中或视频中学到的知识理解并能写出代码实际应用。比如学面向对象继承，不能只知语法，还要知道继承的好处和适用场景。

**同类资源对比的 7 个因素：**

1. **资源时效**：选较新、未过时的资源。经典理论、基础知识和编程语言视频时效较长，几年前的也能看；但框架和类库一定要看近 2 年内的（如学 SpringBoot 看 2.x 不看 1.x），否则照着过时写法敲代码怎么都运行不了。
2. **作者或机构**：优先技术圈知名大佬写的书——能在 IT 圈获得认可的大佬创作更专业；培训机构网课比起机构名声更看重老师本人（学员反馈、讲课方式是否让你舒适），可以跟一位老师长期学习。
3. **资源内容**：先看一遍目录了解大概，很多知识已掌握就不必再跟学；同类资源（如两套视频课）互相对比目录再做决定。
4. **目标匹配度**：追求全面可选覆盖知识点更多的课程（熟悉的内容快速跳过）；时间紧张想速成则选小而精的课程。
5. **资源质量**：排版、清晰度、有无杂音等基本要求，学习同时注意保护视力和听力。
6. **配套资源**：优秀书籍和课程会配套代码练习、习题答案、讲义、笔记等，利用好能显著提升学习效率。
7. **资源认可度**：参考豆瓣评分、播放量、收藏数、好评率等，但流量时代数据可刷，多问身边同学的真实意见。

**其他建议**：把认为不错的资源保存下来，方便复习和分享；难以抉择时先分别试看一部分内容再决定。

## 编程学习误区

### 以看视频时长衡量学习量是致命误区

- 很多同学以看视频课程的时长来衡量自己学了多少编程知识
- 陷入这个误区会一味看课刷课、自我安慰，直到看几个月视频后上手写代码，才发现自己根本写不出来

**为什么是误区？**

- 编程需要靠实践来提升水平，看视频再明白、不上手写代码就是纸上谈兵
- 绝大多数视频课程都是顺风顺水地带你演示项目，很多错误和细节根本看不到

**正确做法：**

- 每看一部分视频，就跟着老师的节奏亲自编写代码
- 不仅要完成视频中的项目，还要自己做更多的项目

### 解决问题的正循环

- 写代码时总会遇到各种问题和报错，一定要多尝试自己解决，而不是直接求人
- 解决问题后加以记录和总结
- 久而久之积累起自己的问题库，对知识的理解和印象更深刻
- 编程水平突飞猛进、解决问题的效率越来越高，形成完全的正循环反馈

## 别被框架束缚：学框架的通病与建议

> 不少同学「离了框架不会写代码、框架没有的功能就不会做」，本质上是「离了视频教程就不会写代码、老师不讲的功能就不会做」。框架只是工具，底层原理要心里有数。

- **实例：用了 MyBatis Plus 却不会动态建表**——需求是根据前端传来的字段自动创建/修改数据库表（字段不固定）。其实 MyBatis、MyBatis Plus 底层都是 JDBC（数据访问框架对 JDBC 的抽象封装），而 JDBC 可以执行**任意** SQL：
  ```java
  // 根据前端字段动态生成建表 SQL，再用 JDBC 执行
  Connection conn = DriverManager.getConnection(url, username, password);
  PreparedStatement stat = conn.prepareStatement(sql); // sql 由程序生成
  stat.executeUpdate();
  ```
  用 MyBatis 同样可以：自定义一个 Mapper，把任意完整 SQL 作为 value 传进 mapper.xml（`${value}`），就能在业务层用 Java 代码灵活生成 SQL，而不是把 SQL 写死到 mapper 里
  ```xml
  <mapper namespace="com.example.MyMapper">
    <insert id="insert" parameterType="java.lang.String">
      ${value}
    </insert>
  </mapper>
  ```
- **⚠️ 动态拼接 SQL 要注意防注入**：`${}` 是直接拼接，有 SQL 注入风险，需对字段名/类型做校验白名单处理
- **只跟着视频教程学的 3 个问题**：① 课程追求快速入门，留给你的思考时间有限；② 很多代码中的坑不会带你踩；③ 很多扩展知识不会带你发现。不主动思考、不多写代码、不自己探索知识，就容易被框架束缚
- **4 条学习建议**：
  1. **入门按路线老老实实学**：JDBC、Servlet 这类基础也要适当了解，不要一上来只学框架
  2. **学框架多思考它怎么运作**：如 Spring Boot 的注解做了什么事？没有 Spring Boot 你怎么达到同样的效果？刚开始以会用为主，但可以把这些问题记下来，之后再慢慢解决
  3. **用框架开发自己的类库/组件**：如开发 Spring Boot starter、前端 hooks，能更好地理解框架原理，写在简历上比「xx 管理系统」亮眼很多
  4. **多读官方文档**：了解并实践框架的配置和更多特性，弥补视频中遗漏的知识点——大家用同一个框架，你能用得更好
- **做后端要自己多写 SQL**，不要被 MyBatis Plus 这类框架「锁」住

## 求知溯源：学技术要知其所以然

> 出自一位自学能力很强的同学：聊到某项技术时，他能清晰地讲出技术的发展历史，也因此对技术有更深刻的认识，知道哪些技术值得学。

- **灵魂三连问**：为什么十年前 PHP 在国内很流行，而如今 Java 占据了后端开发的半壁江山？你了解过编程语言或技术的发展史么？只知道很多人在学 Java，你知道为什么要学 Java 么？
- 如果回答不出来，说明你只看到了现在，而忽略了一门语言或技术兴衰的本质
- **技术人物同样可以溯源**：聊到某位大佬时，去查阅了解这个人的故事，通过他此前的所作所为分析成功秘诀和性格特征，取其精华去其糟粕，帮助自己在正确的道路上成长

## 读源码的时机：积累与性价比

> 不要看别人读源码，你也跟着读，更不必因此焦虑——真正敢说自己读过牛逼源码的同学始终是少数。该不该读、什么时候读，取决于两个因素：**积累** 和 **性价比**。

### 积累：先会用、再深挖

没有足够积累、缺少前置知识（如设计模式）就直接读源码，必然知难而退或半途而废。学任何技术都应遵循递进步骤：

1. 先了解这门技术的作用（如 Nginx 是高性能 HTTP 和反向代理 Web 服务器）
2. 能使用该技术解决问题、完成需求（如用 Nginx 搭网站并支持他人访问）
3. 学习如何更好地用它（了解各项配置、按场景调参、提升性能）
4. 了解其架构组成、各模块作用与通讯机制、核心设计原理
5. 最后才是阅读源码、深挖细节

找工作不一定要读牛逼源码，一般做到第 4 步（了解架构和设计原理）就足够了。

### 性价比：带着目的去读

- 读源码极其耗时，要衡量性价比：是去看源码，还是去做自己的项目？取决于当前阶段和发展目标——技术已能满足做项目需求时，不必投入太多时间读源码；写程序遇到问题时本能地追踪进源代码分析，即**带着目的去读源码**，收获最大。
- **理想方式**：先猜想作者会怎么实现、心中有大致的预期和方案，再通过读源码验证猜想——类比做数学题是「检查答案」，而不是没学过知识点就硬看答案。
- **求职者建议**：还没有项目经历时，先不要花太多时间读源码（可以了解），把企业中常用的技术框架玩转，源码等找到工作后再精心研究也不迟。

## 初学心态与代码阅读方法

### 初学编程的心态：别担心，我们都一样

刚开始学编程，代码又长又多、看不懂源码、自己写的代码 Bug 多、算法题不会做、学了就忘——这些问题所有学编程的同学都经历过，很正常，不要因此怀疑自己。

- **多尝试方向**：除了正在学的语言，也可以尝试其他方向（如前端），重新找到对编程的兴趣
- **自主学习**：不要只依赖课堂和老师，多通过网上搜集资料自学，找到适合自己的学习方法
- **相信自己能学好**：让学习进度保持超前而不是拖拉，自信心会慢慢提升

### 复杂代码 / 逻辑拆解法

- **语法看不懂** → 用搜索引擎查询、翻阅官方文档
- **逻辑看不懂**（如算法题）→ 先试着用中文依次描述整个程序 => 单个函数 => 部分代码片段的作用，再一行一行代码调试、观察变量的变化
- **工作中遇到复杂逻辑同样适用**：先给程序写中文大纲、再逐步拆解细化，静下心来慢慢啃，没有什么逻辑是啃不下来的

### 写代码 + 整理笔记

- 看过的视频知识会忘记，但**写过的代码、做过的笔记是自己的财富**
- 初学编程一定要多写代码、整理思路为笔记，看自己整理的内容通常比接受别人的知识更轻松

### 坚持与连续学习

- 初学编程一定要坚持，**不要三天打鱼两天晒网**，学一天停一天
- 用连续的时间学习编程效率更高、也更容易记住

## 兴趣与成就感驱动

- **爱上编程往往需要一个契机**：可能是读到一本经典好书（如《Java 编程思想》），即使一开始难懂，也会被其中蕴含的思想吸引，一看就是一整天——每一行代码都凝结着前人的智慧结晶
- **成就感是最好的持续动力**：用所学知识一步步实现项目需求、解决实际问题，看着需求被一点点实现会让人上瘾、甚至废寝忘食；这种持续的成就感远比「找工作」这类外部理由更能支撑长期学习
- **任何时候开始都不晚**：即使大学前几年荒废、考研失败，只要找到兴趣并坚持，边工作/实习边学习也能成功转行上岸；过去的失败不等于人生的失败

## 学习多门编程语言的经验

> 学编程 5 年多，学过十几种语言（C、C++、Java、Python、JavaScript、Go、PHP、C#、SQL、Scala 等）。学过的语言很多，熟练的就那么几个，很多语言学完不写就忘了；但也正是这些经历，让我摸清了编程学习的门道。

### 为什么学多门语言

- **兴趣**：高中时就想做自己的网站，上大学第一个自学的是前端，学了 HTML、CSS、JavaScript 三件套
- **学校课程**：跟着学校学了 C 语言（学得一塌糊涂，最后写了个图书管理系统）；后来又自学 C++，写了一点简单的桌面程序
- **找工作**：听说 Java 好找工作才转学 Java，直到学了企业级开发、接触 Spring 等框架后才真正理解 Java 的价值，并坚持走后台开发路线，后续又学了 SQL、Scala 等
- **项目需要**：
  - Python：大一为完成一个数据抓取 + 可视化项目，听说简单、做得快，学几天就搞定了
  - Go：当时在实验室搞区块链，用的框架是 Go 语言
  - C#：实验室有个桌面端项目要用
  - C++：算法竞赛、保研机试都用它，拿 C++ 刷了几百道 OJ 题，毕设还用它做了个图像处理程序
  - PHP：听说它是"世界上最好的语言"就学了，开发确实很爽，但如今大公司基本不用

### 坏处

- **语法容易记混**：每种语言在数据类型、语法和 API 上都有差别，语言学多了时常陷入混乱；尤其是 Go，语法和其他语言差别极大（如 Go 与 Java 语法对比），简直怀疑人生
- **工作中多语言切换容易写混**：既要写 Java 又要写 JavaScript 时，经常在 Java 中写 JavaScript 的函数、在 JavaScript 中 new Java 的对象
- **开发工具不统一**：白天工作用 Mac、晚上用 Windows，开发工具的快捷键不一样，切换成本很高

### 好处

- **摸清语言学习套路**：语言无非是数据类型、流程控制、函数对象和一些特性，学新语言越来越轻松快速（没学过 Kotlin，也能看懂并重构 Kotlin 代码）
- **学到更多设计思想**：了解每种语言更适合做什么，理解了编译型 vs 解释型语言的区别与该如何选型
- **看代码不被语言束缚**：基本啥都能看懂，交流编程语言时也有了更多发言权，不必再纠结"什么是最好的编程语言"
- **开发时工具选择更多**：如处理 Excel 表格，只会 Java 只能用 Java 类库、不够方便；会 Python 就有更多类库可选，几行代码搞定、效率拉满
- **最重要的：找到最适合自己的语言**：正是因为学了更多语言，才从前端转到了 Java 后端

### 建议

- **技多不压身**：会的语言越多越好，但一定要先重点学好一门——深入理解一门语言后，再学别的就很简单；时间有限，把每门语言都学得很精不现实（编程领域还有太多技术、工具、方法、思想要学），什么语言都浅尝辄止，面试时一定会吃大亏
- **语法混淆靠编辑器纠正**：现在的编辑器语法校验功能都很强大，语法输错了也能很快纠正过来
- **不必刻意背语法**：干脆就别去记忆语法，熟能生巧

## 如何做好项目：11 条实践建议

> 为什么同样做项目，有人完成得快、做完能独立开发，有人做了几个项目还是啥都不会？差距在于方法和投入。学好项目没有捷径，核心就两点：**掌握正确的方法 + 投入大量的时间**。

1. **选择合适的项目**：做项目前至少学完一门框架（前端 Vue/React、后端 Spring Boot）；按当前技术栈和水平选项目，刚学完框架不要为了赶时间一上来就做微服务、高并发项目，先掌握项目基本开发流程；如果项目里没学过的技术太多、又没有对应教程讲解，先暂停项目补充知识再来
2. **多敲代码**：看完教程必须自己把每行代码都敲出来，才算真正学过这个项目——「一看就会、一写就废」往往是因为只顾着看教程没动手；不要以「掌握理论、背熟八股文」作为学好项目的标准
3. **自主思考**：跟着教程多问「为什么要这么设计？有什么好处？有没有更好的写法？」，必要时查资料验证；讲师说的不一定是最优解，能提出和讲师不同的方案就很棒
4. **持续记录**：做项目时多写笔记，重点记录自己的理解、遇到的问题和解决方案；自己写过的每行代码都完整保存，学得更多后回头对比，能直观感受进步
5. **自主解决问题（最重要）**：主流技术遇到的 Bug 别人一定也遇到过，99% 都能自己解决——先搜集足够多的错误信息（如日志），再查搜索引擎、技术社区、官方文档、问 AI；实在解决不了再求助，但要把问题描述清楚、列出已尝试过的方案
6. **多读官方文档**：新技术层出不穷，不可能每个都有保姆级教程，公司自研技术只能靠文档；学完新技术花 1-2 小时读官方文档，既能了解教程之外的技术特性，也提升读文档、学新技术的能力
7. **多写文档**：每做完一个项目写完整的项目总结文档（背景、设计、实现、亮点），从上帝视角回顾巩固，也便于写简历、开源分享；有能力的画功能模块图、架构图、UML 类图（一图胜千言）；写不出总结文档，说明项目还没完全掌握
8. **自主优化**：给项目增加几个扩展点、回顾代码找优化空间（如代码规范），增加简历区分度；可以等半年后以更高的水平回头优化之前的项目（所以自己的代码一定要留好）
9. **上线项目**：本地完成后尽量上线并正常运行一段时间，跑通整个流程——独立开发者必备技能，也能大幅增加简历的真实性
10. **主动分享**：把项目和总结文档分享给同学，他人帮你「测试」网站、指出不足，带来更多优化思路和机会，也给自己正反馈
11. **学会合作**：时间有限时找方向互补的朋友协作开发（前端配后端），一起参加竞赛也是极好的

> 认真完成并理解 4 个及以上项目，做项目的能力可达中厂水平。

## 找项目的途径：通用 / 校园 / 职场

> 学编程一定要多做项目来提升实力、丰富简历，但去哪儿找项目？按身份分为通用、校园、职场三类途径。

### 通用

- **开源项目**：通过 GitHub 等开源平台，有机会和编程大佬一起做项目。不要担心水平不够——找感兴趣的项目，从简单的工作（如 good first issue）上手开发；给知名项目贡献代码的简历含金量可能远大于自己写一个小系统
- **实验平台（Lab）**：FreeCodeCamp、CodeGym 等实战平台提供帮助初学者快速上手的小例子和项目；腾讯云动手实验室、实验楼等基于真实服务器开发环境，有练手小实验也有完整项目；英文不错可去啃国外优质课程实验——MIT 6.s081 操作系统工程、MIT 6.824 分布式系统、斯坦福 CS143 编译原理，啃下来实力足以进大厂
- **学习资源**：B 站等视频教程一般都会带大家做一个项目；**千万不要只看不做**，一个视频看下来一定要有样学样亲手肝出来一个项目
- **做你所想**：有不错的想法和创意，不妨用所学的技术实现它——兴趣驱动反而更有动力完成，可以边做边自主学习更多技术把它做得更好

### 校园

- **课堂大作业**：最直接的项目——很多专业课期末要求上交作品，虽然可能拿不出手，但可以在现有代码上继续完善、开发新功能；也可以把自己基于兴趣做的项目略加修改当作业提交，分数往往更高；认真完成并好好留存作业代码
- **帮老师做项目**：学院和老师常有计算机方面需求（学院网站、管理系统等），可以向老师和辅导员表达意愿争取机会；老师要求一般不高、好沟通，锻炼编程水平的同时还能赚钱
- **参与竞赛**：互联网+、挑战杯、计算机应用能力大赛、ACM 等；多组队参与能提升兴趣、培养责任感、促进学习和完善项目，还能互相学习进步；**毕业之后机会就很少了，强烈建议大学时参加**
- **工作室 / 社团**：计算机、编程类工作室或社团一般有学长大佬带队，一起学习讨论氛围更好
- **实验室**：本科期间加入学院实验室，在研究生学长和导师带领下做项目；很多实验室乐于接受和培养本科同学，机会要自己争取

### 职场

- **参与公司建设**：想更快晋升、提高技术影响力，多参与和完善公司内部项目（如内部定时任务平台不够方便就去优化它），也可以自己造轮子
- **参与竞赛**：小程序开发、应用开发、大数据竞赛等面向职场开放，还有不少以公司、团队为单位的竞赛；BAT 大厂内部也常定期举办技术类竞赛
- **外包平台**：程序员客栈等接单平台可远程参与项目，根据需求复杂度获取相应收益，甚至可以把自己外包出去

> 学会积累和复用：把自己做过的每个项目保存好。同一个项目既可以当课堂大作业、又可以拿去参加竞赛，一举两得。

## 后端要不要学前端（全栈取舍）

> 核心是性价比：后端学到什么程度再去学前端？

### 时机判断

- **初学阶段先专注一个方向**：先一条路入门单个编程语言/方向，更快做出完整作品、提高兴趣；大部分公司只要纯后端或纯前端，专注一个方向学得更深才更有优势，不要反复横跳（纠结「Java 太卷要不要转 C++/Go」同理）
- **以后端为主**：在没有达到后端入职标准、后端知识没玩明白前，不要抽大量时间学前端（时间紧的话不学前端完全没问题）；后端建议先学完 Java 学习路线上的 Spring Cloud 微服务章节
- **时间充裕且后端进度 ok** 时，再抽小部分时间自学前端
- **工作后**：想晋升高工、当 Leader 或项目负责人的朋友建议学前端，拓宽技能边界

### 学前端的好处

- 和前端配合、沟通更顺畅，能站在更高层、全局的角度设计项目整体的前后端实现方案，不被前端方案牵着走
- 懂前端能设计出更干净的接口：如给每个请求单独写一个接收参数的对象，自动生成的接口文档更清晰，前端更清楚要传什么参数（也更安全）

### 后端学前端的最小集

1. **三件套 + Vue**：做到能看懂代码、通过复制粘贴 + 修改完成开发
2. **Ajax 和 HTTP 协议**：理解前端与后端如何交互，从全局角度排查问题、划分前后端错误边界（后端本来就要重点学 HTTP 协议）
3. **打包工具**：知道怎么构建部署前端项目

> 做完一个前后端完整的项目（如伙伴匹配系统），后端的前端水平基本就够用了，剩下有空多练习。

### 入门资源

- B 站 Pink 老师前端入门视频（很详细，适合慢学）
- FreeCodeCamp 在线代码训练（很直接，适合速学）

## 如何提高行动力（拒绝拖延的 6 个方法）

> 打破焦虑的最好办法，不是收藏多少资源、自怨自艾，而是立刻开始行动。以下 6 个方法来自长期与拖延作斗争、最终调整好状态的经验总结。

1. **随手记录**：利用碎片时间随手记录想法、学到的知识和做完的事——看到好笔记随手收藏、与人交流有启发立刻用手机记下、有项目灵感马上记下来、吃饭时记录白天完成的工作。难的不是记录，而是养成「想到就记录」的习惯。
2. **做好 2 个 list**：todoList（计划）让学习工作更有计划性，但完不成容易产生挫败感；配合 doneList（每完成一项打勾 ✅）能持续给自己正反馈、激励前行——即使计划常完不成，也比不做计划走得快得多。工作后计划临时增减是常态，享受持续完成事情的感觉即可。
3. **正确的心理暗示**：座右铭「相信自己有能力，那么你就真的会有」。遇到困难（如一个 Bug）不要自我否定（「我太菜了、肯定解决不了」），而是正向暗示自己一定能搞定；自信可以后天培养。
4. **进入心流**：心流 = 完全投入、高度专注的「忘我」状态，效率更高且结束后有满足感。可以培养一个「仪式感暗示」帮助快速进入状态，比如戴上耳机就代表开始工作；简单到深呼吸、吃水果、默念几句话也可以。
5. **立即行动**：不要找任何理由拖延，先做起来会发现没那么难；利用外部约束逼自己——立 Flag、公开承诺 Deadline，即使最后没完成，也比不立 Flag 的进度快。
6. **任务拆解 + 每个子任务设 deadline**：人本能地抗拒庞大困难的任务，不拆分的结局往往是直接放弃。把大任务拆成小任务逐个击破，靠完成一个个小目标收获成就感、保持热血；同时给每个子任务都设 deadline——没有截止时间就会不紧不慢、想些有的没的，忽视关键目标。实测同一个任务给 3 天能按预期完成，给 1 周反而完不成，所以要多设 deadline、持续给自己压迫感。
   - **教训：做事要分主次**：作者大学独立开发 APP 时，60-70% 的时间花在了产品功能和界面设计上，而主要目的其实是学后端微服务——明确项目的核心目的，别在次要环节（界面细节、图标素材选取）上过度纠结；深夜思考迟缓更容易陷入无意义纠结，熬夜做无意义的事是最大的浪费。
   - **与上一方法互补**：方法 5 靠外部承诺逼自己，方法 6 是从内部把任务拆碎、逐项设限，两者可叠加使用。

#### 任务拆解 + deadline 的实际应用

- **做项目**：先定总目标（如 1 个月内上线），再拆解：3 天确定产品功能、1 天参考同类产品设计（把更多时间留给开发）、1 天设计库表、7 天开发前端、3 天开发后端（1 天登录、2 天基础增删改查），剩余时间填充网页内容和优化；没按预期完成小任务时反思原因，动态调整剩余工作的时间，保证整体目标达成。
- **学编程**：先扫一遍视频（书籍）目录，根据视频时长和章节定总目标（如 1 个月学完 Java 基础），再拆解：3 天搭好环境跑起项目、5 天学完基础语法、10 天学完面向对象、5 天做一个实战项目、最后 5 天学习高级特性并复习。
- **刷算法**：定下目标每天 2-3 道题、每道限时 30 分钟，想不出来直接看题解，有了思路再想、再多复习巩固——避免在一道题上硬耗几个小时（作者用这个方法一年半刷了 1000 多道题）。
