# Go 底层原理 09 — 内存分配器

## 核心思想：TCMalloc

Go 的内存分配器基于 **TCMalloc（Thread-Caching Malloc）** 设计：

- **多级缓存** — 减少锁竞争
- **大小分级** — 按对象大小分不同管理策略
- **无锁操作** — 大部分分配无需加锁

## 内存管理层次

```
  分配请求
     │
     ├── ≤ 16B  → 微型分配器（tiny allocator）
     │
     ├── ≤ 32KB → 当前 P 的 mcache（无锁）
     │               │
     │               └── mcache 不足 → mcentral（有锁）
     │                                      │
     │                                      └── mcentral 不足 → mheap（全局）
     │                                                              │
     └── > 32KB → 直接从 mheap 分配（大对象）
                                                              │
                                                    munmap syscall
```

## 数据结构详解

### mspan — 内存页管理单元

```go
type mspan struct {
    next        *mspan         // 链表下一个
    prev        *mspan         // 链表上一个
    startAddr   uintptr        // 起始地址
    npages      uintptr        // 页数
    freeindex   uint16         // 空闲对象索引
    nelems      uint16         // 对象总数
    allocBits   *gcBits        // 分配位图
    spanclass   spanClass      // 规格（如 class 1 = 8 bytes）
    state       mSpanStateBox  // 状态
    sweepgen    uint32         // 清理代
}
```

### spanClass — 67 种规格

| class | 对象大小 | 页数 | 说明 |
|-------|---------|------|------|
| 1 | 8 B | 1 | 最小对象 |
| 2 | 16 B | 1 | |
| ... | ... | ... | |
| 67 | 32 KB | 1 | 最大小对象 |
| 大对象 | > 32 KB | 自定义 | 直接由 mheap 管理 |

### mcache — 每 P 缓存（无锁）

```go
type mcache struct {
    alloc [numSpanClasses]*mspan  // 每个 spanClass 对应一个 mspan
    tiny  uintptr                  // 微型分配器偏移
    tinyoffset uintptr
    tinyAllocs uintptr
}
```

- 每个 **P** 有自己独立的 mcache
- 小对象分配**不需要加锁**
- 零存整取：从 mcentral 获取一整段 mspan

### mcentral — 中心缓存

```go
type mcentral struct {
    spanclass spanClass
    partial   [2]spanSet  // 已清理的 span
    full      [2]spanSet  // 待清理的 span
}
```

- 每个 spanClass 一个 mcentral
- mcache 不足时从 mcentral 取
- mcache 有多余时归还给 mcentral
- 需要加锁

### mheap — 全局堆

```go
type mheap struct {
    lock      mutex          // 全局锁
    arenas    []arena        // 虚拟内存区（64MB/块）
    central   [numSpanClasses]mcentral  // 所有中心缓存
    pages     pageAlloc      // 页分配器
    sweepArenas []arena_idx  // 等待清理的 arena

    // 大对象直接分配
    largealloc  uint64
    largefree   uint64
}
```

## 分配流程详解

### 1. 微型分配器（≤ 16 B）

```go
// 小结构体指针等
type small struct {
    a, b uint64  // 16 字节
    c    bool    // 1 字节
}
// 多个小对象合并到一个 16 字节槽位
```

### 2. 小对象（≤ 32 KB）

```go
// 1. 计算对象的 spanClass
// 2. 从 mcache.alloc[class] 取 mspan
// 3. 从 mspan 的空闲链表取一个槽位
// 4. mspan 空时从 mcentral 取新 mspan
// 5. mcentral 空时从 mheap 取新 mspan
```

### 3. 大对象（> 32 KB）

```go
// 直接从 mheap.alloc 分配
// 按页数（npages = size / pageSize）分配
// 直接管理，不经过 mcache/mcentral
```

## 逃逸分析

编译器决定对象分配在栈上还是堆上：

```go
// 栈上分配（没有逃逸）
func sum() int {
    nums := make([]int, 3)  // 大小已知，栈上分配
    return nums[0] + nums[1] + nums[2]
}

// 堆上分配（逃逸到堆）
func newCounter() *int {
    i := 42
    return &i   // 指针被返回，i 逃逸到堆
}

// 接口逃逸
func printVal(v interface{}) {
    fmt.Println(v)
}
printVal(42)    // int 被装箱到 eface，逃逸到堆
```

### 查看逃逸分析

```bash
go build -gcflags '-m -l' main.go  # -m 显示逃逸分析
# 输出示例：
# ./main.go:10:6: moved to heap: i
# ./main.go:15:13: 42 escapes to heap
```

## 内存统计与调试

```go
import "runtime"

var m runtime.MemStats
runtime.ReadMemStats(&m)

fmt.Printf("Alloc = %v MiB", m.Alloc / 1024 / 1024)
fmt.Printf("TotalAlloc = %v MiB", m.TotalAlloc / 1024 / 1024)
fmt.Printf("Sys = %v MiB", m.Sys / 1024 / 1024)
fmt.Printf("NumGC = %v\n", m.NumGC)
```

```bash
# GODEBUG 查看 GC 日志
GODEBUG=gctrace=1 go run main.go

```
