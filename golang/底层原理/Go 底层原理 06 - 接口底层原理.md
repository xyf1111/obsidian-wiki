# Go 底层原理 06 — 接口底层原理

## eface 与 iface

Go 接口在运行时由两种结构体表示：

### eface（空接口 `interface{}`）

```go
type eface struct {
    _type *_type         // 指向实际类型的元数据
    data  unsafe.Pointer // 指向实际值的指针
}
```

### iface（有方法的接口）

```go
type iface struct {
    tab  *itab           // 接口表：类型 + 方法集
    data unsafe.Pointer  // 指向实际值的指针
}

type itab struct {
    inter *interfacetype  // 接口类型信息
    _type *_type          // 实际类型信息
    hash  uint32          // 类型哈希（用于快速类型断言）
    fun   [1]uintptr      // 方法地址数组（变长）
}
```

## 接口值的内存布局

```go
var i interface{}       // eface{nil, nil}
i = 42                  // eface{int_type, &42}

var r io.Reader         // iface{tab=nil, data=nil}
r = os.Stdin            // iface{tab=&itab{os.Stdin, *os.File}, data=&os.File{...}}
```

### nil 接口 vs 有类型 nil

```go
// ⚠️ 经典陷阱
var p *int = nil
var i interface{} = p

fmt.Println(p == nil)   // true
fmt.Println(i == nil)   // false！因为 eface 中 _type != nil
```

```
p 的值：
┌─────────────┐
│ _type = nil  │     ← 类型信息是 nil
│ data  = nil  │
└─────────────┘

i 的值（赋值后）：
┌─────────────┐
│ _type = *int │     ← 类型信息是 *int，非 nil！
│ data  = nil  │
└─────────────┘
```

## 类型断言底层

```go
var i interface{} = "hello"

// 安全断言
s, ok := i.(string)    // ok = true, s = "hello"
n, ok := i.(int)       // ok = false, n = 0

// 不安全断言（失败会 panic）
s := i.(string)        // ✅
// n := i.(int)        // ❌ panic
```

### 底层流程

1. 获取 `eface._type` 或 `iface.tab._type`
2. 和目标类型比较 `_type`
3. 如果匹配，从 `data` 指针拷贝值
4. 不匹配返回零值 + false（或 panic）

### switch 类型断言

```go
switch v := i.(type) {
case string:
    fmt.Println("string:", v)
case int:
    fmt.Println("int:", v)
default:
    fmt.Printf("unknown type: %T", v)
}
```

## 动态派发（Dynamic Dispatch）

通过接口调用方法需要**查 itab 找到方法地址**，比直接调用慢：

```go
type Printer interface {
    Print()
}

type MyPrinter struct{}

func (p MyPrinter) Print() {}  // 值接收者

var p Printer = MyPrinter{}
p.Print()  // 动态派发：通过 itab.fun 查找方法地址
```

### 性能影响

```go
// 直接调用（静态绑定）—— 快
mp := MyPrinter{}
mp.Print()

// 接口调用（动态派发）—— 慢 10-20%
var p Printer = mp
p.Print()
```

> ⚠️ 动态派发在**内联优化**时也会被阻止，实际影响因场景而异。

## 接口比较

两个接口值相等当且仅当：

1. **类型相同**（`_type` 指向同一类型元数据）
2. **值可比较且相等**

```go
var a interface{} = [2]int{1, 2}
var b interface{} = [2]int{1, 2}
fmt.Println(a == b) // true

var c interface{} = []int{1, 2} // slice 不可比较
// fmt.Println(c == c)          // ❌ panic：runtime comparing uncomparable type []int
```
