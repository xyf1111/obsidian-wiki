# Go 面试 10 - 26 届春招 Go 热题

> 26 届春招 Go 高频面试题汇总（Go 语言基础 / 底层原理 / 并发），每题为「回答重点 + 扩展知识」结构。

## 一、非接口的任意类型 T 都能调用 *T 的方法么？反过来呢？

**回答重点**：都可以。

- 对于非接口的任意类型 T，确实可以调用 `*T`（指向 T 的指针）的方法：当在一个 T 类型的值上调用 `*T` 方法时，Go 编译器会**隐式获取该值的地址**，再调用相应方法——这种行为称为「指针接收者方法调用的自动解引用」。
- 反过来，`*T` 类型的值也可以调用 T 的方法，因为 `*T` 的方法集同时包含接收者为 T 和 `*T` 的方法。

### 示例代码

```go
package main

import "fmt"

type MyStruct struct {
	field int
}

func (ms MyStruct) ValueReceiverMethod() {
	fmt.Println("ValueReceiverMethod")
}

func (ms *MyStruct) PointReceiverMethod() {
	fmt.Println("PointReceiverMethod")
}

func main() {
	var s MyStruct
	s.ValueReceiverMethod()  // 输出 ValueReceiverMethod
	s.PointReceiverMethod()  // 输出 PointReceiverMethod
	tmpS := &s
	tmpS.ValueReceiverMethod() // 输出 ValueReceiverMethod
	tmpS.PointReceiverMethod() // 输出 PointReceiverMethod
}
```

### 扩展知识

1. **方法集（Method Sets）**：每个类型都有一个与之关联的方法集。对于类型 T，其方法集包含所有接收者类型为 T 的方法；对于 `*T`，其方法集包含接收者类型为 T 和 `*T` 的所有方法。因此：`*T` 的值可以调用 T 与 `*T` 两种方法；只有 T 类型的值时，只能调用 T 的方法，但编译器会隐式取地址后调用 `*T` 的方法。
2. **接口（Interfaces）**：接口定义一组方法签名，任何实现了这些方法的具体类型都被认为实现了该接口。把具体类型值赋给接口变量时，Go 会检查该具体类型的**方法集**是否包含接口定义的所有方法。
3. **值接收者和指针接收者**：值接收者（T）方法内部对接收者的修改不影响原始值；指针接收者（`*T`）方法内部对接收者的修改会影响原始值。
4. **多态（Polymorphism）**：通过接口实现，接口类型的变量可持有实现了该接口的任意具体类型的值并调用其方法，无需关心具体类型。
5. **嵌入类型（Embedded Types）**：Go 支持类型嵌入，将类型嵌入另一类型后，被嵌入类型的方法成为外部类型的方法，提供类似继承的代码复用方式。

## 二、Go 语言 channel 底层的数据结构是什么？

**回答重点**：channel 底层的数据结构叫 `hchan`，定义如下：

```go
type hchan struct {
	qcount   uint           // 队列中所有数据总数
	dataqsiz uint           // 环形队列的 size
	buf      unsafe.Pointer // 指向 dataqsiz 长度的数组
	elemsize uint16         // 单个元素大小
	closed   uint32         // 队列是否已经被关闭
	elemtype *_type         // 保存的元素类型
	sendx    uint           // 已发送的元素在环形队列中的位置
	recvx    uint           // 已接收的元素在环形队列中的位置
	recvq    waitq          // 接收者的等待队列
	sendq    waitq          // 发送者的等待队列

	lock mutex // 数据保护锁
}
```

### 有缓冲 channel

指内部有缓存数据的地方，即源码中的 `buf`，`buf` 的长度即为缓冲的长度。

1. `buf` 指向一个数组，数组用作**环形队列**。
2. 写入数据放到数组的 `sendx` 位置。
3. 读取数据从 `recvx` 位置开始读，当 `recvx` 与 `sendx` 相等时表示无数据。

### 无缓冲 channel

无缓冲 channel 的 `buf` 字段指向 `unsafe.Pointer(nil)`，即无缓冲队列。

1. 数据写入时，把当前发送端写入 `sendq`，并使当前发送端进入阻塞态。
2. 数据接收时，获取 `sendq` 队列中的元素，将数据交给接收端，同时解除 `sendq` 的阻塞。
3. 数据接收先触发时则进行相反操作。

> 源码：`https://github.com/golang/go/blob/master/src/runtime/chan.go#L33`

### 扩展知识

**性能优化**

1. **缓冲区大小**：合理设置 channel 缓冲区大小可提高性能，减少 goroutine 的阻塞和上下文切换。
2. **避免不必要的阻塞**：高并发场景中尽量避免 channel 发送/接收阻塞，可通过增加缓冲区大小或使用 `select` 语句实现。
3. **减少锁竞争**：channel 底层实现使用了互斥锁，频繁的锁竞争会影响性能，可通过减少对共享资源的访问来优化。

**常见陷阱**

1）**关闭已关闭的 channel**：会 panic，因此关闭前应确保未被关闭。

```go
func safeClose(ch chan int) {
	defer func() {
		if recover() != nil {
			fmt.Println("Channel already closed")
		}
	}()
	close(ch)
}
```

2）**从已关闭的 channel 接收数据**：不会阻塞，并会返回元素类型的零值。

```go
ch := make(chan int)
close(ch)
value, ok := <-ch
fmt.Println(value, ok) // 输出: 0 false
```

3）**死锁**：所有 channel 操作都阻塞时程序发生死锁。应避免在没有其他 goroutine 运行的情况下进行阻塞操作。

```go
func main() {
	ch := make(chan int)
	ch <- 1 // 死锁，因为没有其他 goroutine 接收数据
}
```

**最佳实践**

1. 使用 `select` 语句处理多个 channel，提高代码健壮性和可读性。
2. 根据具体场景合理设置缓冲区大小，平衡性能和资源使用。
3. 避免滥用 channel——某些情况下使用互斥锁（`sync.Mutex`）或其他同步机制更合适。
4. 关闭 channel 的时机：只有确定没有其他发送操作时才关闭，且通常由发送方负责关闭。

## 三、Go 语言中 defer 的变量快照在什么情况下会失效？

**重点回答**：`defer` 的变量快照指 `defer` 语句**定义时捕获的变量的状态**。以下情况快照会失效，导致行为不如预期：

1）**匿名函数闭包**：当 `defer` 语句中使用的匿名函数**捕获了外部变量**时，若变量值在 `defer` 定义后发生变化，`defer` 执行时会使用变化后的值。

2）**引用类型**：当 `defer` 引用持有**引用类型的变量**（如指针、切片、映射、通道和函数）时，虽然引用本身的地址不会变，但指向的内容可能变化，也会导致最终结果与预期快照不同。

### 扩展知识

编程时经常需要打开资源（数据库连接、文件、锁等），用完必须释放，否则造成内存泄漏。Go 中 `defer` 一般用于资源清理、文件关闭、解锁互斥量等操作。

#### 1）defer 常见用法

在函数开始时定义 defer，确保退出时资源正确释放。

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	file, err := os.Open("example.txt")
	if err != nil {
		fmt.Println("Error opening file:", err)
		return
	}
	defer file.Close()

	// 处理文件的逻辑
}
```

#### 2）闭包的 defer 变量

```go
package main

import "fmt"

func main() {
	x := 0
	defer func() { fmt.Println("deferred x:", x) }() // 这里捕获的是 x 的引用
	x = 1
	fmt.Println("Normal x:", x)
}
```

输出结果：

```text
Normal x: 1
deferred x: 1
```

#### 3）defer + 引用类型

当 `defer` 引用持有引用类型的变量时，如果变量指向的内容发生变化，也会导致最终结果与预期快照不同。

```go
package main

import "fmt"

func main() {
	x := []int64{0}
	defer fmt.Println("deferred x:", x) // 这里捕获的是 x 的引用
	x[0] = 1
	fmt.Println("Normal x:", x)
}
```

输出结果：

```text
Normal x: [1]
deferred x: [1]
```

#### 4）defer + 函数参数

把变量作为函数的参数传递给匿名函数，`defer` 后面跟的就是一个函数调用了。此时参数值在 defer 定义时即被求值并拷贝，因此快照生效。

```go
package main

import "fmt"

func main() {
	for i := 0; i < 3; i++ {
		defer func(item int) { // 函数调用
			fmt.Println(item)
		}(i)
	}
}
```

输出结果：

```text
2
1
0
```

## 四、Go 语言中 init() 函数在什么时候执行？

**回答重点**：`init()` 函数在 Go 程序执行之前自动调用，即在 `main()` 函数之前。它用于**初始化包级别的变量**、设置初始状态或执行一次性初始化操作（不能有参数，也不能有返回值）。每个包可以有多个 `init()` 函数。

**执行顺序**：

1. **包的初始化顺序**：若一个包被多个包依赖，Go 会先执行所有被导入包的 `init()` 函数，被依赖的包 `init()` 先执行。
2. **同一包内多文件多 `init()`**：按文件名的顺序调用，同一文件内的多个 `init()` 按出现的顺序依次调用。
3. **程序入口**：最终在 `main()` 开始执行之前，所有相关包的 `init()` 函数都已执行完毕。

### 注意点

- 在 `main.main` 函数执行之前，所有代码都运行在同一个 `Goroutine`（主系统线程）中。
- 若某个 `init()` 内部启动了新的 `Goroutine`，那么新的 `Goroutine` 和 `main.main` 函数是并发执行的。

### 使用场景与实际例子

**初始化数据库连接**：

```go
func init() {
  db, err := sql.Open("mysql", "user:password@tcp(localhost:3306)/dbname")
  if err != nil {
      log.Fatal(err)
  }
  fmt.Println("数据库连接成功")
}
```

**注册自定义的日志记录器**：

```go
func init() {
  log.SetFlags(log.Ldate | log.Ltime | log.Lshortfile)
}
```

## 五、Go 语言中函数返回局部变量的指针是否安全？

**回答重点**：安全。Go 的编译器和运行时系统通过**逃逸分析**识别出该局部变量将在函数外被引用，于是在**堆**（而非栈）上为它分配内存；即使函数结束，局部变量的内存位置仍会保留。

Go 编译器对每个局部变量执行逃逸分析：若发现其使用范围超过所在函数，则该变量的内存不会在栈上分配，而是在堆上。可借助编译选项 `-gcflags=-m` 查看变量逃逸的情况。

**注意**：虽然在 Go 中返回局部变量的指针是安全的，但**对返回的局部变量指针进行操作不一定安全**——例如对指向 slice 类型对象的指针进行扩容操作，底层数组改变后该指针可能失效。

### 关于逃逸

- 在 C/C++ 等语言中返回局部变量指针不安全（函数返回后栈空间被释放）；Go 由逃逸分析决定存储位置。
- **逃逸分析**：确定哪些变量超出了函数作用范围——地址被传递出去、或函数返回局部变量地址，该变量即被视为「逃逸」。
- **内存逃逸**：检测到变量逃逸出函数作用域时，分配到堆而非栈，堆上变量的生命周期超出函数调用，安全可靠。
- **垃圾回收**：Go 用 GC 定期扫描堆内存并回收不再使用的对象，程序无需过多关心内存管理。

```go
package main

import "fmt"

func createPointer() *int {
    var localVar int = 42
    return &localVar
}

func main() {
    ptr := createPointer()
    fmt.Println(*ptr)  // 输出 42
}
```

## 六、Go 语言中如何访问私有成员？

**重点回答**：Go 中**以小写字母开头**的标识符是私有成员（字段、方法、函数等），遵循语言的可见性规则，仅在定义它的包内可见，包外无法直接访问。访问私有成员主要包括三种方式：

- 同一包内，可以直接访问小写字母开头的私有成员。
- 其他包中，无法直接访问，但可以通过**公开的接口 / 方法**间接访问。
- 使用**反射**绕过封装机制访问和修改私有字段（不建议使用）。

### 访问私有成员的规则

**可见性规则**：

- **私有成员**：以小写字母开头的标识符，仅在定义它的包内可见，包外无法访问。
- **公开成员**：以大写字母开头的标识符，可在任何包中访问。

**1）私有成员的访问（包内）**：

```go
package example

type Person struct {
    name string
    age  int
}

func NewPerson(name string, age int) Person {
    return Person{name: name, age: age}
}

func GetPersonAge(p Person) int {
    return p.age
}
```

**2）通过公开方法访问私有成员（包外）**：

```go
package main

import (
    "fmt"
    "example" // 假设 example 是定义 Person 的包
)

func main() {
    p := example.NewPerson("John", 30)

    // 不能直接访问 p.age，因为 age 是私有的
    // fmt.Println(p.age) // 编译错误

    // 通过包内公开的函数访问私有成员
    age := example.GetPersonAge(p)
    fmt.Println("Age:", age) // 输出: Age: 30
}
```

**3）通过反射访问私有成员**（违背封装原则）：

```go
package main

import (
    "fmt"
    "reflect"
)

type Person struct {
    name string
    age  int
}

func main() {
    p := Person{name: "John", age: 30}

    // 获取指向 p 的指针的反射值，Elem 用于获取指针指向的值
    v := reflect.ValueOf(&p).Elem()

    // 获取私有字段 name
    nameField := v.FieldByName("name")
    fmt.Println("name (private):", nameField.String())
}
```

借助 `unsafe` 还可进一步读写私有字段：

```go
field := value.FieldByName("name")
realField := reflect.NewAt(field.Type(), unsafe.Pointer(field.UnsafeAddr())).Elem()
fmt.Println("name (private):", realField.String())
```

**注意点**：

- **安全性**：通过反射访问 / 修改私有字段破坏封装性，应谨慎使用，尽量避免在生产代码中使用。
- **性能**：反射操作通常比直接访问字段慢，性能敏感的代码中应避免频繁使用。
