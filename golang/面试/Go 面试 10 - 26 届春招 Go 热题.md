# Go 面试 10 - 26 届春招 Go 热题

> 26 届春招 Go 高频面试题汇总（Go 语言基础 / 底层原理 / 并发），每题为「回答重点 + 扩展知识」结构。

## 一、非接口的任意类型 T 都能调用 *T 的方法么？反过来呢？

**回答重点**：都可以。

- 对于非接口的任意类型 T，确实可以调用 `*T`（指向 T 的指针）的方法：当在一个 T 类型的值上调用 `*T` 方法时，Go 编译器会**隐式获取该值的地址**，再调用相应方法——这种行为称为「指针接收者方法调用的自动解引用」。
- 反过来，`*T` 类型的值也可以调用 T 的方法，因为 `*T` 的方法集同时包含接收者为 T 和 `*T` 的方法。

### 示例代码

```go
package main

import "fmt"

type MyStruct struct {
	field int
}

func (ms MyStruct) ValueReceiverMethod() {
	fmt.Println("ValueReceiverMethod")
}

func (ms *MyStruct) PointReceiverMethod() {
	fmt.Println("PointReceiverMethod")
}

func main() {
	var s MyStruct
	s.ValueReceiverMethod()  // 输出 ValueReceiverMethod
	s.PointReceiverMethod()  // 输出 PointReceiverMethod
	tmpS := &s
	tmpS.ValueReceiverMethod() // 输出 ValueReceiverMethod
	tmpS.PointReceiverMethod() // 输出 PointReceiverMethod
}
```

### 扩展知识

1. **方法集（Method Sets）**：每个类型都有一个与之关联的方法集。对于类型 T，其方法集包含所有接收者类型为 T 的方法；对于 `*T`，其方法集包含接收者类型为 T 和 `*T` 的所有方法。因此：`*T` 的值可以调用 T 与 `*T` 两种方法；只有 T 类型的值时，只能调用 T 的方法，但编译器会隐式取地址后调用 `*T` 的方法。
2. **接口（Interfaces）**：接口定义一组方法签名，任何实现了这些方法的具体类型都被认为实现了该接口。把具体类型值赋给接口变量时，Go 会检查该具体类型的**方法集**是否包含接口定义的所有方法。
3. **值接收者和指针接收者**：值接收者（T）方法内部对接收者的修改不影响原始值；指针接收者（`*T`）方法内部对接收者的修改会影响原始值。
4. **多态（Polymorphism）**：通过接口实现，接口类型的变量可持有实现了该接口的任意具体类型的值并调用其方法，无需关心具体类型。
5. **嵌入类型（Embedded Types）**：Go 支持类型嵌入，将类型嵌入另一类型后，被嵌入类型的方法成为外部类型的方法，提供类似继承的代码复用方式。

## 二、Go 语言 channel 底层的数据结构是什么？

**回答重点**：channel 底层的数据结构叫 `hchan`，定义如下：

```go
type hchan struct {
	qcount   uint           // 队列中所有数据总数
	dataqsiz uint           // 环形队列的 size
	buf      unsafe.Pointer // 指向 dataqsiz 长度的数组
	elemsize uint16         // 单个元素大小
	closed   uint32         // 队列是否已经被关闭
	elemtype *_type         // 保存的元素类型
	sendx    uint           // 已发送的元素在环形队列中的位置
	recvx    uint           // 已接收的元素在环形队列中的位置
	recvq    waitq          // 接收者的等待队列
	sendq    waitq          // 发送者的等待队列

	lock mutex // 数据保护锁
}
```

### 有缓冲 channel

指内部有缓存数据的地方，即源码中的 `buf`，`buf` 的长度即为缓冲的长度。

1. `buf` 指向一个数组，数组用作**环形队列**。
2. 写入数据放到数组的 `sendx` 位置。
3. 读取数据从 `recvx` 位置开始读，当 `recvx` 与 `sendx` 相等时表示无数据。

### 无缓冲 channel

无缓冲 channel 的 `buf` 字段指向 `unsafe.Pointer(nil)`，即无缓冲队列。

1. 数据写入时，把当前发送端写入 `sendq`，并使当前发送端进入阻塞态。
2. 数据接收时，获取 `sendq` 队列中的元素，将数据交给接收端，同时解除 `sendq` 的阻塞。
3. 数据接收先触发时则进行相反操作。

> 源码：`https://github.com/golang/go/blob/master/src/runtime/chan.go#L33`

### 扩展知识

**性能优化**

1. **缓冲区大小**：合理设置 channel 缓冲区大小可提高性能，减少 goroutine 的阻塞和上下文切换。
2. **避免不必要的阻塞**：高并发场景中尽量避免 channel 发送/接收阻塞，可通过增加缓冲区大小或使用 `select` 语句实现。
3. **减少锁竞争**：channel 底层实现使用了互斥锁，频繁的锁竞争会影响性能，可通过减少对共享资源的访问来优化。

**常见陷阱**

1）**关闭已关闭的 channel**：会 panic，因此关闭前应确保未被关闭。

```go
func safeClose(ch chan int) {
	defer func() {
		if recover() != nil {
			fmt.Println("Channel already closed")
		}
	}()
	close(ch)
}
```

2）**从已关闭的 channel 接收数据**：不会阻塞，并会返回元素类型的零值。

```go
ch := make(chan int)
close(ch)
value, ok := <-ch
fmt.Println(value, ok) // 输出: 0 false
```

3）**死锁**：所有 channel 操作都阻塞时程序发生死锁。应避免在没有其他 goroutine 运行的情况下进行阻塞操作。

```go
func main() {
	ch := make(chan int)
	ch <- 1 // 死锁，因为没有其他 goroutine 接收数据
}
```

**最佳实践**

1. 使用 `select` 语句处理多个 channel，提高代码健壮性和可读性。
2. 根据具体场景合理设置缓冲区大小，平衡性能和资源使用。
3. 避免滥用 channel——某些情况下使用互斥锁（`sync.Mutex`）或其他同步机制更合适。
4. 关闭 channel 的时机：只有确定没有其他发送操作时才关闭，且通常由发送方负责关闭。

## 三、Go 语言中 defer 的变量快照在什么情况下会失效？

**重点回答**：`defer` 的变量快照指 `defer` 语句**定义时捕获的变量的状态**。以下情况快照会失效，导致行为不如预期：

1）**匿名函数闭包**：当 `defer` 语句中使用的匿名函数**捕获了外部变量**时，若变量值在 `defer` 定义后发生变化，`defer` 执行时会使用变化后的值。

2）**引用类型**：当 `defer` 引用持有**引用类型的变量**（如指针、切片、映射、通道和函数）时，虽然引用本身的地址不会变，但指向的内容可能变化，也会导致最终结果与预期快照不同。

### 扩展知识

编程时经常需要打开资源（数据库连接、文件、锁等），用完必须释放，否则造成内存泄漏。Go 中 `defer` 一般用于资源清理、文件关闭、解锁互斥量等操作。

#### 1）defer 常见用法

在函数开始时定义 defer，确保退出时资源正确释放。

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	file, err := os.Open("example.txt")
	if err != nil {
		fmt.Println("Error opening file:", err)
		return
	}
	defer file.Close()

	// 处理文件的逻辑
}
```

#### 2）闭包的 defer 变量

```go
package main

import "fmt"

func main() {
	x := 0
	defer func() { fmt.Println("deferred x:", x) }() // 这里捕获的是 x 的引用
	x = 1
	fmt.Println("Normal x:", x)
}
```

输出结果：

```text
Normal x: 1
deferred x: 1
```

#### 3）defer + 引用类型

当 `defer` 引用持有引用类型的变量时，如果变量指向的内容发生变化，也会导致最终结果与预期快照不同。

```go
package main

import "fmt"

func main() {
	x := []int64{0}
	defer fmt.Println("deferred x:", x) // 这里捕获的是 x 的引用
	x[0] = 1
	fmt.Println("Normal x:", x)
}
```

输出结果：

```text
Normal x: [1]
deferred x: [1]
```

#### 4）defer + 函数参数

把变量作为函数的参数传递给匿名函数，`defer` 后面跟的就是一个函数调用了。此时参数值在 defer 定义时即被求值并拷贝，因此快照生效。

```go
package main

import "fmt"

func main() {
	for i := 0; i < 3; i++ {
		defer func(item int) { // 函数调用
			fmt.Println(item)
		}(i)
	}
}
```

输出结果：

```text
2
1
0
```

## 四、Go 语言中 init() 函数在什么时候执行？

**回答重点**：`init()` 函数在 Go 程序执行之前自动调用，即在 `main()` 函数之前。它用于**初始化包级别的变量**、设置初始状态或执行一次性初始化操作（不能有参数，也不能有返回值）。每个包可以有多个 `init()` 函数。

**执行顺序**：

1. **包的初始化顺序**：若一个包被多个包依赖，Go 会先执行所有被导入包的 `init()` 函数，被依赖的包 `init()` 先执行。
2. **同一包内多文件多 `init()`**：按文件名的顺序调用，同一文件内的多个 `init()` 按出现的顺序依次调用。
3. **程序入口**：最终在 `main()` 开始执行之前，所有相关包的 `init()` 函数都已执行完毕。

### 注意点

- 在 `main.main` 函数执行之前，所有代码都运行在同一个 `Goroutine`（主系统线程）中。
- 若某个 `init()` 内部启动了新的 `Goroutine`，那么新的 `Goroutine` 和 `main.main` 函数是并发执行的。

### 使用场景与实际例子

**初始化数据库连接**：

```go
func init() {
  db, err := sql.Open("mysql", "user:password@tcp(localhost:3306)/dbname")
  if err != nil {
      log.Fatal(err)
  }
  fmt.Println("数据库连接成功")
}
```

**注册自定义的日志记录器**：

```go
func init() {
  log.SetFlags(log.Ldate | log.Ltime | log.Lshortfile)
}
```

## 五、Go 语言中函数返回局部变量的指针是否安全？

**回答重点**：安全。Go 的编译器和运行时系统通过**逃逸分析**识别出该局部变量将在函数外被引用，于是在**堆**（而非栈）上为它分配内存；即使函数结束，局部变量的内存位置仍会保留。

Go 编译器对每个局部变量执行逃逸分析：若发现其使用范围超过所在函数，则该变量的内存不会在栈上分配，而是在堆上。可借助编译选项 `-gcflags=-m` 查看变量逃逸的情况。

**注意**：虽然在 Go 中返回局部变量的指针是安全的，但**对返回的局部变量指针进行操作不一定安全**——例如对指向 slice 类型对象的指针进行扩容操作，底层数组改变后该指针可能失效。

### 关于逃逸

- 在 C/C++ 等语言中返回局部变量指针不安全（函数返回后栈空间被释放）；Go 由逃逸分析决定存储位置。
- **逃逸分析**：确定哪些变量超出了函数作用范围——地址被传递出去、或函数返回局部变量地址，该变量即被视为「逃逸」。
- **内存逃逸**：检测到变量逃逸出函数作用域时，分配到堆而非栈，堆上变量的生命周期超出函数调用，安全可靠。
- **垃圾回收**：Go 用 GC 定期扫描堆内存并回收不再使用的对象，程序无需过多关心内存管理。

```go
package main

import "fmt"

func createPointer() *int {
    var localVar int = 42
    return &localVar
}

func main() {
    ptr := createPointer()
    fmt.Println(*ptr)  // 输出 42
}
```

## 六、Go 语言中如何访问私有成员？

**重点回答**：Go 中**以小写字母开头**的标识符是私有成员（字段、方法、函数等），遵循语言的可见性规则，仅在定义它的包内可见，包外无法直接访问。访问私有成员主要包括三种方式：

- 同一包内，可以直接访问小写字母开头的私有成员。
- 其他包中，无法直接访问，但可以通过**公开的接口 / 方法**间接访问。
- 使用**反射**绕过封装机制访问和修改私有字段（不建议使用）。

### 访问私有成员的规则

**可见性规则**：

- **私有成员**：以小写字母开头的标识符，仅在定义它的包内可见，包外无法访问。
- **公开成员**：以大写字母开头的标识符，可在任何包中访问。

**1）私有成员的访问（包内）**：

```go
package example

type Person struct {
    name string
    age  int
}

func NewPerson(name string, age int) Person {
    return Person{name: name, age: age}
}

func GetPersonAge(p Person) int {
    return p.age
}
```

**2）通过公开方法访问私有成员（包外）**：

```go
package main

import (
    "fmt"
    "example" // 假设 example 是定义 Person 的包
)

func main() {
    p := example.NewPerson("John", 30)

    // 不能直接访问 p.age，因为 age 是私有的
    // fmt.Println(p.age) // 编译错误

    // 通过包内公开的函数访问私有成员
    age := example.GetPersonAge(p)
    fmt.Println("Age:", age) // 输出: Age: 30
}
```

**3）通过反射访问私有成员**（违背封装原则）：

```go
package main

import (
    "fmt"
    "reflect"
)

type Person struct {
    name string
    age  int
}

func main() {
    p := Person{name: "John", age: 30}

    // 获取指向 p 的指针的反射值，Elem 用于获取指针指向的值
    v := reflect.ValueOf(&p).Elem()

    // 获取私有字段 name
    nameField := v.FieldByName("name")
    fmt.Println("name (private):", nameField.String())
}
```

借助 `unsafe` 还可进一步读写私有字段：

```go
field := value.FieldByName("name")
realField := reflect.NewAt(field.Type(), unsafe.Pointer(field.UnsafeAddr())).Elem()
fmt.Println("name (private):", realField.String())
```

**注意点**：

- **安全性**：通过反射访问 / 修改私有字段破坏封装性，应谨慎使用，尽量避免在生产代码中使用。
- **性能**：反射操作通常比直接访问字段慢，性能敏感的代码中应避免频繁使用。

> 相关：[[Go 基础 08 - 封装与包管理]]、[[Go 基础 10 - 接口 interface]]

## 七、Go 语言中怎么实现闭包？闭包的主要应用场景是什么？

**回答重点**：闭包（Closure）是一个**函数值**，它引用了其外部作用域中的变量——实现方式很简单：在一个函数内部定义另一个函数，并让它访问外部函数的变量。闭包被「绑定」到被捕获的变量上，可以读取并修改它。

```go
func adder() func(int) int {
	sum := 0                  // 外部作用域的变量
	return func(x int) int {  // 返回匿名函数（闭包）
		sum += x
		return sum
	}
}

func main() {
	pos, neg := adder(), adder() // 两个闭包各自捕获自己的 sum，互不干扰
	for i := 0; i < 10; i++ {
		fmt.Println(pos(i), neg(-2*i))
	}
}
```

**主要应用场景**：

1. **伪全局变量**：捕获外部变量实现类似全局变量的效果，但作用域被限制在闭包内，比全局变量更可控。
2. **函数工厂**：根据不同的配置参数动态创建函数。
3. **装饰器模式**：不修改原有函数即可动态添加新功能。
4. **回调函数**：把函数作为参数传递，并用闭包捕获上下文信息。
5. **并发编程**：在多个 goroutine 中共享和修改变量的一种简洁方式。
6. **保存中间态**：用作累加器 / 计数器，持久化「上一次的运行状态」。

### 扩展知识

1）**保存中间态（计数器）**：每次调用都会「记住」上次的状态。

```go
func incrementer() func() int {
	count := 0
	return func() int {
		count++
		return count
	}
}
// inc() 依次返回 1、2、3
```

2）**工厂模式**：用 `CalcFactory(operation)` 按运算符返回不同的闭包，让函数的创建更灵活、可定制。

```go
func CalcFactory(operation string) func(int, int) int {
	switch operation {
	case "add":
		return func(a, b int) int { return a + b }
	case "subtract":
		return func(a, b int) int { return a - b }
	case "multiply":
		return func(a, b int) int { return a * b }
	case "divide": // 函数签名返回 int，除法会向下取整
		return func(a, b int) int {
			if b != 0 {
				return a / b
			}
			return 0
		}
	default:
		return nil
	}
}
```

3）**装饰器模式**：包装原函数，在不修改它的情况下追加行为（如打印日志）。

```go
func doubleAndPrint(fn func(int) int) func(int) int {
	return func(x int) int {
		result := fn(x)
		fmt.Println("Result:", result*2)
		return result
	}
}
// doubleAndPrint(square)(3) → 打印 18
```

4）**回调函数**：适合需要等待长时间操作或事件触发的场景——异步任务完成后把结果交给回调闭包。

```go
func TaskAsync(input int, callback func(int)) {
	go func() {
		time.Sleep(1 * time.Second) // 模拟运算操作
		callback(input * 3)
	}()
}
// 主协程需要等待（Sleep 或 WaitGroup），否则程序会提前结束
```

5）**并发编程**：为循环中的每个任务创建 goroutine 时，**把循环变量作为参数显式传入**，让每个闭包捕获属于自己的副本，避免所有 goroutine 共享同一个变量。

```go
for _, url := range urls {
	wg.Add(1)
	go func(url string) { // url 以参数传入 = 捕获副本
		defer wg.Done()
		fmt.Println(url)
	}(url)
}
```

6）**封装逻辑**：把处理回调 / 事件的相关逻辑收进闭包，让代码更简洁易读。

7）**模拟私有变量**：借助闭包实现数据的封装与隐藏，达到其他语言中私有变量的效果。

## 八、Go 语言中所有的 T 类型都有 *T 类型吗？

**重点回答**：不是。绝大多数类型 `T` 都可以有对应的指针类型 `*T`，**例外是接口类型**——指向接口的指针没有实际意义：接口本身已是引用类型、可以直接引用对象，无需再取指针；而且「指向接口的指针」的**方法集为空**，无法调用接口定义的方法。

### 扩展知识

**1）普通情况**：基础类型、自定义类型、结构体、切片、映射、通道都可以取指针。

```go
var a int = 10
var p *int = &a

type Person struct {
	Name string
	Age  int
}
var person Person
var pPtr *Person = &person

var s []int
var sPtr *[]int = &s
var m map[string]int
var mPtr *map[string]int = &m
var ch chan int
var chPtr *chan int = &ch
```

**2）特殊情况**：

- **数组**：`*[N]int`（如 `*[5]int`）是合法类型，表示固定大小为 N 的数组的指针。
- **接口**：指向接口的指针没有意义（见「回答重点」）——这是本题的关键考点。
- **函数**：`*func() int` 也是合法类型，但实际开发中很少直接使用函数指针类型。

> 相关：[[Go 基础 17 - 指针 Pointer]]、[[Go 基础 10 - 接口 interface]]

## 九、Go 语言中数组与切片有什么异同？

**回答重点**：

- **数组**：长度固定（编译时确定）、值类型、元素在内存中连续；作为参数传递时是**值传递**，会复制整个数组内容，对副本的修改不影响原数组。
- **切片**：动态大小、可在运行时扩展；由三部分组成——指向底层数组的指针、长度 len、容量 cap；传递的是切片的**元数据**（指针 / 长度 / 容量），扩容时会创建新的底层数组并复制数据。

| 特性 | 数组 | 切片 |
|---|---|---|
| **长度** | 固定，编译时确定 | 动态，可以扩展 |
| **类型** | 类型包含元素类型与长度（`[3]int` 与 `[4]int` 是不同类型） | 类型为 `[]T`，不含长度 |
| **内存管理** | 内存连续，位于栈或堆上（依上下文） | 是对底层数组的引用（视图） |
| **传递方式** | 值传递，复制整个数组内容 | 传递元数据（指针 / 长度 / 容量） |
| **灵活性** | 不灵活，大小固定 | 灵活，可用 `append` 动态增长 |
| **扩展性** | 不支持扩展，编译时固定 | 支持动态扩展，`append` 会扩容 |
| **性能** | 较好，尤其是不需要扩展时 | 扩容有一定开销，但更适应动态数据操作 |
| **操作简便性** | 不能直接扩展或裁剪 | 提供丰富的内建函数（`append`、`copy`） |

**小结**：

- **数组**：适用于固定大小、不需要扩展的场景，内存管理简单，但不灵活且值传递有复制开销。
- **切片**：适用于动态集合，灵活、支持扩展与裁剪，但要注意扩容带来的性能损失与容量管理。

### 扩展知识

**数组的实现**：值类型，元素在内存中紧凑连续；**数组长度是类型的一部分**（`[3]int` 与 `[4]int` 是不同类型），编译器在编译期即确定大小。作为参数传递会完整复制，大数组会带来不必要的复制开销：

```go
func modifyArray(arr [5]int) {
	arr[0] = 100 // 修改的是副本，不影响原数组
}
```

**切片的实现**：底层结构为 `array / len / cap` 三要素，指针指向底层数组的起始位置；切片本身不存储数据，只是对底层数组的视图。容量不足时 `append` 触发扩容：分配一个更大的底层数组 → 复制原有数据 → 返回新切片，这也是扩容内存开销的来源：

```go
// 扩容逻辑示意：容量不足则创建新切片并复制数据
func grow(slice []T, newCap int) []T {
	if newCap <= cap(slice) {
		return slice
	}
	newSlice := make([]T, len(slice), newCap)
	copy(newSlice, slice)
	return newSlice
}
```

**扩容策略**：

- Go 1.18 以前：容量 < 1024 时按 2 倍扩容，≥ 1024 时按 1.25 倍扩容。
- Go 1.18 及以后：容量 < 256 时按 2 倍扩容；≥ 256 时增长因子从 2 平滑降到 1.25（阈值 `threshold = 256`，`newcap += (newcap + 3*threshold) >> 2` 即约 1.25 倍增长）。

| starting cap | growth factor |
|---|---|
| 256 | 2.0 |
| 512 | 1.63 |
| 1024 | 1.44 |
| 2048 | 1.35 |
| 4096 | 1.30 |

```go
// 1.18+ 的 nextslicecap：计算下一次扩容后的容量
func nextslicecap(newLen, oldCap int) int {
	newcap := oldCap
	doublecap := newcap + newcap
	if newLen > doublecap {
		return newLen // 目标长度已超过两倍，直接取目标长度
	}
	const threshold = 256
	if oldCap < threshold {
		return doublecap // 小切片直接翻倍
	}
	for {
		newcap += (newcap + 3*threshold) >> 2 // 平滑过渡到约 1.25 倍
		if uint(newcap) >= uint(newLen) {
			break
		}
	}
	if newcap <= 0 { // 溢出保护
		return newLen
	}
	return newcap
}
```

**延伸问题：如何避免切片频繁扩容？** 预先分配合适的容量，例如 `slice := make([]int, 0, 1000)`。

**其他注意点**：

- 子切片（如 `slice[1:4]`）不复制底层数据，只是指向原数组某一部分的新视图。
- **切片内存泄漏**：切片引用底层数组，若长期持有只用了少量元素的大切片，底层数组内存无法释放——应及时切割掉不需要的部分或手动管理内存。

> 相关：[[Go 基础 04 - 数组与切片]]、[[Go 基础 14 - Slice 操作专题]]、[[Go 底层原理 02 - Slice]]

## 十、Go 语言中的 = 和 := 有什么区别？

**回答重点**：

- `=`：给**已声明的变量赋新值**，变量必须已声明且有类型。
- `:=`：**声明并初始化新变量**，变量必须是全新的，不能用于已有变量的重新赋值（只能在函数内部使用）。

```go
var y int = 20 // 声明 + 赋值
y = 50         // = 重新赋值（变量须已存在）

z := 20 // := 声明 + 赋值新变量
// z := 30 // 不允许：不能对已有变量用 := 重新赋值
```

### 扩展知识

**1）包级别变量只能用 `=`**：声明包级变量只能用 `=`，`:=` 只能在函数内部使用：

```go
var x = 10 // 包级变量，只能用 =
// x := 10 // 不允许

func main() {
	fmt.Println("x:", x)
}
```

**2）自动类型推断**：`=`（配合 `var`）与 `:=` 都可省略类型，由 Go 自动推断，可用 `reflect.TypeOf` 验证：

```go
var x = 10
y := 20
z := "hello"
fmt.Println(reflect.TypeOf(x), reflect.TypeOf(y), reflect.TypeOf(z)) // int int string
```

**3）多重赋值**：支持同时为多个变量赋值，适合交换变量、接收函数多返回值等场景：

```go
var x, y int = 10, 20
y, x = x, y // 交换变量值

x, z := 30, 40 // 允许：z 是新变量
// x, y := 1, 2 // 不允许：:= 至少要有一个未声明过的新变量
```

**注意**：使用 `:=` 多重赋值时，**至少要有一个未声明过的新变量**——对已声明的变量是赋值，对新变量是声明 + 赋值。

## 十一、Go 语言中的 rune 类型是什么？

**回答重点**：`rune` 用来表示一个 **Unicode 码点**，本质是 `int32` 的别名，用来区分「字符值」与「整数值」。它定义在 `builtin/builtin.go`：

```go
type rune = int32
```

Go 字符串底层采用 UTF-8 编码——英文字母占 1 字节，中文/特殊字符占 1~3 字节。`rune` 让开发者能正确处理 Unicode 字符，尤其是**中文的计数与分割**问题。

### 扩展知识

**1）统计含中英文的字符串长度**（`len` 数字节、`len([]rune(s))` 数字符）：

```go
s := "今天happy"
fmt.Println(len(s))         // 11（字节数）
fmt.Println(len([]rune(s))) // 7（字符数）
```

**2）按字符截取含中英文的字符串**（直接切片按字节切会乱码）：

```go
s := "今天happy"
fmt.Println(s[:2])                 // 乱码 �
fmt.Println(string([]rune(s)[:2])) // 今天
```

**3）Unicode 与码点**：Unicode 是字符编码标准，为每个字符/符号设定唯一数字编码（码点 code point）。

**4）byte vs rune**：

- `byte` = `uint8` 别名，表示单个字节，用于操作原始二进制数据。
- `rune` = `int32` 别名，表示一个 Unicode 码点，用于处理字符与字符串。

**5）rune 与字符串**：Go 字符串本质是 `[]byte`（UTF-8 字节序列）；`range` 遍历字符串会自动把字符解码为 `rune`，直接转 `[]rune` 则可按字符访问：

```go
s := "你好，世界"
for _, r := range []rune(s) {
	fmt.Printf("%c ", r)
}
```

## 十二、Go 语言中的局部变量是分配在栈上还是堆上？

**回答重点**：既可能在栈上，也可能在堆上，由编译器通过**逃逸分析**决定。

- 若变量生命周期**局限于函数作用域**、不逃逸到函数外 → 分配在**栈**上。
- 若生命周期**超出函数作用域**（如通过指针返回给外部使用）→ 编译器将其分配在**堆**上，确保作用域外仍有效。

### 扩展知识

**栈 vs 堆**：

- **栈**：线程私有，分配/释放由编译器管理，速度快，通常用于函数局部变量。
- **堆**：全局共享，分配/释放由垃圾回收器（GC）管理，适合动态分配与长生命周期内存，但性能较慢。

**逃逸分析原理**：一种**编译时优化技术**，编译器分析变量的使用场景，判断其生命周期与存储位置（堆 / 栈），核心是**判断变量引用是否超出了函数的生命周期**。

**触发堆分配的场景**：

1）**返回指针**：

```go
func createPointer() *int {
	x := 10
	return &x // x 逃逸到堆上
}
```

2）**闭包捕获**：局部变量被闭包捕获，生命周期可能超过函数范围。

```go
func closure() func() int {
	x := 10
	return func() int { return x } // x 逃逸到堆上
}
```

3）**跨 Goroutine 传递**：变量被传入另一个 Goroutine，无法保证安全地留在栈上。

```go
func goroutine() {
	x := 10
	go func() { fmt.Println(x) }() // x 逃逸到堆上
}
```

**查看逃逸分析结果**：`go build`/`go run` 加 `-gcflags="-m"`：

```bash
go build -gcflags="-m" main.go
# main.go:5:6: moved to heap: x
```
