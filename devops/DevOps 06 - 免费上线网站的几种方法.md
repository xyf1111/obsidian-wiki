# DevOps 06 - 免费上线网站的几种方法

> 不买域名、不买服务器，把练手小网站上线给别人访问的 4 种方式：云编程环境、网站托管服务、对象存储、内网穿透。正式产品仍建议走常规收费方案。

## 常规上线流程为何复杂

购买域名 → 购买服务器 → 人工上传网页文件 → 安装配置 Nginx 等 Web 服务器软件。对小网站练手或临时发给朋友看，没必要这么麻烦。

> 前提：得先有网页文件（自己写、拖拽式网页生成器、GitHub 借鉴代码均可）。

## 方法一：云编程环境（云 IDE）

- CodePen、JSFiddle、GitPod 等平台：在线编写代码、实时查看运行效果，可保存代码并把网站直接分享给别人浏览
- 对前端开发最方便：**直接省略部署过程，所见即所得**

## 方法二：网站 / 容器托管服务

原理：网站文件交给已有服务器的服务商托管。

- 国外：Vercel、GitHub Pages —— 访问速度受网络波动影响，**不推荐**
- 国内：Webify、Gitee Pages、静态网站托管等 —— 访问速度有保障

### Webify 实战（腾讯云一站式托管）

Webify 是腾讯云的一站式 Web 应用托管服务：提供服务器、默认域名、自定义域名、HTTPS、CDN 加速，且内置基于 Git 工作流的 DevOps 流程（push 代码自动重新构建部署，无需登录服务器）。产品形态类似 Vercel / GitHub Pages，优势是**在国内、提供高速 CDN**，并能与其他云产品打通形成体系。

**创建应用（两种方式）：**

1. **Git 导入**：适合已有源代码，代码放 GitHub/Gitee 后直接导入；按技术栈选预设配置（如 Vue.js），不用手填构建命令
2. **从模板创建**：没有代码也能建，内置项目模板（如 Docusaurus 2 站点生成器），选中后自动复制模板到新 Git 仓库并关联应用

**持续发布流程：**

- Webify 自动给 Git 仓库配置 Webhooks，代码 push 后自动触发重新部署
- 修改代码：建议本地改 → push 到 dev 分支 → 确认无误合并到 master
- 更新后没立即看到新内容，多为 **CDN 缓存**（默认 2 分钟），等几分钟即可

**应用管理：**

- 部署时系统自动创建「云开发」环境，构建产物放到静态网站托管，可在云开发控制台查看/修改上传文件、调整 CDN 缓存设置
- 应用详情页可配置自定义域名、修改构建配置、删除应用

**费用**：依托云开发，**需收费**（提供 1 个月免费体验），但比自己买服务器（即使学生机）性价比更高。追求长期免费可优先考虑纯免费方案。

### Railway 实战（免费容器托管）

Railway（railway.app）是国外免费的**容器托管**平台。与 Vercel 不同：Vercel 一般托管前端网页，Railway 部署的是容器，可放网站、后端程序、定时任务、数据库等；部署在国外的容器还能直接访问国外接口（如 OpenAI API）。

**一键部署流程：**

1. 项目 README 放「Deploy」按钮（或直接点开源项目的一键部署按钮），进入部署界面点 `Deploy Now`
2. 用 GitHub 注册登录，平台会把项目克隆到你自己的 GitHub 仓库（填个不冲突的仓库名）
3. 进入项目控制台，配置**环境变量**（如把 OPENAI_API_KEY 换成自己的）
4. 部署成功后用 `View Logs` 查看部署日志；web 项目在设置里点 `Generate Domain` 生成免费域名，也可绑定自定义域名

**注意：**

- 免费额度：每月 500 小时（约 20 多天）应用部署时长，练手够用
- 部署自己的项目需先写 **Dockerfile** 把代码封装为容器（可参考开源项目现成写法）

### 微信云托管实战（微信生态的容器托管，官网 cloud.weixin.qq.com）

微信云托管是微信团队推出的云原生免运维上云方案：把应用打包为独立容器托管运行，**无需购买服务器**、几分钟即可上线任意后端项目；支持任意编程语言，内置主流框架模板（一行代码不写也能发项目，用来体验容器平台核心流程）。

**发布首个版本（以 Java Spring Boot 后端为例）：**

1. 登录平台创建环境（需公众号 / 小程序账号，可免费申请）→ 进入服务列表**新建服务**，填服务名；希望项目能被外网访问就**开启公网访问**
2. 在服务下新建**版本**（相当于项目版本号），三种上传方式：**本地上传**（代码只在本地电脑）、**代码库拉取**（代码已放到 GitHub / Gitee 等仓库，选仓库 + 端口号与项目保持一致）、**镜像拉取**（已有现成镜像）
3. 高级配置（可选）：指定 Dockerfile 名称、容器 CPU 与内存（最低支持 0.25 核）、实例副本数、扩缩容条件、用环境变量区分测试与生产环境；不会写 Dockerfile 可用平台界面定义启动方式，或直接抄同框架项目的 Dockerfile
4. 平台自动拉取代码、构建镜像，过程可实时查看日志；版本列表支持升级新版本、回退老版本
5. 进入**部署发布**，首次发布直接点**全量发布**；成功后可在线调试后台接口（如请求 `/api/health` 健康检测接口返回 ok 即表示部署成功）
6. 自带**服务监控**（接口调用情况、容器 CPU / 内存占用图表）与**日志检索**面板，不用自己登录服务器看日志、也不用另搭一套日志服务

**弹性扩缩容**：平台按访问流量自动增减实例副本数，上能扛高并发、下能节约成本。

**流水线自动发布**：新建流水线并填写代码仓库，默认该仓库任何代码修改都会触发（可通过指定目标目录如 `src`、推送分支、定时触发来缩小触发范围，比如只改了 README 就没必要触发）；平台通过仓库的 webhook 钩子感知代码变更并自动执行流水线；发布策略建议选「构建版本 + 镜像」，比直接全量发布保险。

**灰度测试**：发布前可配置测试 URL 参数（如 `user=test`）并点击**灰度上线**，请求接口时带上 `?user=test` 才访问到最新版本，其他用户访问到的仍是老版本；自测无 Bug 后调整灰度流量比例放量，没问题再全量发布。

**优势与成本：**

- **天然打通微信生态**：免鉴权、更轻松地调用云调用、消息推送、微信支付、小程序服务等微信能力；服务基于亿级用户同时在线的微信接入层实现，提供防数据爬取、防 DNS 劫持、防 DDoS 攻击能力，微信用户就近接入
- **一键开通数据库、对象存储、资源监控**，后端项目所需资源基本都能在平台内申请和管理，不用到处开通、自行搭建
- **按量计费**：按实际使用的 CPU、内存等资源计费，用多少付多少，停掉的项目（或平台自动缩容后）不再扣费；新用户享 **3 个月免费额度**，练手项目比买同配置服务器更划算
- 练手可用作者开源的表情包网站后端仓库（github.com/liyupi/father-backend）fork 后部署

容器托管方式在前后端部署全流程中的位置见 [[DevOps 08 - 主流前后端项目部署方式]]。

## 方法三：对象存储

- 对象存储可理解为网盘：存放图片、音视频等文件并支持预览下载；**网站本质也是文件**，把网站文件及资源打包上传，通过服务商提供的网址即可访问
- 国内可选七牛云、腾讯云存储；**七牛云 SDK 丰富、提供部分免费空间**，适合入门

## 方法四：内网穿透

- 前三种本质仍是「把文件放到别人服务器上」；内网穿透则**打通网络，直接让别人访问自己电脑上的网页**——不用买服务器、不用部署各种服务，适合临时演示、竞赛评委演示、协作开发等场景

**原理**：个人电脑多处于内网（无公开独立 IP），外网用户无法直接建立连接。内网穿透工具充当「中间人」，建立一条隧道，把内网电脑「暴露」到公共网络，并分配一个公网可访问的域名（自动带 HTTPS）。

**Ngrok 实战（免费内网穿透工具）：**

1. 官网（ngrok.com/download）注册登录（GitHub/邮箱），按操作系统下载安装包并解压
2. 参照官方文档执行 `ngrok config add-authtoken <token>` 添加 authtoken（保存到本地配置文件）
3. 执行 `ngrok http <端口号>` 启动穿透服务（端口改为本地项目占用端口，前端一般 80、后端一般 8080），工具自动生成一个 HTTPS 域名指向本机服务，浏览器访问即可

**固定域名：** 默认每次启动域名随机，不利于持续访问。可在官网免费创建静态域名，启动时指定 `domain` 参数（本质是 `ngrok http --domain=xxx <端口>`），每次穿透域名固定——后端同学让前端访问本地开发接口时很方便，无需反复部署到测试服务器。

**多服务同时穿透：** 修改 ngrok 配置文件 `ngrok.yml`，手动配置多条隧道（如 frontend → 5173、backend → 8104），用 `ngrok start <隧道名>` 启动指定隧道，或 `ngrok start --all` 同时启动全部（分配多个 `ngrok-free.app` 子域名）。注意：**每个固定域名只能绑定一个端口**，免费版不支持多端口分配子域名；想用固定域名访问本地多个端口，可先用 Nginx 监听 80 端口做转发（按 url 前缀转发到对应前端/后端服务），再让内网穿透指向 80 端口。

**安全注意：** 用完记得关闭服务，否则别人可直接访问你电脑上的指定服务；authtoken 切勿泄露。

**其他应用场景：** 协作开发时让别人随时访问本地开发中的网站/服务；开发微信公众号后台服务时，需要填写服务域名接收微信请求——没有域名和线上服务器时可用内网穿透生成一个，还能直接在本地 Debug 程序。

**NATAPP 实战（另一款国产免费内网穿透工具，官网 natapp.cn）：**

1. 官网注册登录后先**新建隧道**，大多数情况选**免费隧道**即可；再填写隧道配置——支持的协议 + 本地端口，例如前端 web 项目跑在本机 3000 端口，隧道协议就选 Web、端口选 3000
2. 创建好隧道会得到一个 `authtoken`（相当于密码），下载对应操作系统的客户端解压（Windows 得到 `natapp.exe`），在该文件所在目录打开命令行执行：`natapp -authtoken=<上一步获取到的 token>`，出现成功提示即表示隧道已启动
3. 启动后 NATAPP 会分配一个 **http 公网域名**，其他人输入该域名就能访问你本地端口对应的项目，可在本地直接打断点 Debug
4. 同类工具还有花生壳等；NATAPP 本身基于 ngrok 反向代理程序实现，水平不错的同学也可以自己搭建内网穿透服务

> 安全提醒：不要将电脑的重要端口暴露出去，最好用完就关，更不要用这类技术做不当用途。

## 风险提示：免费网站的「天价账单」与封号

真实案例：某博主把一个静态网页上线到云服务按量计费服务，被恶意刷了几百 G 流量，一天欠费数千元；云服务商「延停服务」在账号欠费后仍继续计费维持服务（界面上显示的额度有误导性），若不及时关闭会持续扣费直到「破产」。作者本人也经历过图床被刷流量一天扣 2 万、新站上线即被攻击等事故。

**经验建议：**

1. **免费 / 练手网站慎用按量计费服务**（CDN、对象存储等）：这类服务按流量计费，被刷流量 = 天价账单。DDOS、CC 类攻击几乎无法彻底预防（大厂高防年费几十万）；不如用带宽稍大的云服务器，被攻击至多停一会儿，不至于欠下巨款
2. **免费托管平台可用，但要了解风险**：Vercel、GitHub Pages 等适合非商用练手（省钱），但 Vercel 在被攻击时可能直接**封号**——攻击者攻击的是平台服务器，平台封不了攻击者就只能封你的账号。商用网站还是用稳定的云服务器；Cloudflare 免费 CDN 号称「减速器」，国内访问反而更慢
3. **付费云服务务必配置费用防护**：在云控制台配置费用预警、流量/资源限额、自动封禁 IP 等策略，欠费第一时间通过短信/电话告警（注意告警有延迟，凌晨的告警可能第二天才看到，但总比没有强）
4. **安全从代码层做起**：XSS、SQL 注入等经典漏洞可在代码层面解决，多学网站安全知识、定期自查（攻击监测与防护见 [[Web 安全 02 - 网站攻击监测与防护]]）
5. **别把免费代码仓库 / 第三方平台当图床**：Gitee 曾突然给图片加上防盗链（事先无任何通知），导致大量用它当图床的项目文档、博客图片全部失效（都显示成 Gitee 图标）。排查手段：对图片地址按 **F12** 看网络请求，如果返回的是 `favicon.ico` 这类图标文件，基本可判定服务端做了 **Referer 白名单校验（防盗链）**——在开发者工具里对该请求「编辑并重发」、补上 `Referer` 头即可验证（防盗链的配置与原理见 [[工具 15 - 存储优化与COS对象存储实践]]）。图片还是存自己的对象存储更可靠（七牛云 / 腾讯云 / 阿里云），Gitee 本身还有单图 1M 的限制；已经中招的迁移 3 步：① 找好新的对象存储服务 ② 把原仓库代码打包下载、完整上传并**保持路径一致** ③ 用文本编辑器批量把图片链接前缀（`gitee.com/xxx`）替换成新前缀（图床搭建见 [[工具 24 - Typora 与 PicGo 写作效率提升]]）

## 结论

以上方法满足临时上线需求；**正式上线产品、用户量大时，建议选择收费、稳定的服务**。
