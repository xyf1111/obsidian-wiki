# DevOps 09 - 本地运行正常上线出 Bug 的原因与预防

> 项目本地跑得好好的，一上线就出 Bug？六大经典原因：代码误发、环境差异、配置差异、资源路径、API 接口、用量差异，各有对应的预防手段。

## 核心要点

### 1、本地代码误发线上

开发时为了方便写的模拟数据、特殊逻辑（如不判断用户权限），上线前不检查就直接发布，导致各种「哭笑不得」的问题。预防：

- 使用 CR（Code Review）机制，代码发布前由同事或上级检查
- 不写仅本地可用的代码、尽量不写与环境有关的特殊逻辑，保证自己写的每行代码都是可发布上线的

人本身就是最大的 Bug，此问题无法根治，只能靠机制预防。

### 2、环境差异

同一套代码换一个环境可能就跑不通：操作系统、网络连通、依赖服务、依赖版本、防火墙安全设置等差异。典型场景：本地数据库新增了字段、测试通过，上线前忘了在线上数据库同步字段，导致相关功能崩掉。预防：

- 尽量保证本地与线上环境一致，如用 Docker 容器等虚拟化技术模拟线上环境
- 正式上线前先经过测试环境、预发布环境部署验证，降低环境差异风险
- 核心项目整理规范部署文档、明确定义项目运行环境，保证团队成员提前知晓并正确配置

### 3、配置差异

适用于本地的项目配置文件不一定适用于线上。如 Java 项目的 application.yml 指定 8080 端口，本地没问题，线上可能端口已被占用、或未给端口开防火墙导致无法访问。预防：

- 分环境配置：`application-dev.yml`、`application-prod.yml` 等，不同环境加载不同配置文件
- 使用 Apollo、Nacos 等可视化配置管理工具统一发布不同环境配置，通过工具校验配置并记录变更，减少人工差错

### 4、资源路径差异

项目引用了本地文件（如 C 盘的 xxx.txt），线上服务器没有该路径或没有该文件，必然报错。预防：

- 尽量使用相对路径加载资源
- 使用分布式文件系统、对象存储服务，给每个资源统一确定的标识（如网址），保证各机器都能用相同路径找到资源

### 5、API 接口差异

多出现在前端：本地调试请求后端开发服务，上线后请求线上服务，不仅路径不同、还可能跨域，导致接口请求失败、无法登录。依赖第三方接口时还要提前测试网络连通性、接口性能差异。预防：

- 保持开发和线上接口的路径规范一致
- 跨域问题用 Nginx 网关反向代理统一解决
- 使用有回调功能的第三方服务（如公众号开发）时，别忘了修改回调地址——这类错误难排查：你能请求通别人的服务，但别人的服务通知不到你

### 6、用量差异

本地/测试环境的数据量、调用量、负载压力远小于线上，很多问题不到线上难以发现。如单线程自测正常，上线 10 个线程同时请求服务就挂、数据不一致；百万用户同时存数据，存储服务直接爆满。预防：

- 不能只测试功能是否可用，还要用 JMeter 等专业压测工具验证性能、稳定性、可用性
- 结合具体业务分析流量特点（如外卖系统午高峰），采用削峰填谷等不同策略优化
- 大公司还会做故障演练：故意制造故障看系统多久能恢复，真出事也能快速处理
