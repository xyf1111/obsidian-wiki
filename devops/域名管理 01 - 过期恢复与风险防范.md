# 域名管理 01 - 过期恢复与风险防范

> 一句话摘要：域名过期是网站运维常见事故——WordPress 站点会因资源域名失效而资源全挂，域名被抢注后还可能被挂不良内容。本文给出恢复手段、风险处理与防范建议。

## 一、WordPress 域名过期后的资源恢复（SQL 域名迁移）

### 问题现象（域名过期后 WordPress 站点瘫痪的原因）

- 域名因太久未续费会被直接删除，域名控制台里已找不到该域名
- WordPress 后台配置了资源域名（`home` / `siteurl`），站点内图片、CSS/JS 等资源的 URL 均为绝对地址且写死为原域名，原域名过期后所有资源无法加载，页面只剩文字
- 验证码图片同样走资源域名 → 管理后台登录不了，无法通过界面修改配置
- 域名没了但云主机可能还在有效期内，阿里云为每台云虚拟主机分配了临时域名，可直接用临时域名访问站点

### 解决方案：直接修改数据库批量替换域名

管理后台本质上就是通过界面改数据库，既然能登录云虚拟主机，配套数据库同样可以修改。恢复步骤如下：

1. 使用云虚拟主机的临时域名访问站点，确认站点可打开但资源全挂
2. 登录云虚拟主机配套的数据库（如 phpMyAdmin / SQL 控制台）
3. 执行三行 SQL，把配置表、文章内容、文章 GUID 中的老域名批量替换为新域名：

```sql
UPDATE wp_options SET option_value = replace( option_value, 'http://www.old.top', 'http://new.com' ) WHERE option_name = 'home' OR option_name = 'siteurl';
UPDATE wp_posts SET post_content = replace( post_content, 'http://www.old.top', 'http://new.com' );
UPDATE wp_posts SET guid = replace( guid, 'http://www.old.top', 'http://new.com' );
```

4. 再次访问临时域名，所有资源成功加载，站点恢复正常

> 要点：`wp_options` 只替换 `home` 与 `siteurl` 两个配置项；`post_content` 与 `guid` 全表替换。真实操作时把示例域名换成自己的新旧域名即可。

## 二、域名过期被抢注的安全风险与处理

### 事故经过

工作室为机构建了二十余个网站，每个网站底部都放了到工作室官网的超链接。工作室域名过期未续费被删除后，被其他公司买走并挂到了不良网站上，导致所有网站底部外链点击后自动跳转到不良内容，最终惊动指导老师、网络安全机构介入。

### 应急处理

1. **立即下线**：把所有网站先下线，切断不良外链的入口
2. **去除外链**：召集人手逐个网站去除底部超链接，尽力减小影响范围
3. **举报域名**：登录「国家域名投诉举报处理平台」举报该域名；担心处理太慢可再拨打举报电话，电话举报可加速处理

### 开发警示

- **不要硬编码易失效内容**：IP 地址、域名等容易失效或变动的内容不应写死在代码里，应使用配置管理
- **前端注意内容与链接安全**：页面内容和链接要考虑失效后的后果，外链指向的域名一旦被他人接管会连带污染自己的站点
- **后端注意上传内容安全**：用户上传内容存在注入不良链接/内容的可能，需要做安全校验与过滤

### 预防建议

- 域名开启自动续费，或设置到期提醒，避免因遗忘导致域名被删除
- 站点对外链接集中管理，便于域名变更时统一替换、及时下线
